# 风动后台接入与透明植被扩展（2026-10-18）

本批完成上批两项关闭候选的可靠性缺口，在隔离 `codex/editor-reliability` worktree 实施。默认启用有保障的风动接入和透明植被策略；混合透明、风动植被、原生 LOD、遮挡剔除等不适合合批的来源继续使用原渲染路径。没有修改正式地图、布局、素材库条目或场景搭建会话的工作目录。

## 风动：缓存内后台绑定，未知变体自动准备

初始入场及传送遮罩继续按实际素材准备 shader 变体。运行期绑定只允许使用已准备的变体，完整检查多 surface 后才替换整行材质；等待期间保留原材质和弱引用，不申请额外模型。

新增 `prepare_pending_covered()` 和世界自动恢复流程：运行期发现未知变体后，冻结输入和战斗，绘制准备遮罩，再逐变体准备并绑定所有仍有效的接收体；恢复 3D 绘制，验证相机首帧并淡入，最后恢复原输入状态。保持当前位置、相机、地图版本与建筑就绪凭据，不触发传送或重建地图。退出试玩时由原生命周期恢复视口，失效协程不继续访问已销毁世界。没有把未知变体无限留给下一次人工传送。

冷 shader 工厂并非无阻塞后台：早期私有线程试验的场景线程轮询仅约 0.193 ms，但渲染帧仍停顿约 53–62 ms。因此删除该线程方案，保留自动遮罩兜底；不宣称消除了底层编译成本。最终风动夹具的两种冷变体用时及遮罩总时长见 `wind_gpu.json`，不把准备跨度当 CPU 时间，也不承诺每次原生调用不超过 2 ms。

HUD 与真实 `playtest_state.preparation.wind` 共用状态；新增 `covered_preparation` 和 `last_recovery`，保留 `ready/scanning/pending_receivers/pending_variants/reason`。未知变体原因仍为 `covered_variant_preparation_pending`，准备完成才返回 ready。

## 透明植被：先证明有收益，再使用远景批次

只扩展静态、单网格、标准 alpha-scissor 来源。保留原材质、纹理、mip、透明阈值、背面、阴影和模型几何。已有风动元数据继续排除，不用记录的 off 覆盖偷偷移除模型本身的风动；原生索引 LOD 保留逐来源选择，不塞进公共包围盒。

- 32 米空间单元按资源、实际几何、完整材质与投影属性分组；至少 128 个来源，单组最多 2048 个实例。实例化共享几何，不复制几千份顶点。
- 距完整包围盒保守近距至少 48 米，且所有角点都进入当前相机视锥时才允许实例化。近景、视野边缘、遮挡剔除或 XR 视口保留逐来源渲染；镜头投影、偏移、尺寸及视口变化都重新检查。
- 当前视口先收集 24 个原路径有效帧；渲染 CPU 中位数大于 0.5 ms 且超过 GPU 两倍才准入。计时不可用或不足时保持原路径。后续 GPU 耗时连续 12 帧超过原 CPU 中位数与 1 ms 的较大值时撤销准入。
- 同一批次管理器最多抑制 4096 个源绘制，限制镜头切换成本。保留作者 Node、mesh、碰撞、UUID、选择与记录，只切换派生 renderer 可见性；逐株隐藏、选择释放、删除、clear 和管理器退出立即恢复来源。重新挂入场景后可以恢复派生批次。

小规模散布沿用引擎自动实例化；未标记的历史随机散布不改写作者记录，重新生成时进入共享散布业务。自带风动、复杂层级、活动件、billboard、混合透明、特殊可见距离等来源保守回退，不把全部树木都归为已优化。

UI 散布面板和 `editor_state.vegetation_batching` 调用同一个 `vegetation_render_status()`；MCP 工具说明同步，未新增手动优化开关或恢复二维工具。原共享散布预览、应用、锁定、撤销、保存与重开流程保留。

## 实际测量与启用范围

私有桌面，Godot 4.7.2 Forward+，RX 7900 XTX，1280×800；4096 株分析性叶片夹具，A/B/A/B/A，每块稳定后采样 100 帧。固定 120 FPS 上限，记录渲染 CPU、全局渲染设置时间、GPU 和提交数量；没有清除 OS/驱动缓存或固定 GPU 时钟，不声称整城 FPS、冷启动、RSS 或 VRAM 改善。

最终五块原始数值及准入观测见 [性能记录](../review_artifacts/wind_cutout_20261018/vegetation_performance.json)。最终渲染 CPU（含设置）中位数为 A `1.697 / 3.286 / 2.790 ms`，B `0.212 / 0.218 ms`。两条路径均为 2 次可见调用、98,304 个提交三角形。GPU 观察由约 `0.522` 增至 `0.714 ms`，这项额外成本已明确保留，不能称为 GPU 提速；实测 CPU 准入和持续 GPU 保护是默认启用的必要条件。

本次 4096 株近景切换为 6.584 ms，单次实例构建耗时见原始批次统计；原生操作无法抢占，不把这些数值包装成硬 2 ms 时限。小规模场景、GPU 繁忙场景和未覆盖硬件不凭本机测试强行实例化。

## 验证与模型复验

按 `rmmo-model-review` 复验受影响的材质、风动、LOD 与管线。58 张固定相机、灯光、曝光和显式时钟的图像组成 29 对对照：风动网格 8 对、既有黄杨与短草 16 对、普通散布 4 对、密集植被 1 对。其中 28 对完全一致；密集叶片对照有 2 / 1,024,000 个像素不同，最大单通道差 43，RGB 平均单通道差小于 0.00005 / 255。该项是有界渲染差异，不能称像素无损。原尺寸查看未见轮廓或投影损失。原 PNG 用于本地精确比较；实际查看使用原尺寸有损 WebP quality=90，逐图参数与 SHA 记录保留。没有角色人像遮挡。

黄杨、短草使用已验候选的既有源文件，本轮未改模型或贴图。当前生产导入与后处理重新生成闭合 native，在独立目录保存、经真实 `Compiled.read` 校验重开，再执行相同镜头和两个风动时刻的对照。原生 LOD 的实际提交数量、源 mesh 与变换保持。母版、源 SHA、实际新 native SHA、解码图片／含 mip 预算见 [资源与画质记录](../review_artifacts/wind_cutout_20261018/production_retention.json)。短草中远景已有亚像素叶片表现保持，不以一致性宣称完成材质细化或任意风动闪烁治理。

分析性透明叶片只用于渲染合同测试，不是写实美术交付。真实库导入、原生保存、MCP 散布和 UI 重生成、非法 token 无副作用、撤销重做、保存重开均通过；其源导出、最终 GLB、native 和 Footprint 身份另在证据清单中记录。没有为了测试放宽导入、路径或资源包约束。旧风动夹具补上测试进程内的隔离资源包目录，验证后恢复原配置；早期 headless 试跑与目录不匹配试跑不用于发布放行，最终使用真实 GPU 全流程通过。

已验证：风动合法／非法编辑、锁定、UI 表单、预制件独立身份、实际变形与固定边、遮挡、卸载回访；真实 HTTP 试玩的新变体自动恢复、首帧与输入恢复、准备中停止、同图／跨图、失败与重开；透明批次近景／边缘／遮挡／原生 LOD 回退、逐株隐藏、源几何身份、管理器退出和重新挂入，以及共享批次原有生命周期和失效回归。

资源审计、受影响画质、隔离运行管线和 UI／3D MCP 接入分别通过；正式模型／地图替换不在本批范围。12 个验收入口的原日志、图像 SHA、当前代码身份和性能口径见 [本批证据](../review_artifacts/wind_cutout_20261018/evidence.json)。所有 GPU 运行均经 `run_godot_background.py` 的不激活桌面完成。

## 依据

- [Godot 管线编译与预编译机制](https://docs.godotengine.org/en/4.4/tutorials/performance/pipeline_compilations.html)：后台优化管线与首次 shader/材质准备不是相同保证；结合当前引擎实际帧观测选择遮罩兜底。
- [线程安全 API 边界](https://docs.godotengine.org/en/stable/tutorials/performance/thread_safe_apis.html)：工作线程不操作活动场景树；没有为本方案切换整个项目的渲染线程设置。
- [RenderingServer 时间测量](https://docs.godotengine.org/en/stable/classes/class_renderingserver.html#class-renderingserver-method-viewport-get-measured-render-time-cpu)：区分视口渲染 CPU、全局帧设置与 GPU；GPU 功耗状态可能影响时间，不能从固定帧率推断耗时。
