# 固定房屋预制件

2026-10-04 按用户确认的工作方式调整：程序生成阶段允许参数和组件拼接；放入编辑器后烘焙为固定建筑，只能整栋移动、绕 Y 轴旋转、复制、删除。内部几何和材质不能再次拆改。活动门窗、逐层/屋顶隐藏和夜间壁灯保留。

## 存储与运行

- `house_prefab.gd` 在提交事务之前合并静态网格和精确碰撞三角形。楼层、楼板轮廓、屋顶/天花板、翼楼以及各活动门窗分别保留，不将整栋合成不可分离网格。天台楼梯间的天花板身份保留。
- 几何以校验摘要和有解压上限的 Zstd 纯数据嵌入原生记录，使用 `bytes_to_var`，不反序列化脚本或对象。保存重开不依赖生成器再次重建源零件。贴图依赖仍参加资源根校验、预取、缺失检查和素材库打包。
- 相同几何共享渲染资源；渲染坐标的 10 微米量化消除浮点抵消误差，精确碰撞不量化。解码缓存限制 64 MiB，两类网格缓存各限制 512 项。缓存不是额外的源零件节点。
- 加载索引直接读取 CPU 几何，驻留时才上传 GPU。运行网格缓存现在可以完整保存烘焙组件的规格，不因重复几何的临时 GPU 实例而退回逐件加载。
- 地图仍有少量按功能划分的组件记录，编辑器将它们作为一栋不可展开拆改的预制件。这不是“整栋只有一个 draw call”，也不是“场景树总节点数只有几十个”：碰撞体、形状和灯光仍有必要的运行节点。

## 编辑器与 MCP

生成、街道生成、区域/街区生成共用 `BuildingTools.commit`，落地前自动烘焙。`bake_building {id}` 与建筑面板的“烘焙旧建筑为固定预制件”共用迁移事务，可撤销恢复旧结构。烘焙失败在写入文档和历史之前返回。

`list_buildings` 返回 `baked`、烘焙后的 `part_count` 和原来的 `source_part_count`；预览返回 `source_part_count`，明确是生成阶段的数量。`update_building`、`detach_building`、组件变换和刷材质对固定房屋拒绝；开启 `component_edit` 也不会解除固定结构。整栋选择、锁定/隐藏、楼层保护和碰撞检查继续生效。`get_object` 不传输不可编辑的几何 Base64，只返回其摘要、版本和长度。

`save_prefab` 可以保存完整固定房屋，打包贴图并保留活动组件与建筑登记；`place_asset` 恢复新的建筑身份，保留固定结构、地基标高、门窗状态及独立实例变换。不能只保存房屋的一部分。放置进入保留区或碰撞已有物件时无副作用失败。普通物件预制件的旧行为保持不变。

## 验证与性能

GPU 测试均使用 `tools/run_godot_background.py` 的独立后台桌面，测试地图/资源包使用临时目录。

- `test_house_prefab.gd`：七种房型的源记录不变、精确碰撞三角形数量、无源节点展开、活动门窗完整性与开关、楼层隐藏/恢复、壁灯锚点和白天熄灭通过。
- `test_house_prefab_mcp.gd`：真实 HTTP 工具发现、旧建筑烘焙、新建自动烘焙、非法调用无副作用、结构只读、整栋移动复制、门窗开合、锁定保护、撤销重做、素材库导出/放置及保存重开通过。
- `test_house_floor_click.gd --walk --map=<临时烘焙样房>`：31 个房间均能点击地板并跑到目标。
- 正式 `LoadingScene` 进图测试通过；几何缓存命中 577 条组件规格，`mesh_us=0`、`spec_us=0`。新进程实测 8.111 秒（几何/元数据缓存已有，导航缓存重建）；随后新进程在几何、元数据及导航缓存均命中时为 6.703 秒，见 `prefab_entry_cached.log`。并非全冷缓存或女性角色的耗时保证。
