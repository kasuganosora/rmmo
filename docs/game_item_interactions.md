# 游戏道具交互统一

2026-10-02：所有可识别的道具展示、选择区域使用道具格子。交易行遵循用户明确指定的例外：保留信息列表，每行首列为道具格子，随后是名称、数量、卖家、整组价格和操作。内容编辑器不在本次范围内。

## 共用组件与操作

- `inv_slot.gd` 提供背包格子、图标、数量角标和悬停/选中描边。数量采用白字深底，避免与图标上的文字混在一起。
- `item_grid_cell.gd` 复用背包格子绘制，单击或键盘确认只选择道具；`item_grid.gd` 负责列数、滚动、详情提示和稳定选择。商品、对方报价等不生成背包拖拽数据，避免被当作自有道具丢弃或使用。
- 交易动作由明确的按钮执行。数量选择受当前库存限制，背包快照更新后所有打开的道具区域同步更新；物品消失时清除选择并禁用数量。
- 背包原有双击使用/装备、Ctrl 拆分、右键锁定及拖入快捷栏保持可用。格子的外观、悬停和选中反馈与其他道具区域共用。
- 仓库、商店、交易背包、邮件附件、上架选物和制作配方使用共用搜索与分类。筛选不改变已选物品或数量；库存刷新保持筛选条件，重建窗口内容时恢复查询、分类和滚动位置。没有匹配时明确提示，并保留已选物品说明。
- 商店左侧只显示实际上架商品，不补占位空格。买入页右侧空格数量按玩家背包容量减去已占格数计算，并预留购物篮新增堆叠所需的格子；移除商品恢复空位，叠入已有物品不占新格。数量及绑定/强化/耐久合并规则在独立 Inventory 副本上预估，不修改真实背包。空间不足的购物篮条目明确提示可装入数量，成交仍由服务器判定。卖出与回购页也不再固定补齐八格。

商店格子数量专项回归：`tools/test_game_window_review.gd` 当前 313 项通过，`tools/test_ui_request_feedback.gd` 33 项通过。覆盖单商品、无商品、实际容量、购物篮占位/移除、已有堆叠、满包及库存刷新；GPU 日志 `D:/code/rmmo_runtime/review_artifacts/game_windows/shop_slots.log`。

## 先修复，再优化（本轮）

| Before | After | Why |
| --- | --- | --- |
| 邮件和上架提交后立即清空 | 等待成功回执，失败保留输入并就地说明原因 | 避免失败后重新填写 |
| 购物篮批量提交后全部清空 | 每项成功才移除，失败项留在篮中供重试 | 部分成交后不会丢失未完成项或重复购买成功项 |
| 等待中还能再次提交 | 锁定当前表单并显示处理进度，按请求 ID 接收一次回执 | 避免连点、迟到或重复回执造成误操作 |
| 提交期间库存更新后选物区滞后 | 完成后重新读取最新库存和数量上限 | 不让旧库存残留在下一次操作中 |
| 重置依赖聊天提示或立即执行 | 共用窗口内确认，明确费用和范围，可取消，Esc 优先取消 | 让高影响操作有可见的决定点 |
| 道具多时只能逐个找 | 搜索名称或 ID，加消耗/装备/材料分类 | 沿用格子交互并加快查找 |
| 拍卖上架与在售列表共用狭窄区域 | 购买 / 我的出售 / 上架物品分三页，上架页独立选物区域 | 容纳更多物品，价格仍明确为整组售价 |
| 数量框横跨整个表单 | 数量和金币字段使用紧凑宽度 | 缩短视线移动，保留内容空间 |
| 缩放时中文锯齿明显 | 游戏主题用可缩放字体，图标保持像素采样 | 改善文字可读性，保留图标边缘 |
| 新草稿仍显示上一笔成功提示 | 编辑新内容时清除旧提示 | 避免误以为新内容已提交 |

`ui_request.gd` 复用现有 RequestPipeline，保持同步 MockServer 与延迟回执接口兼容。结果经现有游戏桥接应用；3D 桥负责库存等游戏动作，邮件/拍卖面板快照交由对应面板，避免重复应用。没有新增交易接口或改变服务器校验。未来真实传输层的断线、超时恢复不在本轮验证范围内。

## 设计复核

| Before | After | Why |
| --- | --- | --- |
| 商店文字商品行、文字购物篮、点击即回购 | 商品、购物篮、出售、回购都用格子；选数量加入，明确确认交易 | 保持物品识别方式一致，选择与成交分开 |
| 仓库左右两列文字按钮 | 左右背包/仓库格子，固定数量和存取按钮 | 与背包形成相同的视觉和选择习惯 |
| 交易文字报价、背包仅前八组快捷按钮 | 双方报价格子与完整背包格子，支持选数量放入和取回 | 道具多时仍能访问每一组 |
| 邮件附件下拉列表、收件附件纯文字 | 发件选背包格子，收件附件也显示格子，提供取消附件 | 发件和收件保持同一种物品表达 |
| 拍卖行纯文字信息块 | 每行首列道具格子，右侧完整信息及购买/下架；出售从背包格子选择 | 保留信息密度，同时统一道具识别 |
| 战利品图标文字行 | 战利品格子，选中后拾取或全部拾取 | 选择行为一致，避免误操作 |
| 制作配方、材料文字列表 | 配方产物格子、成品格子和材料格子，显示持有/需要数量 | 用实际道具图标识别配方与材料 |
| 数量弹窗、掷骰、任务奖励只有名称 | 使用相同道具格子及数量角标 | 单件物品也保持一致表达 |
| 刷新后数量过期、长背包选择后回到顶部 | 同步数量上限，保留有效选择和滚动位置 | 连续操作不中断 |

任务、日常和成就有结构化 `reward.items` 时展示奖励格子；只有历史描述文字的数据保留描述，不猜测道具 ID。
