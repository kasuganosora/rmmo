# 城镇已准备资源的发布调度（2026-10-17）

本轮接受同优先级草木、独立物件与房屋组件之间的有界轮转，同时保留房屋间原有的就绪顺序。解决的是已准备资源长时间排在房屋组件之后的问题；整区视觉准备仍约一分钟，原生材质单次发布仍有约 0.74–0.76 秒峰值，不能据此关闭整个加载性能任务。

## 实现范围

`scripts/world3d/publication_order.gd` 只选择当前已准备、已准入的发布队列头，同一个资源路径最多连续推进 4 个单位，再让同优先级的其他合格路径获得机会。房屋候选只保留当前排序最前的就绪房屋，以保持贴图复用顺序；不会为了轮转提前处理另一栋更远房屋的材质。负优先级的碰撞、导航和传送需求继续严格采用原来的排序，高优先级需求也不会被低优先级物件越过。

`deferred_asset_loader.gd` 默认使用该策略，`fair_publication_enabled=false` 仅供旧路径对照。没有增加 worker、准入容量、驻留范围或发布预算。原有资源身份、碰撞就绪保护、整栋原子发布、失败清理与撤销保存语义不变；策略对象只保存路径和轮次，不持有模型资源。UI 和游戏使用的加载业务接口未变，没有新增编辑器操作或 MCP 参数。本轮未修改模型、材质、地图内容或重新测试住宅室内。

## 未采用的实验与剩余问题

- 共享预制件贴图后台准备实验把单次峰值从约 716 毫秒降到 151 毫秒，但区域等待从 63.849 秒增至 83.974 秒。两个既有实验开关继续默认关闭，原始证据在 `baseline_trace`、`shared_pixels_trace`。
- 不限制房屋顺序的首版轮转缩短了草丛排队，但两次 ABBA 新策略样本把单次材质峰值提高至 1.095–1.141 秒；旧策略为 0.740–0.825 秒。`obj_1132` 的材质创建由原先复用变成集中加载，因此未采用首版。证据和原实现 `rejected_round_robin_order.gd` 均保留。
- 最终策略接受草木排队改善，不能称为消除了卡顿或实现流畅的整区加载。后续继续处理 `house_prefab.gd` → `runtime_mesh_cache.gd` 的材质恢复阶段，保持身份校验、预算、取消清理及原子显示；不能直接打开已失败的全量贴图准备实验。
- Blender 的植被资源候选仍是离线候选，本轮没有替换正式地图资产。镜头细化、岸草疏密和摊棚材质仍按总布局文档继续。

同日后续已完成材质分帧阶段，详见 `axel_material_publication_20261017.md`：在保留本策略的同版本开关对照中，材质与物件发布单位峰值由 731.047 毫秒降至 223.561 毫秒，区域等待基本持平。上面的原实验数字保留；单张贴图停顿与整区约一分钟等待仍未解决。
