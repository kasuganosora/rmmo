## 必须先消除的三个不确定点

1. **最终骨骼姿态能否进入身体求解。** 09-28 已补最终姿态同步和关节快照，旋转动作与附着物检查通过。后续正式动画仍须复验；身份形态的关节平移/缩放尚未支持，目前会拒绝同步。
2. **布料插件能否消费我们的实际身体表面与服装目标。** 原型需要分轴求解后的控制点，不是重新按标准 LBS 算的身体。先检查插件输入接口，再尝试分体裙和 HW 叠裙；不能为迁就插件偷偷换身体或服装。
3. **捏人形态与服装适配的数据是否齐全。** 先盘点现有形态来源、拓扑匹配、有效范围、关节变化及装备联动。引擎只负责驱动形态，不能创造缺失的美术资产；没有对应形态的控件不能做成看似可用的空滑杆。

每项输出明确结果：可直接用 / 小范围适配 / 阻塞及原因。现成方案失败时记录具体失败条件，再决定补哪个接口或算法，不能静默回到全面自研。

## 实施与完成门槛

- [ ] **躺姿的人体动作调整（2026-09-28 用户新增）**：参考真实人类躺下及躺稳后的姿势，调整头颈朝向、肩肘、手腕与手指的自然放松和支撑关系；分别检查过渡与最终姿势、正侧视角，以及地面/床面接触。属于现有视觉与动作阶段，不排到 MMD 表情之后。动作设计与布料接触分别验收，保留原躺姿作为碰撞回归，不能通过摆开头手来隐藏穿模。

按依赖顺序推进，不把未完成项藏进“后续优化”：

1. **资源与配方盘点。** 确认身体、眼睛、头发、皮肤、内搭、服装和形态的可用范围及来源；保留认可基线。男性与其它已有体型单独列状态，女性通过不能算它们通过。
2. **最小集成选型。** 骨骼时序、布料输入和形态三项先验证，再决定用哪个现成实现。保留原场景/报告作回归，不无限扩展候选。
3. **完成视觉和动作接触。** 自然垂手压裙、转身、走动、抬腿、坐下、躺下；正侧背、手部近景、衣服内外层、身体可见面和材质。保留原版型，不改动作、删网格、发黑或变硬来通过测试。
4. **接通完整捏人链路。** 同一配方在创建页、选角、正式玩家、NPC 与装备预览一致；修改参数、换装、恢复配方、旧配方迁移和两个实例同时运行要验证。使用现有客户端/mocker 数据流程，Go 持久化仍不在本轮。
5. **性能阶段。** 视觉成立后测量并优化，保持同一资产/动作/质量，不换成简单模型宣称达标。当前 186 ms 是旧原型测量，不能当引擎上限或新插件预期。
6. **新增 MMD 二次元表情与标签。** 按 [需求文档](character_expression_requirements.md) 实现和验收，继续使用统一角色语义与实例状态。
7. **交接内容制作。** 写清支持的身体、衣服、形态、表情和动作范围、资产导入规范及仍有的限制，给内容编辑器/NPC 制作提供稳定接口，再转向新手城内容。用户提到未来新手城不等于现在解除正式地图暂缓。

成功标准不是“截图更好看”或“插件能运行”，而是已有明确需求在支持范围内形成可重复的完整游戏流程。完整美术仍需制作和验收，不能因 token 预算有限就降低标准或假称完成。
