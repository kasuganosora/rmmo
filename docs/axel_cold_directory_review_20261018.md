# axel_town 白模：派生目录失效后的首次重建

本轮只处理白模冷目录入口。基础提交 `30ba3c4` 已保存此前源文件认证、索引提交、导航登记和卸载修复。本报告中的“冷”指该地图的派生依赖目录缺失或生成器失效；不是清空操作系统文件缓存、所有网格缓存或所有资源。地图与模型文件不修改，GPU 测试通过独立桌面后台运行。

证据目录：`D:/code/rmmo_runtime/review_artifacts/axel_pipeline_blind_20261017/`。引擎为官方 Godot 4.7.2 `ed1daf0bf`；GDB 使用同提交的带符号构建。地图 SHA 为 `2786d854c6fb1f2a9a2803f1227ab3ab07b7381e217e541e893e173b26f070f8`。

## 30.39 秒的实际组成

`white_entry_final_warmup.json` 的 30,394.620 ms 是从加载入口到白模可用的总时间，并非单独的目录构建时间。该轮选中 323 条记录、1 个模型、2,473 个规格，已有 322 个可复用网格。

| 阶段 | 时间 | 关系 |
|---|---:|---|
| 全量引用还原 | 3,470.617 ms | 1,058 份不同定义，2,369 条记录 |
| 全量业务验证 | 1,603.068 ms | 保留远端记录和所有权约束 |
| 目录构建 | 11,359.194 ms | 包含定义重新认证、分类、源校验、落盘 |

模型准备与目录构建已有重叠，不能把相互包含或并行的 span 相加。构建内部定义批次为 2,559.826 ms；分类长事件累计 5,319.6 ms。10 次 `imported.source_read` 共执行两遍相同的 5 个建筑源认证，单遍总字节数 357,912,912。

## 定位证据与修复

1. **构建后丢弃结果，再从磁盘重新建立加载凭证。** 新增 `Index.build_for_loading()`，工厂内部生成并验证独占目录，完成原子持久化后递归封为只读并发放同类型凭证。增加与磁盘读取一致的 payload 检查；完整引用 SHA、源观察、模型范围、所有权、取消、选区再次验证与最终发布检查仍保留。普通 `build()`/`read()` 继续返回可变对象。任意调用方字典不能借用工厂凭证。
2. **道路数值数组走了通用诊断校验。** GDB 的 14 个分类样本中，11 个包含 `document_schema.validate`，可见字符串拼接/分配以及递归 VM 调用。官方纯 CPU profiler 三轮记录约 520 万次 `validate` 调用。新增无错误文本的 `Schema.matches()`，为布尔消费者批量检查数值数组；道路切换此接口，原 `validate()` 诊断内容不变。保留类型、有限值、长度、枚举、整数、数值范围及道路几何约束。
3. **同一模型路径逐实例重新遍历文件系统祖先。** 分类阶段 912 个模型实例只对应 49 条路径。使用一次同步构建内的路径观察表，发布前仍逐路径重新检查；不跨加载保留文件系统观察。独立 `_classify()` 调用继续拥有独立检查范围。重建前 `_cold_model_hints()` 也复用该次调用的路径观察，并在返回前复查。
4. **资源数组逐标量递归调用 `_safe`。** 数字、布尔、空值数组成员直接执行原有检查，仍逐值扣除总预算，保留深度、NaN/INF、循环、对象/可执行类型等约束。定义完整序列化与 SHA 身份认证仍执行，没有用时间戳代替内容认证。

`profile_cold_index_classification.gd` 在真实地图上还原并验证完整记录，再执行分类，避免 GPU/模型导入干扰。仅道路布尔校验的 ABBA 对照，326 条道路分类均值约从 3.085 s 降到 1.803 s；全部 2,369 行的结果完全相同。加入路径批处理后的分类 ABBA 总均值约为 4.944 → 2.996 s，模型分类约 1.558 → 0.650 s；这些不是全图加载时间。

`profile_cold_definition_checks.gd` 用真实 1,058 份不同定义复现构建认证：旧路径 2.604 / 2.597 s，新路径 1.943 / 2.010 s，均值 2.600 → 1.976 s。逐定义验证完整 SHA、长度、序列化原始字节数完全相同，每次扫描减少 1,334,467 个数组标量的递归 VM 调用。冷还原与目录认证都经过该扫描，但没有删除内容检查。官方分类复测 `cold_classify_official_candidate_summary.json` 中，三轮布尔校验为 1,806,777 次 `matches` 调用；原三轮约 5,206,665 次 `validate`。少量其他组件的 `validate` 仍保留（2,084 次）。

## 正确性验证

- `test_boolean_schema`：272 个对照，包括最后一个路缘点损坏、NaN/INF、未知字段、数组边界、枚举和实际道路几何；与原校验接受/拒绝结果一致。
- `test_resource_scalar_safety`：216 个对照；除接受/拒绝外，对比剩余值预算、祖先栈清理、深度边界、别名、循环、对象型容器和大数组尾部损坏。
- `test_dependency_build_handoff`：17 项；直接交接与磁盘目录完全相等，完整组选择一致，调用方嵌套修改不能影响只读目录；错误源 SHA、变更的位姿/定义/资源被拒绝。补充预取提示的重复实例、缺失模型、越界路径和不同根目录独立调用检查。
- 冷目录加载既有回归覆盖缺失、损坏、旧生成器、写入失败回退、远端错误、源变更和取消；目录证明、道路/城防目录、原始资源读写及道路准备回归保留。

## 测量边界与剩余项

首次真实冷加载的官方 profiler 采集发生引擎异常退出（`white_cold_index_official_baseline.log`，退出码 3221225477），不作为性能通过或改善证据。随后纯 CPU 官方采集完整成功（`cold_classify_official_baseline_summary.json`）；GDB 栈另存 `cold_classify_gdb_baseline_stacks.jsonl`。调试暂停、profiler 重叠时间以及首次启用帧不作为正式加载耗时。

新代码生成器改变也会使程序网格缓存失效。`white_cold_rebuild_1_legacy` 因此只作为预热记录：39.145 s，网格缓存未命中、构建 6.680 s；不得拿它直接和网格缓存命中的候选轮比较。正式对照另行保留相同代码、相同网格缓存条件的缺失目录样本。
