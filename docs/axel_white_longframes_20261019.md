## 累计实现

1. 需求候选只缓存空间成员关系，仍读取当前发布、错误、优先级、事务作用域和地形支撑；按目录变化划分类型，投影 X/Z 为原生 Rect2；排序改为原生数值排序，插入序号保持确定的平局次序；每个需求的固定信息移出部件内循环，相同建筑支撑只按更高优先级重新展开。发布后的新需求留到下一次调度，旧修订不能提前释放已接受任务和内存租约。
2. 大型原始模型的私有、尚未发布部件在限时准备中生成导航、资源归属和分组信息。提交时读取当前索引/导航冲突和地形支撑，批量接收信息；不再复制整个私有输入后启动同步 schema 验证 worker。准备期间唯一允许的门窗姿态写入若发生改变，会在任何发布之前重启准备。公开可变输入仍保留原有校验路径。
3. 正式索引在 build/append 时维护命名空间数量、夹具键、去重后的源范围以及建筑/地表代表信息；只有游戏内部完整单元退役使用该目录。所有范围均为原索引范围，门窗覆盖完整转动范围；当前建筑边界和反向地形依赖仍读取正式索引。先检查当前玩家/相机源，再生成计划，避免对不能卸载的近处建筑不断重做计划。当前 gameplay、native、导航、碰撞、worker、未完成批次和发布占用继续阻止卸载。目录不持有 Mesh/Material，只保存标量身份与范围；重建、追加、卸载同步维护，不读取旧包缓存。
4. 完成退役的私有数组交给资源回收器，逐项放下引用；不递归修改任何仍被其他实例引用的资源。
5. 资源归属使用地图实例 UUID，不能使用模型内部组件 UUID。两种模型可以含有完全相同的内部 ID，不能因此互相占用或提前释放对方的资源。
6. 道路刷面保留未改动完整表面的原数组；只有实际合并多个同材质/布局表面时才构造 SurfaceTool。保留逐三角形的几何、法线、切线、UV、材质和作者数据。没有更改模型资源，也没有以省略白模应有的几何来减少工作。
