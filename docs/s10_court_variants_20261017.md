## 参考与设计边界

- 镜头：[果树住宅庭院](D:/code/rmmo/docs/references/town_required_shots_20261012/02_fruit_tree_residential_court.webp)。宽展树冠、较高树下净空、浅灰泥住宅、深色实木门和窄高百叶窗是本轮目标。参考未明确树种；红果树仍是项目变体，不冒称官方物种。
- 住宅沿用既有 12.5 × 11 m、一层、地台 0.3 m、层高 3.5 m 的生产组件。主体占地与含屋檐、台阶、地下基础的包围盒不同；不能用全模型 AABB 反推房间尺寸。
- 背面、内部分隔、屋顶小窗、连接件及尺寸适配属于项目补充设计。传统窗框、窗扇及围护结构参照 [Historic England 传统窗维护指南](https://historicengland.org.uk/images-books/publications/traditional-windows-care-repair-upgrading/) 与 [传统建筑构造特性](https://historicengland.org.uk/advice/technical-advice/retrofit-and-energy-efficiency-in-historic-buildings/traditional-buildings-and-energy-efficiency/properties-of-traditional-building-construction/)，不以此宣称建筑工程认证。

## 发布失败的闭环

1. 住宅 v2 带空的可选 `GODOT_single_root` 声明。正式发布拒绝按已验 SHA 直接复制；没有放宽生产导入保护。v3 仅移除该无载荷声明，其他 JSON、几何和图片 BIN 保持一致，重新导入的 11 个相机画面与 v2 逐像素相同。
2. v3 正式库导入成功，但真实 HTTP 保存失败。原因是两处沿用烛台语义的 `floor_y=0.30000001192092896` 被目录 JSON 写为 `0.300000011920929`，与源合同精确比较不相等；门窗清单也未正确开放。原失败报告完整保留，不能以“目录里有模型”代替接入通过。
3. v4 将两处语义高度统一到设计值 `0.3`，但正式 HTTP 仍发现两处房间边界 `1.2999999999999998` 与目录中的 `1.3` 不等。v4 同样撤回，不把阶段性修复标成完成。
4. v5 对整份楼层与房间边界采用毫米设计精度，修复两处区域 z 边界到 `1.3`，并增加完整 source descriptor 连续两次 Godot JSON 保存重读预检。检查同时覆盖 36 个分件和 27 个活动件，全部字段精确一致；没有放宽生产比较规则。生成器同步固定楼层与区域描述，不依赖后续手工改库。
5. 元数据修复没有改变网格、变换、铰链和图片字节。v5 重新导入/native 保存重开及 11 视角复验通过，画面与 v2 逐像素相同；v5 正面另行实际查看，其余十图明确引用已查看的 v2 图及逐像素一致证据，不伪称重新人工查看。
6. v3、v4 已通过组件库原生原子保存撤回目录项，源、缩略图和失败证据保留。为解除有限缓存容量阻碍，仅将一份过期隔离验收 native 与本任务撤回的 v3、v4 native 可恢复地移出缓存，保留全部源和元数据，未扩大容量或删除文件。精确清单和收据位于本批验收根。
