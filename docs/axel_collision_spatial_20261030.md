## 问题与实现

此前已去掉已驻留对象的重复网格边界读取，但邻域查询仍取 32 米区块的所有候选。上一轮整图最终索引版本有 663 个候选，查询仍是主要脚本开销。本轮不把此前数字当作新的测量结果。

增加 `collision_neighborhood_index.gd`，将运行时静态几何按 4 米单元索引；大对象自动采用更粗层级，每件最多占 16 个桶引用，避免道路/地形铺满细网格。这是存储策略，不是地图尺寸或对象数量限制。查询范围最多缓存 8 份，宽范围查询不缓存，结果不截断。

候选缓存覆盖查询单元的完整并集，保留对象身份并跨桶去重；每次查询仍检查实际 footprint。发布只失效与新片段覆盖范围相交的缓存，退休只清除含有被移除 ID 的缓存。小批退休枚举退休 ID 与缓存 ID 中较小的一侧，不再反复遍历较大的缓存列表。

索引缓存候选和空间信息，不缓存“碰撞已就绪”：

- `nearby_collision_ready` 每次读取当前碰撞体/合批登记；移除、释放或重新发布在同次查询生效。
- `collision_readiness` 同样接入细索引，继续检查 SceneTree、碰撞层、排队删除、物理发布帧及下一物理帧同步。
- 门扇使用 `BuildingFixtures.prepare_spec` 已计算的完整转动包围范围，实际开合位置仍实时读取。
- 单独的 `collision_mesh` 边界与显示网格边界合并，不能因显示模型较小而漏掉碰撞义务。
- 公共可变源仍采用原粗桶覆盖；其位置、无 changed 信号的网格边界修改和碰撞模式继续实时生效。
- 索引绑定粗索引对象身份和成员版本。公共完整重建显式清除旧细索引；不能误用上一次地图的候选。

## 继续审查时补齐的路径

1. **正常入口的后台索引接入。** 单改 `WorldStream._index_buildings` 不够：正式 `MapLoader` 在 `final_index_preparation` 后台任务中提前建好索引，主线程会跳过重建。新增真实加载断言复现此遗漏后，将细索引纳入现有后台构建，主线程直接接收。
2. **小模型、复制投影和原生预制件追加。** 不只私有大模型包能生成细候选；Deferred 显式传递运行时几何合同。复制投影在现有准备切片中复用已读取的边界，小批无准备游标的追加在原构建循环中生成，并在原提交循环绑定回原始对象。独立可变 API 默认保持原合同。
3. **精确物理查询遗漏。** 初稿仅接入旧式存在性查询；精确物理收据现在共享细候选，而物理同步判定保持实时。
4. **额外外圈扫描。** 初稿把缓存单元并集的排他上界再次当作包含端点，4 个单元变成 9 个。独立测试得到 144 个候选而非 64 个；修正后保留失败样本。
5. **准备与释放成本。** 初始索引不为无碰撞、无结构用途的源额外读边界；BoxMesh 使用 CPU 尺寸。大批候选准备复用原切片，提交采用准备好的桶，不在主线程再次遍历几何。退休同步清除细桶及相关缓存引用；释放测试区分必要的清理收据所有者与隐藏索引所有者。
6. **旧测试夹具失效。** `test_private_publication_packet` 没有设置当前 demand 成员表和取消 token，在发布门口提前返回后访问缺失字段，还打印 `failures=0`。补全当前加载协议和清理状态，现已真正执行门扇状态变化、重启准备、单次提交及导航回调；未通过放宽生产校验修复测试。

`runtime_geometry=true` 是加载器持有不可变几何的显式合同，不是公共对象已不可变的猜测。复制投影的既有签名检查仍执行；准备后修改姿态的用例必须拒绝发布。门窗运行时姿态变化继续使用完整转动覆盖。没有新增模型/纹理资源，也没有改变渲染外观。
