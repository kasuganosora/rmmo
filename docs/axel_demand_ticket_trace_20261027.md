## typed/full-scan 与后续验证边界

在本段 48 个约 500ms observer 快照的**首末差值**中，记录了 504 个 typed full-scan 票据、125,172 个 typed 分类候选行、对照原始未过滤工作 954,852 行，typed partition 重建为 0。此窗口并不与事件边界完全重合。四类远端票据各有 128 次 membership miss，但本诊断没有记录每个 miss 选择 typed 还是 spatial，不能将两组数字逐一对应；typed 行也不能直接加到上表输入行，因为可能存在包含关系。typed 分类本身已经减少候选范围，下一步应调查 membership miss 后重复的 bounds 交集及候选归并，而不是重复建设分类。

可探索以精确索引版本、票据完整身份和变更集驱动的增量 membership/贡献维护：未变的票据贡献可以保留，改变的边界只重算受影响的 owner；最终仍须对当前所有票据按原规则归并排序并读取 live publication、错误、路径和 support。索引注册、重入、owner 替换、同 UUID 别名、候选首见次序、group/scope、inclusive 边界和支持对象变化必须纳入失效规则。远端票据存在大量稳定观察只是筛选方向，不能单凭 UUID 序列作正确性证明。

实现前应构造包含真实规模、重叠票据和连续移动的独立压测，并与原全扫描逐刷新比对 UUID、owner 身份、排序、path heads、优先级、support 和实时就绪；分别记录扫描行、距离计算、候选合并工作、工作量及时间。之后才用同一隔离地图路线做非插桩对照，保留失败和慢样本；普通步行也需单独评估，不能将高速压力推演为普遍收益。
