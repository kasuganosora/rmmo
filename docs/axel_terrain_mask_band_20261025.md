# 地形混合遮罩的过渡带距离计算

## 证据与修改

纹理返回阶段的官方 profiler (`material_submit_review_20261025/demand_official01`) 记录了 `terrain_regions.mask` 五次调用、累计 28.685 秒、15,848,516 次最近线段查询。这是后台函数累计值，含 profiler 开销，不是主线程帧时，也不代表正常游戏精确花费 28.685 秒。

原算法对区域矩形内每个像素遍历所有多边形边。`smoothstep(-feather/2, feather/2, signed_distance)` 在过渡带之外已饱和；这部分逐边距离不影响最终权重。本轮先冻结旧算法作为逐像素 oracle，用实际地图的引用定义和实例 size/state 组合复现，再改生产算法。

新算法按每条边的半羽化宽度扩展包围盒，仅在这条带内计算精确距离，保守外扩一像素处理浮点换算。原来的原生 closest-point、点内判断、smoothstep、区域叠加顺序、RG8 量化全部保留。不增加结果缓存，不修改地图、材质定义或分辨率。每次调用独占一份 `257*257*8=528392` 字节距离暂存，后台并发不共享缓冲区；这是 CPU 暂存大小，不是 RSS/VRAM。

编辑器的既有工作量保护 `work()` 保持原口径，未借性能优化放宽编辑合法性或改动 MCP 参数。UI、MCP 与游戏继续调用同一 `Regions.mask`。

## 独立回归

入口：`tests/test_terrain_mask_band.gd`，headless，`--without-mock-server`，可选 `--map=<axel_town/map.gltf>` 与新外部 `--output`。

覆盖空区域、区域包住整块地形、区域在地形外、凹形、长细条、非正方形地形、两通道不同透明度重叠、不同羽化宽度的固定种子多边形、真实地图以及两个并发 worker。输出与冻结旧算法逐字节比较，包括尺寸、格式和无 mip 合同。

- `mask_baseline03.json`：修改生产算法前，12 个案例（含两个真实地块）全部通过；真实旧算法约 458–508ms。
- `mask_band01.json`：20 个合成 + 6 个真实案例全部通过，真实 oracle 439–533ms、新算法 59–71ms。单块真实距离查询从约 383 万降至 3014–34540。
- `mask_all02.json`：扩展至 17 个真实区域定义，全部输出字节相同；所有真实案例合计原距离查询 **48,237,376** 次，改后 **237,634** 次（减少 **99.507%**）。该轮期间有其他功能测试，时间值只保留，不作为隔离性能验收。
- `mask_checks02.result.json`：全量 mask 测试与既有 `test_terrain_region_data.gd` 均退出 0、零脚本/引擎错误。旧的拷贝、旋转坐标、材料槽与编辑器工作量上限语义继续通过。

最初 `mask_baseline01/02` 的夹具漏合并实例 size，产生脚本错误且未正常完成。原文件保留；修正夹具后才有 baseline03。它们不是游戏路径失败，更不是性能样本。

像素输出完全一致，可沿用现有同版本材质视觉验收；本轮没有交付新的模型/贴图资产，也不把 CPU 微测的倍数当成整图加载收益。真实地图累计结果另行记录，主线程需求刷新长帧在获得独立证据前仍算未解决。

四轮的后台遮罩均为 **17 张 / 2,245,666 B**，主线程遮罩生成和 fallback 均为零；shader 创建 10 / 复用 7；纹理上传 **862,537,776 B**；退休 **504 单元 / 3677 specs**。没有通过少加载/少回收取得收益。返回的需求输入行数会随异步结果完成与移动时序改变，故不声称整个调度工作量逐项相同。

两端旧样本都慢于两个新样本，full-ready 均值从 20.764s 到 13.392s，减少约 **7.371s / 35.5%**。这是本组现有 OS cache 条件下的 ABBA，不是 cold p95，也不是完整游戏（导入模型仍白材质，HUD 等关闭）。17 次后台遮罩累计与入口时间有嵌套/并行关系，不相加计算收益。

B2 的慢帧必须保留：最大需求刷新 **116.494ms**，返回 160.201ms，重载 91.368ms。B1 卸载也有 76.917ms。新算法解决了大量遮罩重复计算，**没有证明需求刷新、卸载、重载所有长帧均已解决**。继续按分段 trace 定位，不把这些样本归为空闲噪声，也不回退已证明的加载/工作量收益。

首轮 `mask_map_prime` 失败不混入此表：纹理角色三元请求迁移漏接了 `_resume_pixel_jobs`，导致第二个包失败、18 需求不能收敛。独立两 worker 队列已复现并修正，之后才启动 `mask2` 的完整 ABBA。完整失败与修复记录见 `axel_editor_dds_adaptation_20261025.md`。
