# 旗帜流式纹理适配（2026-10-30）

## 机制与范围

旗帜换图不再从 Texture2D 读回 mip0、缩成固定 512×1024 RGBA 画布并上传替代贴图。整面图和图案直接复用原图的 StreamedTexture2D，以 StandardMaterial3D detail 层覆盖布料底色。图案沿用原来的 340×350 范围、顶部 170 像素布局，通过独立 UV2 映射；只生成固定 512×1024 的 L8 覆盖遮罩，按矩形共享。这仍有一次小遮罩生成/上传，不能称作完全零主线程工作。

风材质转换同步携带 detail 纹理、遮罩、UV2 和混合模式，同一纹理所有者继续被复用。顶部锚定、尖尾/平头/燕尾几何、金属灯柱与布料不碰撞的现有语义保留。只添加派生 UV2，母版网格不改写。派生 mesh 缓存改为弱引用，并将当前纹理实例纳入身份，避免隐式长期保有纹理或源刷新后继续使用旧对象。

UI 外部文件选择在共享预算内分块复制，再使用原有后台表面导入服务；不再同步解码或任意拒绝超过 8192 的图片。复制完成时若文档、修订或选择已变，只留下导入资源，不修改地图。内容根内的 MCP 请求仍受原路径限制。`set_streetlamp_banner` 不再限制 256 个选择项，但原有有效性与锁定保护继续有效。

修改事务先在私有记录上准备模型和唯一图案，后台并行工作，完成后才一次发布记录、视图和历史；失败/取消不提交半次编辑。多个灯共用一次导入生产者及纹理对象，预算归还。既有地图的可变图片仍可通过原有后台像素准备打开；新换图会保存为不可变的导入路径。

## 预制件补齐

原有打包只复制 PNG，会丢失 STEX、DDS 和 coverage mip，并把不同阈值压到同一路径。新增 `published_texture_copy.gd` 复制编码产物与描述，使用源像素身份及变体描述区分目录，先发布 payload 再发布描述和源图引用。每次 prefab capture 按唯一源路径去重，避免每个灯重复哈希/复制同一贴图。

本次复制仍是既有预制件保存流程的一部分，没有将它宣称为完全后台化。原生文件复制避免在脚本里持有整个 STEX/DDS 字节数组。可移植验收范围仍是同一 content_root 下资源库打包与放置，不等于完整跨根导出。
