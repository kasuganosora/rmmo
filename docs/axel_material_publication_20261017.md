# 城镇材质发布分帧（2026-10-17）

本轮处理原生预制件第一次发布时连续读取多张贴图形成的主线程长停顿。模型、贴图文件和地图内容不变；一次工作单位现在完成一张贴图，或恢复一个完整材质，再让调度器检查本帧剩余预算。整栋房屋仍等全部组件齐全后原子显示。

## 实现与边界

- `material_publication.gd` 沿用 `surface_materials.gd` 的根目录、文件、解码、源 SHA、法线方向、透明度和 mip 处理，不重写贴图加载算法。贴图与材质进入原有共享缓存，容量没有增加。
- `runtime_mesh_cache.gd` 提取单材质恢复函数，同步恢复与分帧恢复共用同一实现。保留存储属性类型校验、空材质槽、顶点色材质的独立副本及共享材质身份。
- `deferred_asset_loader.gd` 每次材质工作后重新执行就绪、需求优先级和碰撞检查；保持当前组件的扫描位置，避免为分帧提前处理下一栋房屋。仍使用既有发布预算、准入规则和房屋间顺序，独立草木继续获得轮转机会。
- 作业不保存跨帧 CPU 图像、部分材质或额外材质游标。取消后没有新的临时图像所有者或准入费用；已经完成的贴图可以继续存在于原有有界共享缓存，不能宣称取消会清空全部 GPU 缓存。
- 已有准备图像／纹理票据路径沿用原来的同步作用域和失效协议。本轮没有启用此前导致区域加载变慢的全量共享贴图准备实验。
- 这是游戏与编辑器共用加载器的内部调度调整，没有新增或修改编辑器业务操作、3D MCP 参数、撤销或保存格式。没有重测住宅室内，也没有改造美术资产。

## 剩余工作

单张大贴图仍需同步读取、校验、解码和创建 GPU 资源，不能在一张图的处理中途让出主线程。本轮不宣称已消除卡顿。后续应针对实际需要的单张贴图准备做有界后台化，保留身份、取消与所有权约束；不能直接重新打开已经因总等待回退而禁用的全量准备实验。整区加载仍约一分钟，场景镜头、植被与摊棚材质细化继续按总布局文档推进。
