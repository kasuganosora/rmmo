# 参考城镇房型与临街排布

本轮按用户提供的动画参考优化普通房屋。五处红框特殊建筑、原道路、河流和桥头保持保护；灰泥浅墙、木构与暖瓦沿用已有材质。建筑效果与部署状态以运行目录 `review_artifacts/town_styles_20261005/`、`town_arrangement_20261005/` 的报告和截图为准，只有后者 `published.json` 表示正式发布。

## 现实结构参考

- [Weald & Downland：North Cray](https://www.wealddown.co.uk/buildings/medieval-house-north-cray/)：提供实物照片、内部空间说明与剖视示意。采用临街端面与侧面都有立面层次、轻微挑层的关系；不复制其中央挑空大厅到普通两层店屋。
- [National Trust：Tudor Merchant’s House](https://www.nationaltrust.org.uk/visit/wales/tudor-merchants-house/visiting-the-tudor-merchants-house)：参考商住结合与紧凑城市建筑的上下空间关系。这是跨晚中世纪至都铎时期的视觉参照，不声称复原某一城镇年代。

动画图负责总体基调和街区疏密，实物资料负责结构关系。本轮使用既有蓝图的楼梯、洞口、屋面求解及支承。3.5 米层高、1.5×2.5 米门洞、1.7 米楼梯净宽与 2 米平台为角色和第三人称相机调整，并非从图片测量。商铺约 3.6～4.3 米退距、住宅约 4～5.2 米退距也是游戏通行、门窗开启与镜头空间选择。

## 进入街区的帧停顿排查（2026-10-05）

用户扩建后反馈走近房屋会卡顿。本轮只改运行时代码，不修改正式地图内容。复现场景仍为第二街区候选，SHA-256 `35fd60fc5cdc449499e414515a5ce583494059c5a74eb8a912838909c8888fd4`；测试走真实角色、点击寻路和碰撞，从 (-114.9, -1.7) 经过原商街到 (-329, 40) 再返回，不能用静止镜头平均 FPS 代替跨区验收。

直接 glTF 加载（编辑器预览使用的路径）的初始往返结果：20 段行走全部到达，帧中位数 17.614 ms、P95 31.363 ms、P99 47.778 ms、最慢帧 762.007 ms，超过 50 ms 共 67 帧。主要尖峰为地块切换后的同步整场景合批准备，单次约 630～731 ms，其中大部分用于重新读取材质属性。GPU 多数约 1～3 ms。报告 `D:/code/rmmo_runtime/review_artifacts/town_street_entry_20261005/baseline.json`。

运行时 `GroundRenderBatches.request_sync` 将收集、分组、替换拆成受预算约束的阶段，旧有效合批在准备期间继续显示；不可变驻留源的分组描述复用，减少重复材质扫描。源卸载仍立即撤销对应合批，旧异步结果不能写入新实例。编辑器 `sync`、`release`、`clear` 清除描述缓存；同步编辑、撤销和 `flush` 保持原来的完成语义。房屋仍保留楼层、屋顶及活动件，不整栋合并。

CPU 碰撞三角面直接按原索引展开，避免为了读取面列表额外生成 `TriangleMesh` 加速树；多表面、无索引表面及顶点绕序有一致性回归。直接 glTF 预览也保留 CPU 碰撞数据。后台工作只计算不可变三角数据，物理资源和节点在主线程接入，遵守 [Godot 线程安全说明](https://docs.godotengine.org/en/stable/tutorials/performance/thread_safe_apis.html) 的物理服务器限制；没有改项目的物理线程模式、缩小碰撞范围或换成堵塞门洞的包围盒。

### Minecraft 与 Godot 大型场景资料核对

这里的 MC 按 Minecraft 理解。参考一手项目资料与代码，不把第三方渲染模组等同于原版引擎，也不直接搬用其实现：

- [Sodium 的 RenderSectionManager](https://github.com/CaffeineMC/sodium/blob/dev/common/src/main/java/net/caffeinemc/mods/sodium/client/render/chunk/RenderSectionManager.java)：区块构建区分紧急与延迟任务，CPU 任务容量和上传开销分别受预算约束。适用结论是后台计算完成不等于可以不受限制地在一帧提交；不照搬其具体常量或 Minecraft 距离。
- [Voxel Tools 性能文档](https://voxel-tools.readthedocs.io/en/latest/performance/)：说明主线程任务时间预算、碰撞形状加速结构成本，以及大量 Vulkan 网格释放可能集中到帧末。它对部分旧版本的观察不能直接证明本项目当前驱动的原因；碰撞问题已用本机测量复现，网格释放仅保留为待证实的定位方向。
- [VoxelEngine 调度实现](https://github.com/Zylann/godot_voxel/blob/master/engine/voxel_engine.cpp)：完成队列与 `TimeSpreadTaskRunner` 分离，并用主线程时间预算推进任务。借鉴的是统一计量接入成本的原则，未引入该扩展或改变项目物理线程模式。
- [Godot 线程安全说明](https://docs.godotengine.org/en/4.6/tutorials/performance/thread_safe_apis.html)：活动场景树和默认物理服务器不能随意从工作线程操作。因此本轮线程只展开私有 CPU 几何，Shape/StaticBody 仍在主线程分片处理。
- [Godot 3D 性能指南](https://docs.godotengine.org/en/stable/tutorials/performance/optimizing_3d_performance.html)：按空间粒度组织渲染与减少提交开销适用于城镇，但整栋合并会破坏既定楼层/屋顶遮挡和活动门窗，仍保留现有分组语义。

据此追加共享预算：正常游戏的流式接入耗时从 3 ms 后台额度中扣除，`GroundRenderBatches` 只使用剩余额度且自身不超过原有 2 ms。这不是全引擎硬性 3 ms 上限：不可拆单次操作和导航/其他逻辑仍独立计时。余额不足时保留原有画面并推迟合批准备/上传；编辑器 `sync/flush` 不受运行时预算影响。生命周期回归新增余额耗尽不隐藏旧画面、同步重建忽略运行时额度等检查，全部通过。

压力测试工具新增诊断参数 `--legacy-collision` 与 `--unshared-budget`，用于在同一份当前代码、同一导航缓存条件下关闭这两项优化做 A/B；正常游戏默认启用，两参数不会改项目配置。原始报告记录开关值，测试结束后再写逐帧和尖峰日志。
