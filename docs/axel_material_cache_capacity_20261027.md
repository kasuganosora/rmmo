## 定位及范围

`reload_official15` 中官方 profiler frame 39901 的调用关系是 Deferred._process →
_publish_ready → WorldDocument._mesh → RiverMaterials.terrain → bind；同一帧29次
texture访问、13次插入后检查及8次完整cache trim（30.171ms嵌套墙时）；按
engine_frame 对齐，frame 39901 后的 observer 间隔70.826ms、最近 publication
分段42.550ms均为插桩样本。原有计数表明正常
整图 `full_insert_budget` 34–35次，但没有逐次记录那个 profiler 帧的原因，因此
不能认定所有8次都是容量替换造成。

固定压测先复现另一种确定的重复扫描：64张相同逻辑成本的热纹理占满预算，连续
替换8张不再被任何热材质/纹理引用的最旧纹理；真实唯一热字节保持不变，旧版保守
并集未扣除删除项，因而8次都触发全扫描。`pressure01_before` 保存四条各8次全扫描
和4条预期断言失败。逻辑成本通过metadata模拟，不是实际VRAM。

## 准确性合同

仅在热纹理硬容量FIFO删除、插入后保守上界超预算的情况下尝试扣除该纹理旧成本。
不持有被删资源：只传递数字 instance ID，避免延长最后GPU owner生命；保守上界仍
超预算、零预算、估算已失效、原元数据数量触发整理等情况继续原完整trim。

shortcut逐项核对**实际当前**热纹理及所有热材质的每个纹理槽，确认所有owner已计入、
成本不大于计账值，被删 ID 不再由任何热条目引用；若存在未记账对象、别名、实际
成本增长或无法证明则回退。检查并回退原始删除后留下的 recency 项，保留完整trim
的清理时机。没有引入新的强引用、跳过必要的预算淘汰、后台提交或延迟超过预算。

早期原型只检查材质identity及信号；独立审查发现 `set_block_signals` 可隐藏槽替换，
不安全。最终实现逐槽读取并有 blocked-signal 反例，不依赖该原型；也保留了
`pressure03` 的原型测试数据，不将其当最终性能。关闭控制开关是同版本的旧扫描路径，
仍含微小新增分支/参数，不能称为字节级旧提交对照。
