## 实现

- `character_axis_assets.gd` 缓存原始只读权重、基础拓扑及显示网格。每个人物独立持有骨骼、适配后的绑定矩阵、姿态、材质覆盖、位置/法线纹理和计算缓冲；静态网格、纹理和 Shader 可以共享。身体材质消费者改为读取 MeshInstance3D 的 active material。
- 预构建显示网格和运行时数据，运行时不再逐面构建同一个网格。数据包只保存基础接触拓扑，显示用的 UV、细分范围和四边面已经包含在网格资源内。
- 材质模板按透明预览/正常3D场景分别保留。纹理预生成 mipmap 并用 Godot 内置 PortableCompressedTexture2D 的 BPTC 模式保存，分辨率、材质参数和 Shader 不变。BPTC 是有损压缩，不把它描述为逐像素相同；25张纹理的64×64网格采样中，最差平均通道误差0.002304、最大单通道误差0.066667（0–1范围）。已核对 mipmap、透明通道及法线纹理，并查看真实渲染截图。API依据：[Godot PortableCompressedTexture2D](https://docs.godotengine.org/en/4.6/classes/class_portablecompressedtexture2d.html)。
- CharacterView3D 等待调用方提供实际人物配方，避免先加载默认男体再立即丢弃；直接使用 CharacterModel3D 的既有自动初始化仍保留。
- GPU 额外输出紧凑的根局部坐标接触点，直接转为 PackedVector3Array，删除每次求解后的21,556点脚本转换。GPU 分组归约人体最低点，脚本只读取337个分组结果，供原有地面支撑使用；CPU参考路径仍保留。没有移除衣服/接触所需数据，也没有降低动作更新频率。
- 头发碰撞未启用时不再刷新碰撞体局部变换，重新启用立即同步当前骨架。负对照诊断可以显式强制刷新碰撞几何，确保关闭碰撞时的测量依然有效。
- 上一轮的装备窗口隐藏暂停继续生效，反复打开不重建人物。

## 2026-10-01 第三轮：索引包、并行接触与明确性能门槛（第84批）

**结论：功能对照通过，性能门槛仍失败。不能把单人中位接近60fps当作稳定达标。** 目标为本机 RX7900XTX 的整帧 p95 ≤16.667ms；真实地图、多人裙装均要单独验收。未减少24次迭代/4子步、原身体或衣服拓扑、碰撞厚度/精度，也未改变姿势或暂停衣服。

### 已实现

- 同帧上传唯一身体顶点及静态三角索引，私有 RenderingDevice 展开为原 vec4 碰撞包；GPU校验有限值和退化面，成功后同时提交目标和碰撞包。非法数据保留旧包；根偏移、额外场景三角形语义不变。局部设备同步与回读仍存在，尚未实现跨角色批处理。
- 每8个基本图元构建二叉包围盒树，GPU逐层归约，覆盖整帧新旧位置并含舍入余量。原顺序树供顺序投影的目标清理使用；静态 Morton 排序树仅服务搜索，接触结果用原始ID处理相等值竞争。
- 保守候选列表覆盖整帧身体运动。查询包围盒超出缓存范围立即重建，新身体包强制刷新；子步窄相位仍计算该子步的真实接触。缓存增加12mm查询余量，仅扩展候选，不改变实际接触厚度。
- 一个64线程工作组并行处理一个布点/布面，按原始接触规则归并。每项最多暂存2048个候选；溢出后执行完整并行搜索，不截断、不漏碰撞。早期串行溢出回退已替换。
- 候选缓存为 `(布点数+布面数)*2055*4` 字节；当前1300点/2496面的裙装约29.8MiB/角色，四人约119MiB（仅候选缓存，不含其他纹理/缓冲）。关闭候选路径时不分配这些缓存。内存成本需纳入后续多人预算。
- `body_block_broadphase=false` 在初始化前设置会同时关闭候选列表，供完整扫描对照。不支持运行途中任意切换这些初始化选项。

### 验收与工具

`test_cloth_performance_regressions.py` 串行执行包布局、GPU索引包、156组GPU结果对照、真实换装生命周期、双手武器最终IK姿态；同时要求退出0、有PASS且无ERROR，不能把脚本异常后误打印的PASS当通过。对照覆盖移动、旋转、尾组、索引逆序、候选复用/越界、新身体包、跨子步复用及强制溢出；最大差0，2481个非零反向修正分量，避免空场景假通过。实际生命周期验证65帧准备、相同装备复用、体型失效、卸装释放，目标包误差0；仍保留原裙摆侧后方外观问题。观察了准备完成截图，未据此宣称所有动作视觉通过。

## 2026-10-01 第四轮：约束批处理与同帧数据传输（第85批）

### 实现与精度边界

1. `cloth_solve.glsl` 共用同一个XPBD约束函数，普通路径与 `RMMO_BATCHED_SOLVE` 仅改变调度。一个工作组处理全衣服，每种颜色内端点互斥，可以并行；保持原颜色先后顺序，每轮执行 `memoryBarrierBuffer` 和 `barrier`。超过256条的单组由线程跨步处理，固定点和退化边的提前返回只退出单条约束函数，不跳过组间屏障。96次结构迭代的dispatch从1536降为96，原24迭代/4子步和额外自接触结构投影不变。设备线程数或X维度上限不足256时回退普通路径。
2. 原生身体输出共用964532字节缓冲，位置0、法线352256、紧凑接触点704512、分组最低点963184起始；shader显式偏移和GDScript常量匹配。一次回读后切分，保证同帧语义。同一RID被多个绑定引用，释放时按唯一拥有者释放，避免重复释放。
3. 身体三角形缓冲在一轮求解内只读，因此上传新帧前直接GPU复制到旧帧缓冲；初次/重建仍用当前包初始化历史。移除每角色每帧约2MiB旧包CPU副本和重复上传。保留目标点历史的原始字节路径：当前目标缓冲会被sanitizer修改，直接复制会改变下一帧动画插值语义。

### 尚未全 GPU 的边界

局部 RenderingDevice 仍执行同一校验核，每次同步读取 4 字节状态，再按 FIFO 顺序向主渲染线程排入展开和求解。它重复一次展开计算及身体点上传，保留同步提交接口下的原子拒绝；不是零同步方案。主 GPU 每帧不再 force_sync，仅初始化/释放等待。第一次原型每次主 GPU 展开都 force_sync，四人待机中位约121ms，已放弃；保留 rejected_resident_sync89.gd 和证据。Godot 官方说明 [force_sync 强制 CPU/GPU 同步且有性能成本](https://docs.godotengine.org/en/stable/classes/class_renderingserver.html#class-renderingserver-method-force-sync)。

身体蒙皮仍由局部 RD 计算，约964532字节的纹理/接触点/边界结果仍回读；衣服 surface-frame 绑定目标仍由 CPU 计算。头顶、坐姿、地面支撑与视图取景还使用身体点。头发接触主要使用骨骼胶囊，不是完整身体点回读的理由，迁移时保留最终骨骼同步即可。

后续依次迁移：主 RD 身体蒙皮与显示纹理 → 同缓冲 GPU 衣服绑定目标 → 身体查询改 GPU 归约/少量查询 → GPU 条件提交与异步诊断，最后去掉同步状态校验。不要直接延迟现有 bool 提交结果而丢掉同帧拒绝/最终 IK。目标是重顶点数据留在 GPU；游戏逻辑、输入和动画调度仍需要 CPU。
