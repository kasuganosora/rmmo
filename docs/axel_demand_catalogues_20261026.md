## 实现与语义

`deferred_asset_loader.gd` 保留每个活跃 UUID 的分数行和哈希槽位，使用仅属于
该队列的递增 epoch 标识本轮首次遇到的候选。每次仍重新计算 live owner、
分数、优先级、来源、支撑闭包和稳定的首次出现序号；当前排序数组独立于缓存
字典的历史插入顺序。失去需求的条目在本轮结束前删除；发布立即删除对应分数行。
完整撤销需求直接 native clear，不新增一遍 GDScript epoch 扫描。

排序后，仅当对象身份、dense rank、优先级和上次提交的路径逐项相同，且当前/
上次没有错误状态，才复用现有 UUID 表、路径数组和有效聚合视图。不同 owner、
同 UUID 替换、原地改 path、排序/优先级变化、scope/支撑/发布变化都保留原提交
行为。读取比对行数单独记录，不把减少写入说成零工作。

发布游标和 admission capacity 仍按原刷新边界重新打开。错误及 `retry_failed`
入口显式使缓存失效：否则错误发生后发布已经改变队首、重试又在下一次刷新前
清除错误时，会错误复用旧队首。`error_before11` 先复现该新实现缺口，修复后
通过真实 `_instance_failed → publication → retry_failed` 回归。

诊断 `--rebuild-demand-catalogues` 同时关闭两项新复用，保留此前其他优化。
这是同代码对照；正式默认开启。没有新增资源校验、目录认证或持久缓存格式。
