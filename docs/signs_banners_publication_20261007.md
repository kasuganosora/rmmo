## 优化与接口

招牌采用 `burned_brackets_v3_20261007` 已审阅版本，总三角面 93,204 → 70,452（约 -24.4%）。三款补齐旗帜采用已审阅优化版，96,640 → 51,072（约 -47.2%）。母版、优化版以及同相机、灯光、曝光比较保留；未为进一步压低面数改变图案、轮廓或布面分段。

GLB 烙画牌与挂架采用共同牌中心原点和 60cm 双挂点。编辑器预制件按既有规则分别以底部中心为放置支点，因此两种模块不能简单以相同地面落点重合；组合时按挂环对齐，或通过物件位置减去预制件内部 record.position 恢复同一源原点。没有新增一键换牌 / 自动吸附面板。布幡独立保留刚性支架和柔性布面，继续使用现有风场；公会徽记仍通过源贴图替换。

牌与挂架各自导出单网格，旗帜两网格；此处没有新增场景生成器。现有共享静态合批仅接收其支持的地面 / 城防 / 房屋记录，普通导入 GLB 不因本次分类调整就自动获得跨实例合批；不把资产内部合并称为全地图合批。

## UI / MCP

素材面板新增分类下拉框；`list_assets` 新增可选 `category` 字符串并返回全部 `categories`，支持与 `query` 同时过滤。共用 `world_editor.asset_items`，不依赖 UI 当前分类。未知分类返回空列表；非字符串由 schema 拒绝。导入新模型 / 保存新预制件后清除当前分类筛选，避免新条目被旧分类隐藏。

沿用现有资源包原子保存与冲突检测。分类变更只修改目录 category 字段，不改原有预制件 payload、asset_id、已放置实例或用户地图。已打开的旧编辑器需要重新进入，才能载入新版 UI 和共享目录。

## 验收入口

`tools/publish_signs_and_banners.gd` 在不激活的私有 Windows 桌面运行。发布前逐项检查源哈希、原生 PBR 通道、实际面数、布料风场和单独渲染；通过后使用真实 HTTP 的 `save_prefab` / `place_asset` 发布与验证。检查分类 schema、UI/MCP 列表一致、名称加分类查询、非法调用无副作用、撤销重做、保存重开及游戏异步加载。

最初将 48 个源 / 发布副本同时放入一张地图的保存调用超时，不能计为通过；随后停止该临时测试。`tools/verify_signs_banners_publication.gd` 改为六张临时地图，每张验证四个正式预制件，覆盖全部 24 项，保存失败立即终止，避免把内存中的旧文档误计为重开成功。异步加载先订阅再启动，避免空图同步完成时漏掉 finished 信号。本次不宣称大批量保存性能已解决。
