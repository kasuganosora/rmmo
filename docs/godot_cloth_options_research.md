## 初步结论

Godot 有可用于布料的内置软体，也存在专用 GPU 布料插件。不能继续以“Godot 没有布料”作为自研理由。优先评估 `alien-life/gpu-cloth-sim`，同时用内置 `SoftBody3D + Jolt` 作基准；确认实际不足后，再决定替换、适配或只补缺口。

这属于方案预研究，不改变已确定的交付顺序：现有身体/服装视觉与接触 → 性能优化 → 新增 MMD 表情。下周先评估现成求解器能否解决视觉缺口，不要求先把当前自研算法优化完，也不因为调查就立即重构运行时。

不要只因资产库标注版本低于本机版本就断定不兼容，也不能反过来视为已兼容。当前工程标记 Godot 4.7 / Forward Plus，实际验证工具为 4.7.2；必须实机试验。`project.godot` 本次未查到显式 `physics_engine` 配置，不能仅根据 Godot 新版本默认值断言本工程实际使用 Jolt。内置 Jolt 与旧扩展配置也不同，试验前读 [Jolt 官方说明](https://docs.godotengine.org/en/stable/tutorials/physics/using_jolt_physics.html)，不要直接改整个游戏的物理后端。

## 我们特有的适配风险

以下为结合本地代码的判断，尚未通过插件试验：

- 新身体不是普通导入骨骼权重直接蒙皮，而是 `female_axis_body.gd` / GPU 分轴求解，展示层再细分。插件即使接受 Skeleton3D，也未必能重现实际身体表面；需要确认能否注入求解后的控制点/碰撞网格，避免插件按另一种蒙皮计算而穿模。
- 当前服装使用源表面绑定、独立固定权重与源约束，不是随便指定一个 Skeleton3D 就能保留原形。必须逐项映射目标位置、自由度、UV 接缝及约束，核对权重方向，不能直接复制数值。
- 保留原材质、透明裁切、法线、双面效果与装饰结构。插件默认布料材质不能取代原裙款；视觉比较固定灯光、镜头、体型与输入动作。
- 插件的身体/自碰撞功能名称不保证连续碰撞、薄层分离与自然受压。不能为通过测试自动抬手或改动作，也不能删身体、删围裙或硬化裙摆。
- 多角色独立状态、换装事务、预热、停止/重置与资源释放都需验证。不要重新造与正式人物系统脱节的角色入口。

## 下周最小评估步骤

1. 固定首选插件提交和许可证，阅读求解/蒙皮/碰撞接口与已知问题；仅取需要的代码和样例，不先批量下载大体积演示资源。此阶段决定是否存在可行接入点。
2. 隔离测试：先跑作者最小示例确认本机兼容，再用原灯光场景、新身体、分体裙和 HW 叠裙。保留当前实现为对照，不直接覆盖。
3. 视觉门槛：自然垂手两侧受压、正侧背与手部近景、连续抬腿/坐下/躺下、内外层及椅子接触。复用原穿透、手边相交、拉伸与姿态不变检查；不能只看演示旗帜或平均帧率。
4. 记录“通过 / 失败 / 未支持 / 未测”，包括源版型、每一层、转换过程与换装。插件若满足需求，优先复用并做薄适配；有缺口则明确是数据适配、插件限制还是需补算法，不能默认继续从零自研。
5. 只在视觉成立后进入正式性能阶段：同一硬件、资产和质量下测整体帧时间及分项开销。作者宣传性能与当前原型的 186 ms 不能直接比较，不能提前承诺帧率。
