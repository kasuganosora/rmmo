# 3D 家具交互（2026-10-01）

当前实现水平座椅/凳子，使用普通 E 交互、共享 CharacterModel3D/AxisRig 和 mocker。表情/衣服外观不在本项调整；不是 Go 联机协议。

## 地图数据

WorldDocument.add_seat(surface_center, dimensions, yaw_degrees) 生成白模凳面，并写入座位元数据。普通地图网格记录或导入网格 extras 可使用：

```json
{"seat":{"surface":[0,0.02,0],"size":[0.55,0.55]}}
```

surface 是家具节点本地座面中心，size 是本地宽/深，单位米；节点还须有稳定 uuid。world_document 保存/加载和 world_stream 碰撞节点保留 seat。朝向取家具本地 +Z，节点可绕 Y 旋转；目前要求水平座面，不支持倾斜家具、床、躺椅或多座位。

## 流程

附近 E → 检查距离/遮挡/地面/站位胶囊/动作能力 → mocker 预留 map+uuid → 保存交互前位置 → 按当前骨架和原坐稳动画的 hip FK 水平对齐 → 共享坐椅动作与座面/足部约束。参考采样不改变可见人物，不发送临时试坐姿。

再次 E、移动或坐下快捷键起身；保持预留直到起身结束，之后回到交互前位置。受击通过现有 sit=false 链起身；死亡保留 death；释放、移动家具、换体型/模型、切图、退出取消约束并清预留。攻击/技能解除家具状态后执行。交互期间只忽略当前凳面的玩家胶囊碰撞，离开恢复。普通NPC和采集交互仍保留。

## 范围与限制

- 当前是单进程 mocker 的占用互斥，不能宣称真实多人网络同步完成。
- 床、沙发、多座位、家具编辑器专用UI尚未实现；现有编辑器的其它未提交改动未触碰。
- 当前使用固定交互前位置作为退出点；坐下过程中若该位置新增动态障碍，退出位置重新寻路/替代点尚需补齐。
- 坐下/起身动作沿用已有动画；本批验证流程与接触，不代表服装碰撞或动作外观已通过。
- 测试 tools/test_world_furniture.gd 使用导出的实际白模地图、E键事件、共享新身体、45度座椅；检查服务端占用、坐稳接触、源FK、移动/受击/死亡、家具移除、切图/退出等。
