## 发现与修复

1. **资源已按 URI 去重，但随后被多层认证重新完整读取。** 同一批资源在解码、引用闭包确认、目录构建、入口提交等阶段重复读取。冷加载计数为 1,058 个唯一资源、6,348 次读取；去掉重复认证后为 1,058 次。暖目录入口为 323 个唯一资源，读取从 1,292 次降为 323 次。保留读取错误反馈和可变地图快照检查。
2. **资源定义解码后仍被递归检查、重新序列化和压缩来证明身份。** 包路径及清单已经给出身份，这些结果不用于生成画面。加载直接采用发布身份和解压头中的原始大小，省去安全遍历、二次身份散列、定义重编码以及导入建筑来源全文认证。新写入数据的身份生成与保存事务不混为一谈。
3. **预制件缓存存在并发冷请求重复解码。** 原实现先查缓存、解锁、解码，再竞争写入，多个线程同时错过时都完成相同重活。现在同一个内容身份共用一个进行中的解码任务，所有等待者收到同一个不可变结果；失败也唤醒全部等待者。不同内容不误并，原容量、独立实例状态和回收策略不扩大。
4. **目录失效仍先遍历过期行；原生分类串行，数字矩阵递归校验重复取 schema。** 失效身份提前退出；原生分类用最多 4 个 CPU worker 并保持原记录顺序；模型分类仍按唯一路径共享边界。数字矩阵公共约束移到行循环之外，布尔结果与详细校验保持一致。严格诊断模式的导入来源按路径归并并行，生产路径不执行这项认证。
5. **模型边界、编辑器打开和预取仍有重复工作。** 入口复用目录已有边界；跨地图预取直接接收刚构建的目录，避免写后丢弃再读；编辑器/MCP 打开和游戏使用相同的信任策略，保存已有包不再重扫资源文件。

## 共享模型结论

实际城镇有 2,369 条记录、1,058 个独立资源定义。其中 912 个直接模型实例指向 49 个 GLB 路径；748 个冻结组件实例对应 375 个预制件负载。冻结组件数不等于房屋数。

没有把“实例多”推断成“GLB 被完整加载 N 次”：初始白模入口实测只解析所需的 1 个 GLB。完整路径上的模型解析、原生资源读取、预制件解码与 GPU 上传分别计数，文件头读取也单独记录。

- 101 个同模型实例：真实 GLB 解析/生成 1 次；实例变换独立，共享不可变网格。
- 同一 CPU 网格连续恢复 101 次：GPU 上传 1 次。
- 模板驻留时返回：新增模型解析 0 次。明确逐出最后一个模板后返回：新增解析 1 次，这是按容量回收后的重新加载。
- 30 万顶点、8 个并发冷请求：解码 8 次降为 1 次，最新测试耗时 237.341 ms → 166.632 ms；输出几何和元数据字节一致。100 次驻留请求不增加解码。
- 城镇第一轮冷加载预制件本身已做到 375 个身份各解码 1 次，不能把上述并发压力测试收益冒称为这次整城加载的 8 倍收益。
