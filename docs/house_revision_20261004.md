- [Historic England：传统窗维护](https://historicengland.org.uk/images-books/publications/traditional-windows-care-repair-upgrading/)：窗框与窗扇区别，五金随所属构件运动。

## 实施与验收次序

1. 几何与空间：连续踏步、通透栏杆、紧凑折返楼梯、更合理房间与三层体量、抬高台基、屋顶/相接墙裁切、消除共面接缝。
2. 门窗细节：铰链/轴销、双侧门把手、窗把手、窗板五金、窗帘，所有活动件保留程序控制；店面真实售卖开口。
3. 默认库 2K PBR、更换外墙/门材质，修正相机遮挡与天空/阴影；动态视角和七款样房近景检查。
4. UI/3D MCP 共享参数与操作，真实 HTTP 合法/非法、撤销重做、保存重开，角色上下楼及门窗状态回归。
5. 之后才测量并优化逐楼层静态渲染、碰撞/加载及上楼卡顿。不能整栋合并，不能把构件数直接当成 draw calls。

4 米层高、加宽楼梯平台、入口缓台阶属于角色与第三人称/VR 舒适度调整，并非声称历史住宅均采用这些尺寸。“小房间至少 1.5 倍大小”先以可用净面积增加至少 50%作为比较口径，同时检查净宽与家具空间，不缩小角色或调整 FOV 掩盖空间问题。

不能把有效缓存结果说成所有首次加载均小于 10 秒。修改几何生成代码、原地图或角色通行尺寸会使相应缓存失效；不支持缓存的资源仍走原生成路径。本次没有清空操作系统文件缓存或显卡驱动缓存。中间版本真实界面曾出现 11.509 秒，因此继续优化了校验与合批标识，最终才取得上面三轮结果；这些数据也不代表任意后台负载或几十栋正式城镇均能在相同时间进入。

对应热点的实现：

- 增加纯数据几何/实例规格缓存，按源地图 SHA256、引擎版本和相关生成器源码摘要失效。保存 CPU 顶点、法线、切线、UV、材质描述、完整碰撞尺寸和活动件闭合姿态，不反序列化脚本/对象。12,812 个规格与 916 个几何键可直接恢复，避免每次重做涂装和几何。缓存长度、载荷摘要、数组布局、引用索引及类型校验失败时回源生成。
- PNG/JPEG/WebP 的解码像素和 mipmap 无损缓存，源图 SHA256 及法线方向参与失效。三个后台任务解码，和元数据/几何读取、完整文档校验重叠；路径仍先通过资源根和存在性检查。新地图加载时检测同路径贴图内容变化，替换进程内旧纹理及材质，不复用陈旧图像。
- 导航缓存以完整几何、实际角色通行高度和导航实现摘要为键，只保存完整烘焙结果。动态门窗仍独立参与原通行检查；无缓存或坏缓存重新烘焙。
- HUD 的中文文本改用原生字号字形缓存，避免每个新进程生成大量 64px MSDF 字形；实际 HUD 构建从约 2.6 秒降至约 0.25 秒，已检查正常尺寸截图。界面和世界资源提前异步读取，角色配置与地图读取并行；256×256 私有离屏视口预热共用天空/角色绘制，随后立即销毁，最终画质选项保持原设置。
- 初始加载遮罩内，可合批的源构件先保持 CPU 网格，仅上传最终渲染组；透明、单件及不合批物体恢复独立 GPU 网格。碰撞直接使用尺寸并共享不可变 BoxShape，避免读取 PrimitiveMesh 包围盒触发无用渲染网格。楼层、屋顶/天花及门窗仍独立，不合成不可拆分整栋。
