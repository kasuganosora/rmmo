# 编辑器增删按受影响记录提交（2026-10-07）

本轮依据 `editor_issue_static_review_20261007.md` 的 Grok 初审及独立复核，在用户明确开始修复后实施。仅使用临时测试地图，不修改用户地图，不改 `walk_mode.gd`、`world_authority.gd` 或保存核心。

## 实现

- 普通 UI 资产、box、普通地面笔划、NPC/采集/传送摆放与当前 3D MCP `place_asset` 通过 `_commit_records` 提交。普通删除同时收集自动瓦片实际变化的邻居。新建/转换地形、普通复制、预制件放置和整栋复制/删除也可按 UUID 更新视图。
- 仅释放受影响的编辑 visual 和独立 collision body；地形源变更时才运行地形邻接更新，并刷新它返回的受影响 UUID。新节点继续经过既有作者楼层装饰、隐藏判定、拾取与行走碰撞生成。
- `GroundBatcher.release_sources` 只失效这些旧节点的描述及所属批次；其余捕获的几何/材质描述保留。随后 `request_sync` 在既有帧预算中整理成员及准备派生几何，编辑调用不再同步执行全场 `_prepare_step(0)`。重新分组期间原始节点可见，未变批次继续使用。
- 普通对象变化和普通选择不再重扫城防碰撞；城防源或其批次选择变化仍做必要同步。完整重建会显式失效此状态。城防位姿变化也失效，避免撤销未选中城防时留下旧碰撞。
- 记录事务撤销/重做按 UUID 比较，更新有差异和被移除的记录；建筑登记变化可与记录一起恢复。改变全局作者视图/环境等地图元数据仍保留其完整刷新路径。
- 普通物件列表只插入、更新或删除相关行，保留其他 `TreeItem` 和文档顺序。组成员变化当前仍刷新列表结构，**不会因此重建 3D 场景**。无关建筑/地形面板不再随普通增删刷新。
- UI 普通地面一笔内重复访问同格时，`WorldPaint.add` 返回空 UUID 即结束，不再置脏、刷新或重复生成记录。自动瓦片空变化同样不提交视图更新。
- 地形绑定变化可通过 `settings_form.update_values` 复用既有河岸/坡度控件；字段或材质目录不兼容时才走原控件构建路径。更新前预检，使用无信号数字/布尔赋值，不把表单重新绑定变成作者修改。

工具清单、参数 schema、返回结构及保护规则未变化；没有注册旧二维接口。UI 和 3D MCP 仍使用同一文档事务、选择与视图提交。更新了 `world_editor_mcp.md` 的操作说明。

## 保留的成本和边界

- 文档 checkpoint/undo 仍保留原完整事务快照，UUID 查找和部分成员整理仍可扫描记录。没有修改保存或撤销的数据格式。
- 一个复杂新模型的导入、一个大地形的几何/邻接及碰撞生成仍可能形成长操作；本轮保证不把无关全城几何一起重建，不保证任意单资源无停顿。
- 批次成员整理是按帧的完整成员清单比较；复用未变几何描述，不能称为完全 O(受影响对象数) 的调度。
- 组物件列表结构、全局作者设置及其他仍明确调用 `_rebuild` 的高级生成工具不在“全部增量完成”的宣称内。
- 编辑视图根的记录 extras 仍是建树时快照，和既有移动/局部刷新行为一致；保存必须以 `_doc.records/map_meta` 为作者真值，不可改用编辑视图根元数据。
