# 内容编辑器布局审查：apple-design（2026-10-12）

> 实施状态（2026-10-13）：用户已授权修复，A1–A8 及紧凑布局、字号、概览与散布反馈已实施。下文保留原始审查证据；实施与回归记录见 [布局修复验收](editor_layout_fix_20261013.md)。

## 结论与范围

当前布局有明确的使用效率问题，集中在功能归类、长表单、操作上下文与状态可见性。建议先改善这些 P2 问题，再统一视觉层级；没有证据支持通过增加动画或模糊效果改善当前工作流。

依据用户指定的 [emilkowalski/skills](https://github.com/emilkowalski/skills) 中 [apple-design](https://github.com/emilkowalski/skills/blob/main/skills/apple-design/SKILL.md)，已读取本机同名技能和远端原文。采用其中的响应、空间一致性、字号适应、可控性、分组及明确导航原则。这是该作者的设计指南；下面的优先级、布局尺寸和改法是对本项目的审查判断，并非 Apple 官方强制规范。

本轮只审查，未修改生产 UI、业务操作、地图或正式模型。新增 `tools/audit_editor_layout.gd` 作为临时地图的只读布局探针；在不激活的独立桌面拍摄 16 张完整编辑器截图，均无角色人像。未恢复历史“未解决-跳过”的性能专项，也没有以小测试场景代表整城运行性能。

## 实拍条件

- 当前 Godot 4.7.2 Forward+，使用之前已保存的临时作物地图，保留生产编辑器完整控件。
- 1920×1080、1366×768、1024×768 三种物理窗口；保留项目 `1280×720 + canvas_items/expand` 缩放设置。前两种同为约 1280×720 逻辑画布；1024×768 对应 1280×960。不能把截图物理尺寸当布局逻辑尺寸。
- 默认侧栏逻辑宽 330，1920 截图中约 495 物理像素；画布逻辑尺寸 942×586。单纯看截图不能得出“侧栏固定 500 像素”结论。
- 额外探测侧栏拉宽和临时字号 14→18；字号探测只改该测试实例，不代表已有用户设置入口。
- 两轮最终日志：`D:/code/rmmo_runtime/editor_layout_review_live.log`、`editor_layout_supplement_live.log`，均正常结束；本次是审查证据，不是修复后的通过验收。

## 优先处理的发现

### A1 · P2：主要工作入口不显眼，工具栏等权控件过多

顶部同时呈现摆放、选择、NPC、采集点、传送点、网格、行走、三种变换、坐标轴和视图等约 17 个按钮；地形、建筑、城镇布局则藏在同一个 11 项工作面板下拉里。用户需要记忆入口，界面很难表达当前主要任务。

证据：[workspace.gd](../scripts/world_editor/workspace.gd) 的 129、144–150、199–230、398 行；实拍 `1920_library.png`、`1920_city_top.png`。当前已有 `HFlowContainer`，本项不是指控旧版单行工具栏硬截断。

建议把选择/变换、相机/行走、添加实体分为明确功能组；NPC/采集点/传送点归入“添加”。侧栏给素材、场景、属性、地形及常用生成任务可见入口，低频任务留“更多”。保持快捷键和工具位置稳定。对应技能 §16 Purpose、Simplicity、Grouping、Wayfinding。

### A2 · P2：地形操作归类错误，常用设置被长表单淹没

“新建 / 转换”实际还包含已有地形换材质、区域绘制、农田垄沟、陡坡露岩和河岸材质；编辑现有地形的用户很难预期这些操作藏在这里。实拍内容高度约 3530 逻辑像素，可视区仅 578，约六屏内容。主标题及说明仍写“地形雕刻”，与当前子任务不完全对应。

证据：[terrain_panel.gd](../scripts/world_editor/terrain_panel.gd) 43–91、107–115 行；`1920_terrain_create.png` 和 `layout.json`。

建议按“雕刻、地表材质/区域、河道、洞穴、新建”组织，垄沟放在选中区域的上下文中；工具专用参数只在对应模式出现。长说明改为一行任务提示加可展开帮助。当前地形页签已经支持溢出箭头，不把页签滚动本身列为 bug。对应 §16 明确命名、常用路径优先、分组映射。

### A3 · P2：城防创建和已冻结对象管理混在同一张表

城防整体展开后约 3639 逻辑像素高，可视区 578，约六屏。折线/圆形/样条、塔楼、材质和门参数大量平铺；预览、应用、解除关联、删除等按钮同样宽且同样强调。载入已冻结城防仍显示可编辑结构字段和应用按钮，仅末尾文字提示结构不可改，后端再拒绝重生成。

证据：[fortification_panel.gd](../scripts/world_editor/fortification_panel.gd) 18–53、129–134 行；[fortification_tools.gd](../scripts/world_editor/fortification_tools.gd) 73 行；`1920_fortification.png`、`1920_fortification_bottom.png`。冻结态部分为代码证据，此轮没有再写入或生成城墙。

建议明确“创建方案 / 管理已生成对象”，按形状显示字段，分组为布局、结构、塔楼、材质、城门。冻结结构只读并在顶部说明，突出仍可操作的门状态和地形跟随。预览/应用固定在面板操作区；删除和解除关联单独分组，不增加每次编辑的确认弹窗。对应 §16 可预测性、简洁、操作自主性。

### A4 · P2：切换变换工具会强制替换当前工作面板

已经处于选择模式，在地形面板选择旋转后，工作面板仍被切成属性页。此轮实际记录 `MODE_PANEL_BEFORE 地形 → MODE_PANEL_AFTER 属性`，可能迫使用户反复回到刚才的任务面板。

证据：[world_editor.gd](../scripts/world_editor/world_editor.gd) 1090–1114 行；`transform_forces_inspector.png`、补充日志。

建议将工具状态与面板状态解耦，W/R/T 切换保留用户主动选择的面板；提供明确的属性入口。宽逻辑视口可允许固定检查器，小视口保留单侧栏。对应 §7 空间一致性、§16 Agency/Familiarity。

### A5 · P2：地图身份、未保存状态和操作错误缺少稳定位置

打开后底栏只显示 `map.gltf`，顶栏没有地图名或未保存状态；搜索或换工具后又被提示文字替换。长操作错误同样写到底栏，启用省略显示，还可能被后台“缩略图已生成”覆盖。用户难以持续确认正在编辑哪个地图、是否需要保存、刚才为何失败。

证据：[world_editor.gd](../scripts/world_editor/world_editor.gd) 37–40、1003、1011、1105 行；[workspace.gd](../scripts/world_editor/workspace.gd) 29–125、402、422–423 行；[city_panel.gd](../scripts/world_editor/city_panel.gd) 175–176 行。当前河道有自己的 message，不将“全部面板都没有局部反馈”作为结论。

建议顶栏常驻地图显示名/资源包、未保存标记、保存状态，完整路径放详情；表单错误靠近提交区，保留到相关操作修正或用户关闭，能查看完整原因。工具帮助和后台完成提示不抢占关键错误。对应 §16 Wayfinding、状态/完成/警告/错误分流。

### A6 · P2：部分标签与字段没有保持空间绑定

吸附标签和数值框分别作为 Flow 子控件。实测侧栏宽 840、画布宽 432 逻辑像素时，“缩放吸附”标签在第一行，值“关闭”独自换到第二行。默认宽度正常，本项触发于用户拖宽侧栏后的窄画布。

属性栏还有独立问题：XYZ 放在 SpinBox 内作 prefix，宽度最低 85；旋转 Y 为 `133.113` 时，截图只看到数值而看不到 Y。字号 18 探测也复现。内部标识 `vegetation_… · asset` 又占据属性标题，无法快速辨认素材名称。

证据：[workspace.gd](../scripts/world_editor/workspace.gd) 231–253 行；[inspector.gd](../scripts/world_editor/inspector.gd) 52–54、147 行；`snap_group_wrap.png`、`1920_inspector.png`、`1920_inspector_font18_probe.png`。

建议每个标签和下拉框作为整体换行；XYZ 做输入框外的持久标签，数值区可扩展、长值可编辑且不掩盖轴向。标题优先显示用户名称/素材名，UUID 放次级详情。对应 §15 字号与布局共同适应、§16 Grouping/Mapping。

### A7 · P2：已存河道缺少可发现的编辑入口

面板已有目录查询能力，但用户只能手输河道 ID，再点“载入此 ID 的已存河道”。同一长表单上还放着加载、删点、删除整条河道、校验和生成，动作作用对象容易混淆。

证据：[terrain_river_panel.gd](../scripts/world_editor/terrain_river_panel.gd) 17–33、47–56 行；`1920_river_top.png`、`1920_river_bottom.png`。该页内容约 1237 逻辑像素，两屏以上。

建议顶部“新建 / 已有河道”选择和名称目录，能从场景选择关联；点列表动作紧贴点列表，整条河道动作在独立区域，ID 置于高级信息。校验/生成与结果区固定在底部。对应 §16 Wayfinding、Familiarity、直接映射。

### A8 · P2：键盘焦点不可见，素材网格不支持完整键盘选择

Button/OptionButton 的 focus 样式为空；素材按钮为 `FOCUS_NONE`。现有 1–9 快捷键只覆盖前九项，没有通用方向键网格导航。鼠标用户不易察觉，但键盘操作路径不完整。

证据：[workspace_theme.gd](../scripts/world_editor/workspace_theme.gd) 28 行；[asset_palette.gd](../scripts/world_editor/asset_palette.gd) 69 行；[world_editor.gd](../scripts/world_editor/world_editor.gd) 322–323 行。

建议可见且克制的 focus ring，素材网格方向键导航、Enter 选取、当前项滚入视野；保存快捷键与编辑器视口快捷键边界保持清晰。对应 §14 可访问性、§16 桌面灵活性。本轮是代码审查，没有宣称完成屏幕阅读器兼容测试。

## 次级改进

- 城镇概览为固定 200×166 逻辑像素，城镇页或地图含道路/参考图时覆盖画布并接收鼠标；缺少可见收起入口。建议可折叠并保存偏好，窄画布使用紧凑形态。代码 `city_overlay.gd:54–58,136–139`。默认 942×586 画布约占 6% 面积，不用夸张成遮挡大半画面。
- 散布筛选后隐藏项仍可保持选中，建议常驻“已选 N / 8”与可移除的选择摘要。代码 `scatter_panel.gd:70–75,98`；本项仅静态审查。
- 统一标题、标签、解释和主操作的视觉层级。当前大量等权的矩形按钮和说明文字让“应用”和次级管理动作不易扫读。优先调整分组、字号/字重和留白，保持专业工具需要的信息密度。
- 1024 物理宽度下项目统一缩放使 14 逻辑字号约为 11.2 物理像素；没有明显控件整体截断，但可读性需用户可调字号/缩放支持。此轮字号 18 探测只证明现有布局能扩展部分最小宽度，不等于已有系统文字大小支持。

## 建议布局与实施顺序

以下是方案建议，尚未实施。

|区域|建议职责|
|---|---|
|顶部文档栏|地图/资源包、未保存和保存状态、文件与全局命令|
|主工具栏|分组呈现选择/变换、坐标与吸附、相机/行走；其他实体从“添加”进入|
|左侧任务区|可见常用任务入口；当前任务的对象选择、必要参数和高级折叠组|
|任务区底部|该任务的预览/应用/取消及持久结果，随内容滚动仍可见|
|中央视口|持续观察和直接操作；概览、提示可收起，不用长期浮层遮住编辑位置|
|可选检查器|宽逻辑视口可固定；窄视口显式切换，切工具不自动夺走任务页|
|底栏|当前工具提示、坐标、非关键后台任务；重要错误有对应任务区域承载|

1. 先处理地图/保存状态、A4 面板跳转、A6 标签换行和数值轴向，以及错误的持久展示。这些改动小且直接影响日常操作。
2. 再拆分地形/城防任务及状态，固定操作区，给已有河道提供目录。保持 UI/MCP 共用既有业务操作，布局调整不另造生成/保存路径。
3. 最后整理工具入口、焦点导航、可折叠概览、字号和面板偏好，再统一视觉样式。高频精确变换继续 1:1 响应；弹性、惯性等只在确有交互收益时评估。

建议验收：切换 W/R/T 不丢任务面板；任意合法分栏宽度标签/值不分离；旋转大数值时 XYZ 持续可见；修改参数后不用滚六屏寻找提交；已冻结结构输入明确只读；失败信息不被后台缩略图消息覆盖；地图身份/未保存状态持续可见；键盘能选择第十项以后的素材。截图以逻辑尺寸和用户缩放设置共同记录。

- 加载已有阶段、进度和用时；保存也有独立进度条。属性小数实时应用及一次编辑撤销已实现，本轮不重复登记为未修复问题。
- 折叠高级项、原生撤销、临时预览及 UI/MCP 共享业务应保留。
- 旧 `tools/test_editor_usability.gd:68` 仍断言地形仅两页，当前实际五页。该测试需要随后续布局实施更新；此轮未运行它，也不声称历史测试能证明当前全部新面板可用。
- 本轮没有测试所有 OS 缩放、全部长名称、屏幕阅读器、鼠标手势延迟或完整保存过程，也没有制作/实施新 UI 原型。
