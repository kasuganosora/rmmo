# 商街高低与排布节奏修订

用户指出首批街道虽然改变屋顶，沿街仍主要是连续一、二层楼，缺少自然城镇的高低错落。本轮保持 16 商铺、8 住宅和道路/地标保留区，重新安排沿街体量；不把之前的功能通过当作美术通过。

## 资料与采用范围

- Bao, Yan, Mitra, Wonka, **Generating and Exploring Good Building Layouts**, ACM TOG / SIGGRAPH 2013，[作者论文](https://archive.ymsc.tsinghua.edu.cn/pacm_download/38/285-2013_TOG_GoodLayout.pdf)，DOI 10.1145/2461912.2461977。借鉴把合法性硬约束与偏好软约束分开的思路；本项目用离散候选搜索，不是论文局部空间与门户探索算法的完整复现。
- Vanegas 等，**Procedural Generation of Parcels in Urban Modeling**, CGF 2012，[出版页](https://onlinelibrary.wiley.com/doi/10.1111/j.1467-8659.2012.03047.x)。地块是道路和房屋之间的独立层次；本轮保留已描好的道路，仅在既有沿街带上以面宽和间隙推进站位，没有声称实现论文的全街坊分割。
- [Esri CityEngine 官方规则建模说明](https://doc.arcgis.com/en/cityengine/2023.1/get-started/get-started-rule-based-modeling.htm)：高度可作为带范围的规则属性。这说明规则化变化是成熟做法，但独立均匀随机本身不能保证相邻高度有节奏；本轮再加配额、邻接和周期惩罚。
- [National Trust：Tudor Merchant’s House](https://www.nationaltrust.org.uk/visit/wales/tudor-merchants-house/visiting-the-tudor-merchants-house)：实物为三层商人住宅，用于三层商住体量的结构参照。并非所有中世纪城镇都应有相同比例；本轮三层占比来自用户的“少量”要求和实际街景判断。

## 本图的规则

`tools/town_frontage_rhythm.gd` 为离线制作配方，固定随机种子，搜索 4,096 个高度序列。先剔除连续三栋同层数、三层楼过近的序列；商铺两侧各安排三层体量。然后对连续相同高度、重复高低交替或三栋循环、两侧镜像及缺少前段高度焦点评分。选择后再按复用次数、相邻房型和屋脊朝向挑选固定预制件。

- 16 栋商铺：4 栋一层、9 栋二层、3 栋三层。
- 8 栋住宅：2 栋一层、5 栋二层、1 栋三层。
- 全批三层 4/24，约 16.7%；这不是论文或历史测量给出的比例。
- 商铺退距 2.8～5.1 米，住宅 3.8～6.2 米；推进间隙 2.7～5.8 米。仍由共同占地校验处理真实碰撞和保留区，冲突时后移，实际间距可能更大。
- 屋门仍朝向道路，不给建筑随意倾斜或把屋前空间塞满来制造“乱”。房屋宽度、屋顶与楼层变化共同构成街景；规划只限制本图自动布局，不限制手动部署。
- 两款三层商铺采用 3.3 / 3.4 米层高，紧凑双层住宅采用 3.15 米层高；门洞、楼梯与平台沿用角色通行尺寸。这些是游戏尺度调整，不能从参考图推断为实测尺寸。

原八款参数保持不变，新增 `town_tall_shop`、`town_tall_eaves_shop`、`town_compact_home`，共十一款，由房屋面板和当前 3D MCP `list_building_templates.town_presets` 共用。生成仍使用已有预览、生成并冻结、烘焙和撤销事务；没有重新启用二维工具。**整条街的候选评分器目前是本图制作脚本，尚未提供通用 UI/MCP 自动排布工具**，不能宣称自动街区编辑功能已交付。

## 整栋窗口方案

仔细对照用户归档的原图 02、04、07、08、09、14 及 [新窗口特写](medieval_town_visual_references.md#2026-10-05-窗口细节补充与用户硬性要求)，制作四套：细长双段 X 斜撑、双菱格及托架窗台、圆拱分格、细长格窗及窗板。圆拱包含真实墙体拱肩填充、木拱框和石拱套，下部单扇可开启，上部拱形玻璃固定；窗台托架有墙面支点。窗套、玻璃和木格使用各自材质，不把所有棱柱错染为灰泥。

现实参考：[Historic England 传统窗保护指南](https://historicengland.org.uk/images-books/publications/traditional-windows-care-repair-upgrading/)、[Cadw 窗门保护说明](https://cadw.gov.wales/windows-and-doors)、[Weald & Downland 的 Walderton 实物建筑](https://www.wealddown.co.uk/buildings/house-from-walderton/)。这些用于核实框、分格、窗套和洞口结构；四种方案按动画风格组合，不声称同属一个历史地区/时期。游戏常规窗宽约 0.92～1.05 米、窗台高 0.8 米、窗洞高至 1.85 米，按现有墙体与角色尺度调整；老虎窗随可用墙高缩小。这些不是截图测量值。

四套方案按独立种子在整栋之间选择并平衡数量，避免相邻相同；绝不逐窗随机。首批 24 栋每套 6 栋。实际所需 18 种房型/窗型组合在编辑器生成并冻结，静态框、石套、托架等进入合并网格；保留活动窗扇/门/窗板身份。运行时不再生成这些细节。

`tools/test_house_window_styles.gd` 检查四套完整三层带老虎窗模型、全部几何记录有效、随机只解析一次、种子可重现；圆拱额外对真实三角网格射线验证顶部中央可穿透、两角墙体封闭。`tools/build_town_window_library.gd` 逐款通过真实 HTTP 烘焙并检查两位数构件、保存重开及近景。当前几何测试与 HTTP 窗口参数测试均通过；最终部署以本页后续发布记录为准。


窗口样本复查后收紧了直窗石过梁与窗套的接缝，并加入几何接触回归。最终样板库 18 种组合全部通过，固定构件 15～66 个；近景 `detail_cross_lattice.png`、`detail_diamond_lattice.png`、`detail_round_arch.png`、`detail_tall_shutter.png` 位于 `review_artifacts/town_window_library_20261005/`。街区 24 栋房屋合计 940 个固定构件（上一版 1,604），完整地图 2,211 条记录，非房屋仍 1,271 条。组件数减少不等于三角面、draw call 或加载耗时同比下降；圆拱几何和更多样板仍需整图运行报告。

## 进图异步准备与加载热点（2026-10-05）

用户反馈“为什么加入时必须加载这么多地图索引，不能异步”。分阶段测量确认，旧进度文字“建立地图索引”实际包含全部地图网格、材质和流式记录构造；真正的空间索引只有约 0.07～0.09 秒。正式 glTF 为 129,581,442 字节，2,211 条记录。瓶颈主要是重复材质/资源路径校验、预制件恢复、地形覆盖图及道路/地形网格计算，不能单靠把字典索引放入线程解决。

本轮实现：

- 地形邻接、区域覆盖图、地形/道路/垄沟顶点数组由后台任务准备；主线程处理房屋的同时推进地形任务。ArrayMesh、材质和场景挂接仍留在主线程，按帧预算执行。同步编辑器与异步运行时复用相同几何算法。
- 渲染/碰撞分块、整栋建筑分组、房屋与支撑地面的依赖索引统一由 `stream_index.gd` 构建，运行时加载在后台调用；移交后不再重复遍历建索引。
- 网格缓存由独立任务读取，主线程轮询完成；写缓存不再延迟场景移交。取消和正常退出会等待本加载器的后台任务收尾，正常取消等待使用逐帧轮询。
- 材质定义和文件权限检查使用单次加载范围的结果复用；修改资源根、文件缺失、非法材质仍拒绝。缓存只优化派生数据，不跳过原生文档校验。
- 某条预制件或动态材质不能直接恢复时，仅该条回退；之前一条不支持就丢弃整份可恢复记录。缓存按 UUID 匹配，准备顺序改变不会错配。此城镇可直接恢复 883 条记录、996 个缓存网格。
- 进度改为“准备地图几何与材质”“准备地形数据（后台）”“构建空间索引（后台）”，避免把所有工作误称索引。
