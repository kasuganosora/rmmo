## 已取得的素体

`VaM_Data/StreamingAssets/f_c`、`m_c` 是标准 UnityFS 包。数据标识分别为 `GenesisFemale-1` 与 `Genesis2Male`，骨骼权重引用 DAZ Genesis 2 源路径。包中保存的是 DAZMesh 序列化数据，不能仅扫描 Unity Mesh 类型，否则会漏掉身体。

男女各有 21,556 个基础顶点、21,098 个面（21,064 个四边形），三角化后 42,162 三角形。头、躯干、手臂、手指、双腿和脚完整。分别保留 23,223 / 23,246 个 UV 顶点、28 个材质分区，以及 80 个权重节点的数据。未叠加人物外观包中的形态；未重塑、减面或平滑烘焙。

输出根目录：`D:/code/rmmo_runtime/assets/characters/source_models/vam_base_reference/`。

每个性别目录包含：

- `original_data.json`：原始身体组件、轴向权重与来源 SHA256。
- `base_original.obj`：原始 Y-up 网格，位置与 UV 使用独立索引。
- `base_original.blend`：原始四边形和逐面 UV，附可关闭的一级预览细分。
- `base_original.glb`：未细分的静态原始网格，可直接检查；不冒充已完成绑定的角色。
- `validation.json`：顶点、面、UV、材质与尺寸核验。
- `merged_binding_reference.json`：衣服可能依赖的拼接身体拓扑，单独保留，不与干净基础身体混用。

原始蒙皮包含 X/Y/Z 方向权重和 bulge 数据，不等同于 glTF 的单一线性权重。当前没有恢复可动画骨架，也没有把这些权重随意平均后宣称兼容。绑定与关节验收属于后续接入工作。

`extract_vam_base.py` 已验证所有索引、数值和逐角 UV 对应位置；`build_vam_reference.py` 保留原始面数。Godot 实际读取男女 GLB，验证各 42,162 三角形、UV 和约 1.795 的坐标高度，并输出正侧背视图。Blender 预览含一级细分，Godot 图为未细分网格，不混称同一精度。

## 换装实际机制

使用用户提供的 `D:/tools/ILSpy_binaries_9.1.0.7988-x64` 检查安装内的 DAZMesh、DAZSkinWrap、DAZSkinWrapStore 数据读写和更新流程。反编译结果仅作本地调查，未复制整套第三方实现进项目。

| 文件/数据 | 已确认用途 |
| --- | --- |
| `.vam` | 服装身份、类别、作者、标签 |
| `.vaj` | 组件、材质参数、厚度/偏移、平滑、碰撞和模拟参数 |
| `.vab` | DynamicStore 容器，包含原始网格与 SkinWrap 表面绑定等二进制段 |
| SkinWrap | 每个 UV 顶点记录身体三角面、三个顶点索引、法线和两条切线方向的位移及法线投影 |

绑定时选取身体表面三角面，并保存局部表面坐标；运行时使用已变形的身体重建该坐标系，从而带动服装。UV 接缝的重复顶点复用同一绑定。厚度、平滑和布料模拟是额外步骤。它不是单纯把衣服缩放到包围盒，也不是把裙子每个点直接吸到腿上。

实测 `maru01.dressM08.4.var` 的裙装：5,287 个基础顶点、5,571 条 UV 绑定，网格与绑定段可完整解析。原配置启用布料模拟与碰撞。`clothing_sample/` 保存原网格 OBJ、解析数据、原 `.vaj/.vam` 与验证报告。

一个重要兼容问题：样例有 18 条绑定涉及基础 21,556 顶点范围之外的点，最大索引 22,851；在原拼接身体的 23,008 顶点范围内合法。直接把这些索引套到干净基础身体会出错。解析成功不代表已经移植布料模拟；样例二进制还有 918,780 字节后续段，本次未解析，明确保留为未知部分。

## 我们的接入方案

1. **冻结基础拓扑。** 固定性别、顶点顺序、UV 和版本哈希。身体、形态与衣服绑定都携带此标识。拓扑不匹配立即拒绝加载，不猜索引。
2. **先完成可动身体。** 提取关节静止变换/层级，将源轴向蒙皮转换为明确的目标方案；验证肩、肘、髋、膝、手指和坐姿后才替换统一角色资源。不能只拿静态 GLB 套当前骨架。
3. **衣服保留原网格。** 离线生成或转换表面绑定，记录法向厚度和局部切向坐标，保持围裙、袖口与背带拓扑。对原拼接拓扑引用做明确映射；无法映射的点重新绑定并验收，不截断索引。
4. **分区处理。** 贴身部分跟随身体表面；裙摆、宽袖、围裙使用独立活动区域和锚点，在绑定结果上做布料形变。避免把所有自由区域当紧身衣，形成钢铁裙或夹腿裙。
5. **顺序明确。** 身体形态 → 骨骼姿态/身体变形 → 衣服基础跟随 → 自由布料与身体碰撞 → 法线/切线更新。缓存绑定，不在每帧全网格找最近面。优先 GPU 批量更新，另设远处角色简化策略。
6. **继续复用现有角色系统。** 玩家/NPC/预览共用外观数据和装备槽，只替换经验证的底层资源与适配器，避免再生出多套人物实现。

验收需要覆盖：默认与形态极值；穿脱恢复；站、走、跑、抬臂、攻击、坐、躺；正侧背和低视角；贴身衣、裙子、宽袖、披风；身体完整性、布料层间关系、独立角色状态及性能。当前只完成源数据提取与机制调查，未宣称这套新换装已在游戏运行。
