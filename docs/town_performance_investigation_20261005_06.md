# 城镇两日性能排查与优化经验

这份复盘覆盖 2026 年 10 月 5 至 6 日的连续排查：入场加载、远景驻留、基础通行、街区扩建、昼夜压力、城防碰撞、街尾接触计算及渲染提交。依据用户反馈、仓库实现、逐轮记录和原始报告整理，供后续会话定位相似问题。用户反馈这段工作持续二十多个小时；这里不将其作为精确工时统计。

最后完整街区复测为 **20 段往返、1309 次昼夜切换、零功能失败，P99 28.367 ms、最长 40.480 ms、超过 50 ms 为 0**。早期普通完整运行仍出现过 165.322 ms 和 183.900 ms 尾帧。整体体验已明显改善，但这是多轮演进，不是只改一个参数获得的严格同条件提速率；缓存、版本、重启及运行环境均有变化。约 40 ms 尾帧仍存在，Vulkan 设备丢失仍未解决。

代码以 `c374c37a` 为复盘截止点。本文不宣称同期未提交的树木、道具和风场等接入也经过这组性能验收。原始逐轮细节仍保留，本文提炼判断依据和可复用方法。

## 用户反馈怎样改变了排查方向

| 用户观察或要求 | 排查发现 | 此后必须保留的验收条件 |
| --- | --- | --- |
| 远处房屋浮空，希望跟地块一起加载 | 房屋和地面的显示范围不一致，缺少支撑依赖 | 逐帧检查可见房屋的全部支撑地块；先地面后房屋加载，卸载顺序相反 |
| 鼠标和键盘都不能前进，验收失败 | 首批导航只覆盖出生点左右各 80 米；旧测试等全图完成后传送到门口，绕过缺陷 | 正常出生后真实行走，不等待全图导航，不以传送代替点击和键盘 |
| 为什么入场要加载这么多地图索引 | 进度标签把几何、材质、预制件恢复都叫“索引”；真正索引约 0.07–0.09 秒 | 分解真实阶段，按关键路径优化，不能根据文字标签猜热点 |
| 夜灯没亮、走过才亮，还要照到路面 | 地图 GLB 与独立灯具场景的控制没有自动等价；近处两灯预算不符合全街亮灯要求 | 检查真实地图全部已加载路灯，而不是逐盏走近检查 |
| 多建一条街后，走近房屋会卡 | 同步合批、碰撞接入、导航发布等多条长操作叠加 | 双街区往返，第一次经过和返回都测，保留全部慢帧 |
| 疯狂切换昼夜，跨区到处跑 | 白天短线漏掉相机重置、材质首次提交和无效阴影 | 昼夜切换与真实移动组合，逐次校验灯光状态 |
| 没有 Blender 任务也卡，城防周围也卡 | 并行应用不能直接当作根因；城防另有未覆盖路径 | 街尾、城防分别固定路线复现，不用环境猜测结案 |
| 设备丢失后重启，要求记录 | 三轮长测中断，前两轮正常不等于整轮通过 | 保留故障与未完成状态；重启恢复不等于根因修复 |

基础功能与性能一起验收。房屋逐层、屋顶和天花板遮挡、活动门窗、真实洞口、导航和碰撞保护、全街夜灯、视距与画质都是边界条件，不能在优化时悄悄拿掉。

## 入场加载的五轮改进

早期既“等得久”，也“进图后走不远”。两者分别处理：近场导航提前扩展和暂存点击解决通行；后台准备与缓存减少入场等待。

当时地图约 129.6 MB、2211 条记录。分阶段计时确认，重复资源校验、冻结预制件解码、地形上下文和材质恢复是主要成本。先将进度拆成几何与材质、后台地形、后台索引，再优化，避免围绕一个便宜的索引做无效工作。

1. **异步几何与恢复路径。** 后台计算地形、道路 CPU 数组，读取网格缓存并构建共享索引；主线程分帧创建 GPU 资源和节点。可恢复记录按 UUID 匹配，单条失败只回退该条；一次加载内复用校验结果。
2. **并行校验与出生区导航。** 预制件解码和校验并行，后台计算网格指纹；单独缓存出生区导航，命中后仍继续近场扩展和全图后台任务。
3. **地形上下文缓存。** 并行生成并缓存高度图、邻接法线和区域覆盖图。恢复约 49.648 ms，替代每次约 3.626 秒的上下文生成。
4. **材质与元数据去重。** 等值材质共享，用二进制属性身份替代长文本；完整相同的预制件载荷只存一次；垄沟复用相同顶点计算。材质整理约 654.7→31.5 ms，合批同步约 721.5→72.3 ms。
5. **固定结构校验与读取并行。** 地形单遍校验，源摘要与元数据读取并行。236 组边界输入及实际地形保持原校验规则，单项校验约 573.979→70.650 ms。

| 阶段报告 | 进入可操作场景 | 条件 |
| --- | ---: | --- |
| `town_async_baseline` | 36.678 秒 | 已有网格缓存但直接恢复未命中，出生区导航现算 |
| `town_async_final_warm` | 21.133 秒 | 几何缓存有效，出生区导航现算 |
| `town_load_stage2_warm` | 14.014 秒 | 几何与出生区导航缓存有效 |
| `town_load_stage3_warm` | 12.885 秒 | 增加地形上下文恢复 |
| `town_load_stage4_final_warm` | 11.789 秒 | 材质复用与元数据去重 |
| `town_load_stage5_final` | 10.818 秒 | 固定结构校验与读取并行 |

这是阶段演进，不是全部缓存条件相同的 A/B。最后一行仍未达到当时低于 10 秒的目标，也没有实现“只生成出生区就移交，其余派生几何随后生成”。并行阶段有重叠，不能相加，也不能把单项节省量等同于总进图收益。

缓存只保存派生数据，不绕过文档校验、源内容摘要、资源根限制、角色高度或生成器身份。损坏、版本变化、缺失纹理、UUID 重排和取消退出均有回归。增加线程数与改成排序校验的微基准没有稳定整体收益，因此未采用。

近场导航在距离边缘尚有 48 米时提前扩展，局部任务与全图队列独立。完整导航尚未完成时，真实键盘与鼠标仍跨过原卡点并返回；异步烘焙中退出也要成功。完整过程见 [入场与加载记录](town_frontage_rhythm_20261005.md)。同期路灯从独立场景到整街夜间控制的过程见 [路灯记录](banner_streetlamp_20261005.md)；用户已否决的近灯预算不应作为后续优化方案恢复。

## 行走尖峰如何逐层拆解

### 合批和导航发布中的同步长操作

最早直接 glTF 预览路线最长 762.007 ms，同步合批准备一次约 630–731 ms，大部分用于重复材质读取。合批改为收集、分组、替换分阶段执行，准备时保留旧有效画面，不可变源复用描述；卸载、编辑失效、取消和同步 flush 保持明确语义。

原生加载另有导航问题：350 米块在 0.1 米精度下约 1225 万栅格，首次行走出现约 646 ms 尖峰；改为 128 米块而不降低精度。之后整图 `map_force_update` 又暴露 2337.150 ms 阻塞，于是等待异步地图真实迭代就绪后再发布，已有近场导航继续服务。约 59 ms 的导航缓存写入也转入后台。

一个阶段变快后，后续更大的同步操作才可能显现。第一条短线跑出约 33 ms，不能代表完整导航发布和整图长测已经通过。

### 后台完成不代表可以一帧接入

约五万个顶点的整块碰撞 `set_faces` 曾耗时 25.473 ms，接入物理世界另约 11 ms。只在线程中展开三角形不足以解决它。实现改为最多 3072 个顶点一片，主线程约 1.5 ms 预算推进；准备中的整个体禁用碰撞，所有片完成后统一启用。保留原始面、绕序、洞口、变换和 UUID，同时处理折返取消、退出和旧结果归属。

流式接入与合批共享预算，避免各模块各自“只用几毫秒”却在一帧叠加。预算是调度目标，不是全引擎硬上限，单次不可拆操作仍须单独测量。

城防卡顿随后揭示覆盖漏洞：已烘焙部件缺少 `terrain_mesh` 作者字段，绕过了仅地形分片。扩展到拥有 CPU 几何的大型静态网格后，同路线最长流式阶段 **46.348→6.877 ms**，最长帧 **55.302→30.735 ms**；两次均 16 段、零失败。优化必须覆盖真实资产入口，而不只覆盖测试构造器。

实现：[碰撞准备](../scripts/world3d/stream_collision_preparer.gd)、[分片准备](../scripts/world3d/terrain_collision_preparer.gd)、[合批调度](../scripts/world3d/ground_batcher.gd)。

### 导航查询只接受可证明安全的快速路径

全图最近点查询仍可耗时数毫秒。先缓存同一地图和迭代的支持点，再后台建立 16 米空间单元索引。只有真实导航点位于水平和垂直容差较小者定义的球内才快速接受；其他情况仍由引擎精确查询。后来补齐三角形边、角及相邻单元搜索，路径规划本身不被替换。

初版随机对照发现非共面多边形表示不等价，生产实现随即跳过该类输入。6000 点合成对照、实际城镇 2000 点对照与楼层边界测试验证“没有错误放行”。一次暖态路线精确查询从 1873 次降至 23 次；减少调用次数不代表单次回退没有尾延迟。

实现：[表面索引](../scripts/world3d/navigation_surface_index.gd)、[权威移动](../scripts/world3d/world_authority.gd)。

### 昼夜切换不应重复地图级工作

天气更新只配置相机环境，避免重建整镇遮挡索引或重置平滑。路灯提前准备日夜材质及 RID，复用共享材质，静止灯不反复提交位置。保留全部 33 盏已加载街灯同时亮灭与照路，不恢复按距离触发亮灯。

之后发现零亮度月亮仍启用方向光阴影。只在最终能量严格为零时关闭其阴影，保留晨昏微光、作者设置、距离和级联质量。同场景 ABBA 中可见绘制次数不变，阴影提交减少 3877 次；夜间渲染 CPU 中位数下降，白天未稳定下降，因此不能把 draw call 降幅直接叫作 FPS 增益。

实现：[天气控制](../scripts/world3d/weather_controller.gd)、[街灯控制](../scripts/world3d/streetlamp_lights.gd)。街灯文件同期仍有其他任务改动，复现历史结果应使用对应提交。

### 小地图和风场中的重复主线程工作

小地图每次扫描 1441 个形状，实际只画约 29 个。先空间索引缩小候选，再将静态绘制指令保留在独立层；覆盖内移动只变换位置，越界、缩放、尺寸、地图修订或替换才重建。候选排序保持原绘制顺序，不能漏掉卸载街区的底图。

静态缓存后重绘中位数 **1.547→0.282 ms**；动态刷新采到 1309 次，静态层只重建 71 次。P99 基本不变，边界重建尾部仍在。三组真实 GPU 画面逐像素一致；计时合并静态层回调，避免只是将开销挪出统计。

风场保留相同 16 点积分与顺序，仅提前计算端点风向量，不再逐点构造完整天气字典。2000 组结果完全一致，函数微测量 202.688→20.487 ms；不能外推成整个游戏提速十倍。

实现：[地图视图](../scripts/ui/world_map_view_3d.gd)、[地图数据](../scripts/world3d/world_map_data.gd)、[天气积分](../scripts/world3d/weather_profile.gd)。

### 街尾接触计算与长期朝向漂移

街尾卡顿时流式阶段仅约 0.04–0.07 ms，但一帧可执行三次物理步。只记录最后一步会漏掉前面的慢查询，因此增加当帧最慢步，以及移动前位置、朝向、速度和接触对象。

完全平坦的实心作者地形仍有 16896 个三角面的碰撞壳。只对严格无起伏、洞口、垄沟且厚度有效的实心长方体替换成 BoxShape；49 块中仅 9 块满足条件，486 条射线一致，真实加载地图也断言实际使用的类型。替换后仍有约 5–7 ms 查询，证明复杂地形并非全部原因。

固定姿态逐体探针没有复现正常行走的慢查询；真实慢帧姿态重放才进一步发现胶囊朝向的数值路径差异。居中竖直胶囊绕竖轴旋转不改变几何，可在同步移动内暂时对齐世界轴，结束立即恢复。倾斜、偏心、缩放、复合形状和变换父节点回退原路径。

短测通过后仍有慢查询，继续检查**实际查询矩阵**，发现旧实现反复设置和还原 `global_basis` 会积累缩放分解误差。逐次复现到第 2025 次转向时约为 `(0.999989986, 1, 0.999989986)`，单位缩放保护开始拒绝优化。改为还原旋转分量后，18000 次连续转向保持精确缩放和最终姿态；实际路线采到的 8998 次查询全部对齐。移动查询 P99 **1.597→1.449 ms**、最大 **7.131→4.362 ms**。

**开关开启不等于优化实际生效，短测正确也不等于长期不漂移。** 需要记录快速路径真实命中，并设计能累积状态变化的测试。

实现：[严格平地替换](../scripts/world3d/flat_terrain_collision.gd)、[胶囊处理](../scripts/world3d/player_clearance.gd)。

### 用原生分析器定位渲染提交

“GPU 只有 1–3 ms”不能排除渲染路径。原生 visual profiler 对齐 3855 个路线帧后，发现方向光或聚光阴影提交最大约 25 ms，部分对应 GPU 阶段不到 1 ms；CPU 标记仍是墙钟时间，可能含驱动或调度等待，不能直接当作纯计算。

按证据减少实际提交：普通建筑批次在局部坐标生成，不同朝向的相同组件共享网格；冻结房屋为兼容不透明材质建立精确三角形阴影代理，按面剔除模式合并投影表面。每层、屋顶及活动件仍独立，透明、裁切、变形等不兼容材质回退。不是整栋合并或减面。

对照阴影调用中位数 **1831→1042**，总绘制 **2624→1843**，渲染 CPU P99 **14.306→12.100 ms**，可见绘制中位数 540→538。六组同机位昼夜比较最大 8 位通道差不超过 3。覆盖 636 个部件、135 份共享资源，行走前后数量不变；生成仍有加载成本，不能只报告运行收益。

实现：[阴影代理](../scripts/world3d/building_shadow_proxy.gd)、[原生采样](../tools/capture_visual_profile.gd)、[原生统计](../tools/summarize_visual_profile.py)。

## 关键结果与比较边界

以下均为两轮 20 段的完整街区路线，功能失败为零，但版本、重启及系统负载不同，整表用于追踪过程，不作为严格单因素 A/B。分析器开启、冷导航诊断、短路线和未完成测试不混入此表。

| 报告 | P99 ms | 最长 ms | 超过 50 ms | 说明 |
| --- | ---: | ---: | ---: | --- |
| `mainthread_repeat_20261006` | 37.652 | 183.900 | 30 | 小地图索引等局部优化后仍有大尾帧 |
| `integrated_final_20261006` | 37.077 | 165.322 | 25 | 碰撞分片与严格平地等整合后仍未解决全部尖峰 |
| `shadow_control_full_20261006` | 32.417 | 50.262 | 1 | 同版本诊断关闭局部坐标与专用阴影 |
| `shadow_partitions_full_20261006` | 29.911 | 56.275 | 2 | 两项开启，P99 改善但最大值未改善 |
| `shadow_radar_full_20261006` | 27.566 | 53.416 | 1 | 再加小地图静态绘制缓存 |
| `capsule_drift_reboot_pair_20261006` | 28.367 | 40.480 | 0 | 修复长期朝向漂移，重启后复测 |

最新最长值比历史 150+ ms 明显小，但 P99 比上一轮略高，不能称所有分位都下降。城防最终另有 16 段和 1044 次切换，P99 19.018 ms、最长 39.371 ms、超过 50 ms 为 0；不能用它替代街区测试。

## 失败假设和测试缺陷留下的经验

| 方向或误判 | 证据与处理 | 可复用经验 |
| --- | --- | --- |
| 等全图完成、传送到目标就能验收入场 | 漏掉局部导航边界，用户键鼠都被挡 | 从真实入口覆盖未完成的后台状态 |
| 截图后的帧率可直接比较 | 旧脚本未恢复跟随相机，视角改变 | 像素检查与性能采样分开，恢复相机 |
| 首次地形碰撞也分片就能解决街尾 | 实际移动仍接近 7 ms | 加载成本和稳定行走查询是不同问题 |
| 最后接触的地面或路灯就是根因 | 固定姿态逐体探针未复现慢查询 | 记录移动前完整状态，多物理步分别分析 |
| 加线程越多越快，排序校验更省 | 整体并行收益不稳定，排序反而更慢 | 只合入完整路径受益的方案 |
| 关 VSync 或怪罪 Blender | 关 VSync 仍有尖峰，用户无 Blender 时也复现 | 环境因素可记录，未证实前不用于结案 |
| 轮廓视口重复画全城阴影 | 独立 GPU 试验为 1 次可见、0 次阴影 | 负对照否定后停止修改无关路径 |
| 普通 shadow_mesh 会减少提交 | 仍按原材质面索引提交 | 核对引擎实际粒度并测调用数 |
| 日志与分析器不影响性能 | 同步 HITCH JSON、调试输出和线程枚举污染计时 | 先存数据后写明细；诊断后关闭采样器复测 |
| 写出 JSON、行走零失败就算通过 | 一个版本在 `world.free()` 崩溃 | 退出阶段及进程返回码也是验收 |

退出崩溃有过明确修复：未发布碰撞体在父场景退出时被同步删除，产生 `Parent node is busy`；退出时改为排队回收并立即清理所有权，四种退出组合通过。这不能解释其他无堆栈访问冲突或 Vulkan 故障。临时 `capsule_guard_live_20261006` 另有 Vector3 与字符串比较错误，整轮诊断数据无效，没有用于性能结论。

## 后续可以直接复用的排查流程

1. **锁定输入。** 记录提交、未提交范围、地图和相关资源哈希、引擎、渲染设置与缓存状态。并行开发时隔离工作区；结果只覆盖实际带入的修改。
2. **选真实路线。** 区分正常出生未完成导航、暖态双街区、街尾固定折返、城防往返。保留首次经过与返回，按改动加入昼夜、门窗和楼梯检查。
3. **先粗后细采样。** 从整帧、流式、导航、物理、天气、UI、渲染开始；只为已出现的热点加细计时。记录坐标、轮次、输入、昼夜、对象计数和内存趋势。
4. **分清计时域。** process、physics 和渲染帧不是同一编号。历史事件字段核对自己的帧号。异步渲染、墙钟等待和重叠线程不能相加；多物理步保留最后与最慢一步。
5. **最小复现验证机制。** 用单体碰撞、真实慢帧重放、同场景 ABBA 或开关对照验证假设。微基准与瞬移探针不能代替完整行走。
6. **优化有适用边界。** 后台只操作私有 CPU 数据，主线程接入和释放也要预算。快速接受有证明与精确回退，缓存有失效、取消及旧结果归属规则。
7. **验证正确性和长期性。** 按风险选择数组、射线、像素、顺序或状态对照，覆盖退出、折返、换图及长时间重复。记录快速路径实际命中，而不只是开关。
8. **恢复普通环境复测。** 关闭诊断分析器，不并行本任务其他 GPU 测试，不在测量中截图读回。Windows 使用不激活的独立桌面。
9. **保留完整结果。** 同时报告中位数、P95/P99、最大值、阈值帧数、样本数、路线及失败数；保留较差复测和中断。报告写出后仍检查日志与退出码。
10. **交接剩余问题。** 保存最坏帧位置、未解释阶段、原始路径和代码身份，留下下一个可证伪假设。不能把“本轮未复现”写成永久解决。
