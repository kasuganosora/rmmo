## 1. 目标、约束与本次审阅结论

目标是把玩法地图改为真正的 3D 世界，让桥、城墙、楼梯、建筑和角色共享空间、光照及遮挡，同时保留接近 2D 瓦片编辑器的制作体验。完成一块灰盒地面或一个模型摆放器，不等于完成这次迁移，更不等于完成整座城。

用户已明确的约束：

- 美术资产全部放在工程外：地图、模型、贴图、动画、音效、缩略图及测试生成的美术夹具都不能进入 `res://`。复用现有外部内容根和资产管线。
- 保留已经调整好的素体、发型、捏人、装备和动作经验。迁移后重新在实际游戏中校准比例、移动速度与步幅。
- 编辑地图仍应能选素材、涂地面、拼建筑、放 NPC 和事件，不要求用户学习建模软件才能制作地图。
- 玩法采用《天堂Ⅱ（Lineage II）》/《魔兽世界》这类可旋转、缩放的第三人称跟随透视镜头，不采用固定上方/俯视玩法镜头。具体按键方案见第 7 节，参考体验不等于逐项复刻两款游戏的操作。
- 玩家和日常地图编辑者不需要安装 Blender；开发者制作源模型可以继续使用现有工具链。
- 验收必须进入实际游戏跑动和交互。无头测试不能代替视觉、动画、操控和性能验收。
- 验收截图、视频、逐帧图片和临时备份使用工程外临时目录，验收后删除。文档只保留必要结论、版本和复现步骤。

## 2. 现有工程能复用什么

本次阅读确认：`scenes/world.tscn` 是 2D 世界入口；`scripts/map/grid_path.gd` 接受和返回 `Vector2i`，通行缓存按二维格索引；`scripts/net/server/movement_module.gd` 的 `try_move(from_x, from_y, dir)` 使用二维权威位置。因此，多层空间不能仅靠替换碰撞对象接入。

| 系统 | 处理方式 |
| --- | --- |
| `CharacterModel3D`、共享骨骼、捏人、头发、装备、动作资源 | 复用；直接挂进 3D 世界。角色预览/头像仍可使用 SubViewport |
| 外部 `content_root`、`ArtPaths`、资源缓存 | 复用和扩展，保持素材不进工程；增加世界资产依赖与失效处理 |
| 背包、任务、对话指令、数值、角色配置 | 复用非空间逻辑；空间距离、目标选择、触发范围另加 3D 适配 |
| 事件页 `when` / `graphic` / `commands`、自开关 | 保留语义和数据，不能缩成只有触发器与文字的简化版 |
| 编辑器资源索引/搜索、属性表单、事件指令编辑器 | 拆出可复用部分；二维瓦片素材面板不复用，需要验证与旧 ContentEditor 控制器的耦合 |
| 旧编辑器画布、瓦片拾取、自动瓦片及二维预览 | 新建 3D 实现；保留选择、拖画和吸附的操作习惯，资源入口改为 3D 模块库 |
| 世界输入、相机、移动、寻路、射线拾取、遮挡、空间音效 | 改写或适配 |
| Loading 的分阶段进度、取消、首帧移交经验 | 复用原则和可用模块，不照搬 2D 贴图合成实现 |
| 原地图布局 | 可作平面规划和灰盒迁移参考，不能自动转换成成品 3D 城市 |

新世界使用独立 `scenes/world_3d.tscn` 和 `scripts/world3d/`；新编辑器使用 `scenes/world_editor.tscn` 和 `scripts/world_editor/`。不让新世界继承并继续扩张 `world.gd`。共享业务放在可独立调用的模块中，不复制出两套会分叉的任务、背包和事件规则。

本机 Godot 源码中的 glTF 实现可辅助分析，但 `D:/code/godot-master` 不自动等于运行二进制的版本。所有依赖导入导出行为的结论必须在目标二进制上验证；本文不把源码测试当成已经完成的工程测试。

## 3. 范围与阶段交付

### A：技术和视觉样板

先建一个外部测试世界，包含街道、建筑门口、城墙、楼梯、一座桥，以及可同时通行的桥上与桥下。加入 NPC、条件事件、采集点和往返传送。不是只有平面的 8×8 Yard。

同时做一段接近目标美术风格的小街区，确认模块尺寸、材质、光照、相机和角色比例。灰盒证明可走；美术样板证明效果值得迁移。两者都通过才扩城。

### B：能持续制图的编辑器

实现第 8 节的必要工具，用编辑器从空白地图搭出并修改样板街区，保存、关闭、重开、F5 试玩全程成立。不能依赖开发者手写 extras 或修文件才能完成日常编辑。

### C：城市生产与默认切换

按区域制作城市、补齐玩法适配，完成规模与回归验收后再切默认入口。整城工作量包括模块素材制作/整理、建筑拼装、碰撞导航、遮挡、灯光、事件及性能，不全部归到“编辑器重做”。

v1 暂不包含自由飞行、游泳、跳跃/跌落物理、可破坏建筑、通用地形雕刻和完整在线服务器迁移。台阶、坡道、城墙步道、桥上桥下，以及可自由绕角色旋转/缩放的第三人称镜头属于 v1 核心，不得延后回避。

## 4. 世界坐标、通行与空间交互

### 研究结论：采用 VRChat 的米制尺度，不设固定屏幕像素换算

用户本轮确认：比例按 VRChat 的米制习惯，位置坐标需要小数。正式约定为 **1 世界单位 = 1 m，0.01 单位 = 1 cm，0.001 单位 = 1 mm**。这项不再作为 P0 待选方案。VRChat 官方以边长 1 m 的 Unity Cube 校准角色；这不意味着“1 m = 固定像素数”。[VRChat 官方角色制作说明](https://creators.vrchat.com/avatars/creating-your-first-avatar/)

需要区分三个量：

| 量 | 本项目约定 |
| --- | --- |
| 世界尺寸 | 位置、模型尺寸、碰撞、速度、交互距离统一以米和秒计量；角色 1.60 m 就是世界高度 1.60，不随窗口改变 |
| 屏幕像素/米 | 相机投影结果，随缩放/分辨率变化；透视下还随深度变化，不能写进世界尺寸或移动规则 |
| 纹理像素/米（texel density） | 材质清晰度的制作指标，由 UV、贴图尺寸和资产类别决定，另按美术预算确定；不改变模型真实大小 |

正交相机中，对平行于相机成像平面的长度，`pixels_per_meter = viewport_height_px / visible_height_m`。例如实际 3D 渲染视口高 1080 px、竖向可见范围 10 m，则该方向 1 m 显示为 108 px；这是算例，不是 VRChat 标准或本项目已选倍率。Godot 的 `Camera3D.size` 为完整宽度或高度，取决于 `keep_aspect`，不能照抄 Unity 半高参数。俯视地面不同方向有投影缩短；透视视图不能用同一个比例覆盖全图。[Godot Camera3D](https://docs.godotengine.org/en/stable/classes/class_camera3d.html)

编辑器提供米制测距和 1 m 标尺。顶视正交模式可显示统一地面比例尺；倾斜/透视模式用实际测量线两端的投影显示局部比例，并标注测量平面/深度。计量时区分 3D 渲染像素、输出窗口像素与 UI 缩放，不能把动态分辨率变化误认为世界缩放。

### 小数坐标是位置事实来源

- 使用 Godot 原生右手系：+X 向东、+Y 向上、+Z 向南；方位是本项目地图约定。Unity 使用左手系，不能因为尺度参考 VRChat 就直接复制 Unity 变换。导入适配器负责轴/单位转换，并用带朝向标记的立方体校验；已转换的 glTF 不能再次手工翻转。[Godot 3D 坐标](https://docs.godotengine.org/en/stable/tutorials/3d/introduction_to_3d.html)、[Unity 坐标说明](https://docs.unity3d.com/6000.0/Documentation/Manual/QuaternionAndEulerRotationsInUnity.html)
- `WorldLocation = { map_ref, position_m: { x, y, z }, surface_id }`。例如脚点 `(12.375, 0.180, -7.625)`：Y 是实际高度，不再借旧接口的 y 表示南向格。`map_ref` 带包命名空间；`surface_id` 用于桥上桥下身份，不能取代小数脚点。
- 编辑器输入、物件变换、玩家/NPC 权威位置、路径端点、出生/复活/传送、交互和存档端到端保留小数；禁止中途转 `Vector2i` 或取整再补 `.0`。父子局部变换与世界脚点须明确区分。
- 坐标面板默认显示 3 位小数（毫米显示粒度），可展开更多位数；这是本项目 UI 选择，不是 VRChat 的精度限制。不主动编辑字段时保持原值，保存不按面板显示位数截断。支持负数，拒绝 NaN/Infinity，单位标签固定为 m。
- 小数显示不等于十进制定点或无限精度。Godot 默认 Vector3 使用 32 位浮点，而 GDScript 标量 float 为 64 位；转成标量并不能找回已丢失的向量精度。每图以局部原点控制量级，不把所有地图摊在巨大绝对坐标里；P6 按地图最远边界验证误差后确定范围上限，需要时再评估原点偏移/双精度构建。[Godot 大世界坐标说明](https://docs.godotengine.org/en/stable/tutorials/physics/large_world_coordinates.html)
- 位置比较使用与用途匹配的容差，不用浮点完全相等判断到达，也不用浮点字符串作为实体 ID。坐标/变换序列化保留可往返的数值精度；初始位置往返误差目标 ≤ 0.001 m，在声明的地图范围内实测，超出时不得继续承诺毫米级精度。
- `surface_id` 来自放置实例身份和稳定可行走区域 ID，不来自 glTF 节点下标、三角形编号或浮点高度。重建缓存不改变身份；区域删除时报告失效引用并显式重定位。

### 编辑吸附、寻路索引与移动分别处理

编辑器主网格可显示 1 m；位置吸附提供 1 / 0.5 / 0.25 / 0.1 / 0.01 m 与关闭选项，默认建议 0.1 m，模块拼接优先使用连接点。数值输入可指定任意有效小数，不被拖拽吸附覆盖；未启动吸附时，切换网格设置不能移动已有对象。

键盘输入表达方向与持续时间，权威移动按米/秒和时间推进小数脚点；点击输入表达命中表面的精确目标，路径拐点和最终落点保留小数。沿连续可通过路径移动，斜向方向归一化，以实际位移校准动画；取消原先“每条指令走一格/站在格心”的默认前提。此处不要求新增跳跃、自由落体或完整刚体控制。

导航可使用表面图/导航网格，或用细分栅格作为内部算法；选择在 P2 通过窄巷、旋转桥面和短连接实测后确定。栅格节点不能覆盖权威位置，不可把点击终点强制吸到格心。起终点需要连接到可达表面并做扫掠；不可达时明确报告，或显示经校验的邻近可达落点，不暗中改层。

区块号仍可用整数，但只用于索引：`chunk_x = floor((position_m.x - origin_m.x) / chunk_size_m)`，Z 同理。例如原点 0、块宽 32 m 时，x=-0.01 属于块 -1，x=0 属于块 0。原二维 Cell 仅留在旧模式/旧数据导入边界；迁移比例由源地图显式配置，不从 48 px 瓦片推导一个所谓 VRChat 比例。

### 碰撞和导航

外观模型与简化碰撞形状可以分离，碰撞形状及语义仍属于世界/资产文档。复杂雕花不必逐三角形参与角色通行。优先复用引擎的形状查询能力，避免自写一套不完整的胶囊物理；不预先规定 `collision_mask = 0` 或强制更换物理后端。

必须建立一套供小数坐标权威移动、寻路与客户端展示共用的通行规则，不让客户端物理和 MockServer 各自得出不同落脚点。P0 定位职责边界，P1–P2 用桥、坡道、台阶和窄门验证查询实现后再冻结具体 API。

导航边建立条件至少包括：

1. 源和目标表面连续或有明确连接；不能因为高度接近就从桥下跳到桥上。
2. 身体沿整段路径做扫掠/连续空间检查，不能只查终点胶囊；低矮桥底也要检查头部净空。
3. 上台阶高度、下台阶高度、最大坡度、胶囊半径和高度分别配置。0.4 m 仅作台阶初始试值；不允许无上限下降或默认坠落到另一层。
4. 斜向移动不得穿角，检测实际运动路径，不只检查两个端点。
5. 水有空间范围和通行类别；存在水下地面不代表可以直接步行。桥面不受其下方水面误阻挡。
6. 动态占位和阻挡带表面/高度范围，桥上的 NPC 不阻挡桥下；门状态变化需使相关边失效。
7. 同时移动的角色在权威逻辑中预留下一段所需空间，处理迎面、狭窄通道竞争及路径过期；不能等表现层相撞后各自修正。体型改变需重新验证净空，冲突时保留原位置/配置并给出原因，不把玩家推到别层。

选择目标必须保留射线命中的表面身份。点击桥下、被屋顶遮挡的区域要有明确的遮挡/选层行为；寻路失败与目标尚未就绪应返回不同状态，不能都当成“不可走”。

### 接口与玩法迁移边界

以下是接口责任草案，P0 定义最小类型，P1–P2 验证后冻结完整契约，并非可直接复制的代码：

| 接口责任 | 必须携带/返回的信息 |
| --- | --- |
| `find_path_world(start, goal, actor_profile)` | 带表面身份的小数位置序列、米制路径长度、就绪/不可达原因、导航版本 |
| `try_move_world(actor_id, from, intent)` | from 为完整 WorldLocation；intent 为带序号的方向/目标意图，非客户端位移裁决；权威步进返回小数位置、actions、原因或 resync |
| `pick_world(screen_position)` | 世界脚点、物件 UUID、表面身份；不只返回二维格 |
| `query_interaction(actor, target)` | 表面连接/垂直间隔、距离和必要的视线遮挡 |
| `prepare_transfer(target_spawn)` | 可取消的准备结果；未成功提交前保留旧地图与玩家状态 |

旧 `try_move` / `GridPath` 只服务旧世界和明确单层的兼容入口，不能直接充当多层世界核心。旧成功/失败/actions 业务语义尽量保留，但 3D 请求与结果必须有完整空间信息。

首阶段仍使用 MockServer；Go 服务与 protobuf 暂不改，也不宣称已支持 3D 联机。正式接 Go 服务之前必须补世界位置、地图版本、移动校验和同步协议，并做跨层测试。

空间适配清单包括玩家/NPC 移动、追击与返家、交互距离、技能目标和范围、掉落拾取、采集/钓鱼、触碰事件、传送、出生/死亡复活、远端角色、飘字/头顶名、小地图和镜头跟随。保留 HUD / RequestAdapter 的可复用业务，清理这些入口对 `cell_to_world` / `world_to_cell`、像素距离及 `Vector2i` 的假设。

旧 Go 协议只有二维整数 Cell，不能无损承载新位置。保持旧服务暂不改的范围，但 3D 正式联机前须新增带版本的米制 XYZ 与表面/地图引用；如需压缩，单独规定量化步长、范围和误差，禁止截成整数米。

### 米制小数坐标的依赖改造清单

以下是实施依赖，不是已经完成的代码修改。先完成共同坐标契约，再按阶段改调用方，不能仅把面板改成小数显示。新模式不允许借用旧二维字段传递新位置；旧代码保留给旧模式。

实施前按上述入口追踪调用和配置字段，记录“旧单位 → 新字段/单位 → 消费方 → 测试”。搜索 `Vector2i`、`player_cell`、`from_x/from_y`、`int(position...)`、`cell_to_world/world_to_cell` 及按格范围常量，逐个区分旧模式合法代码与新模式误用；不能全工程机械替换。阶段完成的条件是该阶段链路没有未说明的旧单位依赖，并通过小数位置从输入到实际结果的端到端验证。

## 5. 世界文档、外部资产与保存

### 文档和运行时视图分离

`WorldDocument` 持有当前地图的完整逻辑文档：所有对象、父子关系、稳定 ID、变换、资产引用、空间语义和事件配置。它独立于场景树、当前视口和常驻区块。

glTF + extras 保留为 v1 世界存档候选，由 `WorldRepository` 负责读写。`GLTFDocument` 只承担几何/场景序列化部分；编辑器不能直接把当前流式场景树交给导出器当作整图保存。导出适配器须从完整文档构造完整导出数据，或完整更新原始场景表示，并验证远处未实例化对象仍在。

### 外部目录与依赖

建议目录，均位于已配置的工程外 `content_root`：

```text
<content_root>/packs/<pack_id>/maps/<map_id>/map.gltf
<content_root>/packs/<pack_id>/maps/<map_id>/map.bin
<content_root>/packs/<pack_id>/maps/<map_id>/textures/...
<content_root>/assets/world3d/<asset_id>/...      # 可复用模型、材质及碰撞资源
<content_root>/cache/world3d/...                 # 可删除、可重建、有容量限制
<content_root>/review_artifacts/<run_id>/...     # 临时验收，完成后清理
```

目录只是候选布局，沿用已有内容包解析器的安全解析入口。资源使用稳定 `asset_id` + 版本/内容哈希；节点名、mesh 名和绝对机器路径都不作身份。

glTF 外部纹理/缓冲依赖必须纳入打包、验证和事务保存。不能宣称一张地图必然只有两个文件。可复用资产通过应用层 extras 引用后由 RMMO 解析；普通 glTF 导出器不会自动处理这套实例语义。P0 做最小验证，P2 结束前验证“引用式物件”与内嵌网格混用、重复实例、材质覆盖和移动整个内容包后的读取。对外通用 glTF 导出若需要展开引用，可作为独立功能，不能冒充原生编辑文档无损往返。

原始 FBX 仅作为外部制作源；运行时使用已转换资源。测试 Yard/街区由代码生成到外部临时包，工程只提交脚本和文本测试定义，不提交生成后的模型和贴图。

### 导出游戏与内容包交付

外部加载必须在导出的游戏程序中成立，不能只在 Godot 编辑器里运行成功。运行所需的模型、纹理、动画和模块元数据都有明确的加载入口；不依赖开发机 `.godot/imported`、编辑器自动导入或 `D:/code` 绝对路径。自定义着色器/行为实现随代码交付，包内用注册 ID 和参数引用，不把任意脚本装进 prefab 自动执行。

内容包清单记录包 ID、版本、入口地图、递归依赖及哈希；角色和模块共享依赖按版本解析。发布时锁定一份依赖快照，运行中不混用新旧资源；修改共享资产或热重载只更新受影响实例和派生数据，缺失时明确报错，不能自动换成同名其他版本。已提交世界引用的旧版本，在确认无文档/运行实例引用之前不能被缓存清理误删。

增加一次“干净导出”验收：在没有工程目录和开发导入缓存的独立目录运行，移动外部内容根后仍能开图、显示材质/动画、试玩和保存；正式安装位置只读时，将缓存、恢复文件和用户存档放到明确的可写用户目录。不要通过把素材重新塞进工程来解决导出加载失败。

### 数据模式

`extras` 是候选格式的应用元数据容器；具体导入到 Godot meta 的映射需目标版本往返测试验证。需要保留可识别的非 RMMO extras；不支持的必需扩展/节点类型明确拒绝编辑，不能打开后悄悄删掉再保存。

| 对象 | 必需信息 |
| --- | --- |
| 世界根 | `rmmo_format`、模式版本、稳定 map ID、米制/轴向声明、小数边界、环境/BGM/光照预设、导航参数 |
| 所有可编辑/可引用对象 | UUID、对象类型、父 ID、变换、显示名、资产引用及版本、编辑层 |
| 可行走/阻挡/水体 | 明确碰撞语义、表面区域 ID、简化几何引用；节点名前缀仅供旧数据迁移 |
| 出生点/书签 | 稳定 ID、WorldLocation、朝向 |
| NPC | 稳定 ID、原型/角色配置引用、外观装备覆盖、行为、交互与战斗配置、出生位置 |
| 传送 | 完整三维触发范围/所属表面、目标 map ID + spawn ID、朝向；不只 `[x,z]` |
| 事件 | 稳定 ID、触发体/表面、条件页、图形/角色引用、指令、自开关语义 |
| 采集/钓鱼 | 既有目录定义引用、覆盖字段、产出/重生规则及空间位置 |

模板和角色目录按 ID 引用，不把全部角色网格复制进每张地图。对象重命名不改变身份；复制生成新 UUID；重复 ID、循环父子、坏引用、非有限变换、负/非法尺寸和未知必需版本均须报错。地图文档与运行存档分开：宝箱已打开、NPC 死亡等玩家状态不能在编辑地图时被写回模板。

迁移器按模式版本显式运行；更高版本拒绝写入。事件适配应保留 `EventCommands` 的 `when`、`graphic`、`commands` 等语义。现有 `EventRuntime.load_events_array()` 会先清空包事件，因此只能按完整快照接入或新增增量接口，不能按区块重复调用；同时要改掉其二维位置索引假设。

### 实例身份、动态对象与玩家存档

模块定义的子对象 ID 是模板内局部 ID；世界中的子对象身份组合“地图引用 + 放置实例 UUID + 子对象局部 ID”。同一间带门/宝箱的房子放十次，门状态、自开关和导航表面必须各自独立。模块内引用随复制重映射，指向外部 NPC/传送点的引用保留或显式提示，不按显示名猜测目标；嵌套装配检测循环并限制深度。

装配允许的 v1 行为为注册的门、宝箱、灯、静态装饰及简单循环动画等类型。状态控制动画/阻挡/事件联动，不由 glTF 动画隐式决定通行。会移动的桥、升降台和载人平台暂不包含在 v1；库中必须标记为不支持，不能当普通静态桥发布。

玩家存档记录内容修订、位置和对象状态，按“地图/实例/子对象”命名空间存放。另存为新地图生成新 map ID 并重映射内部引用；普通保存维持 ID。地图修订删掉玩家所站表面时，按明确的出生点回退并记录原因，不能选同 XZ 任意地面。迁移在新存档槽执行，旧槽保持可回滚；兼容映射与失败原因要可检查。

### 事务保存与故障恢复

保存捕获一个文档修订号的不可变快照，写入同盘临时位置，检查所有返回值、重新加载并校验依赖及对象数量，完成后才切换有效版本。保存过程中继续编辑时，只有已保存修订变为 clean，新改动仍标 dirty。

`.gltf` / `.bin` / 纹理不能靠逐个覆盖实现事务。P2–P3 比较单 GLB 与版本目录 + 小型提交指针两种方案，验证 Windows 下中断、文件占用和恢复行为后选定一种。提交指针是存储事务元数据，不另存一套玩法世界。未通过断写恢复测试，不开放覆盖正式地图。

备份/自动恢复设数量和总容量上限，成功提交后清理无引用临时版本；不能无限积累验收文件或历史模型。关窗/换图有未保存状态提示，外部文件被修改需检测冲突。

## 6. 加载、分块和性能

整图 `append_from_file` 得到 GLTFState 后只分帧创建节点，属于“场景实例分批”，不是磁盘、纹理或内存的完整流式加载。必须分别记录解析、纹理解码/上传、碰撞构建和节点提交成本。

v1 小图可使用整图解析，并明确地图规模上限。32 m 为候选块宽，不是固定正确答案；规模测试不达标时引入可重建分块产物或区域文件，不坚持“无论多大永远一对文件”。生成过程集成进游戏/编辑器，不增加终端用户外部工具依赖。派生缓存按文档/资产哈希、模式和构建版本失效，删除后仍能从源文档恢复。

空间索引和常驻策略：

- 用父子合成后的世界变换计算对象 AABB，并登记其覆盖的所有区块；跨块三角形/长墙查询也要覆盖所有相交块。索引可多处引用，实例只创建一次，避免重复碰撞。
- 渲染根据第三人称相机视锥、快速绕视预测与安全边界加载，覆盖拉远/低角度远景；镜头避障几何单独预取，不仅看相机位置的一圈。
- 碰撞根据玩家、活动 NPC、移动预测及交互范围保留；导航拓扑可比渲染更广。隐藏模型不能把可通行地面变为越界。
- NPC/事件持久状态与表现节点分离；区块卸载不重置宝箱、重生计时或任务。远处 AI 可以降频/休眠，不等于删除状态。
- 到未准备好的区域返回 loading/pending，预取完成后继续；不得在 `try_move` 热路径同步解析整块来“插队”。取消路径或地图变化后丢弃过期请求。
- 任务按耗时预算及工作量拆分，单个大区块也要可分批；主线程完成必要的场景/GPU 工作。后台只做目标版本允许的独立数据计算，不跨线程修改场景树。

进图/传送状态机：解析文档 → 验证依赖 → 准备目标碰撞/导航和首屏 → 完成世界绑定 → 首帧显示 → 恢复输入。Loading 与加载器一起实现，进度按真实阶段报告，可取消、有失败返回入口，不伪造到 100%。

目标准备成功后才提交切图，旧地图与玩家状态在此之前保持有效。准备失败、资源缺失或取消时恢复原世界；切换采用请求代号隔离晚到任务。准备期间两张图的峰值内存也要计入预算。加载器向世界移交已解析资源和已准备块，禁止交互恢复前重新解析/上传一遍。

### 渲染批次、动画和模块库的负载

一个铺地格不必对应一个永久 MeshInstance 节点。静态重复模块可按区块/材质组织实例批次，文档仍保留每个物件的独立身份和编辑选择映射；不要把整座城合成一个无法有效剔除或局部更新的巨型批次。交互对象、骨骼角色和透明物件按不同需求管理。批处理策略必须与拾取、隐藏屋顶、撤销和局部重建一起验收。

预览缩略图按需异步生成、限制并发并按资产版本缓存，列表使用按需展示；打开模块库不加载全部模型和贴图，不能给每个卡片持续运行一个 3D 视口。性能采样同时统计 draw calls、可见三角形、活动骨骼/动画数、实时灯和阴影开销，避免只优化磁盘加载。

## 7. 相机、角色与美术规格

### 已确定：可旋转的第三人称跟随透视镜头

玩法镜头方向按用户本轮要求固定：参考《天堂Ⅱ》/《魔兽世界》的第三人称角色跟随体验。使用透视投影，玩家可绕角色水平旋转 360°、调整俯仰和滚轮拉近/拉远；不再比较“正交还是俯视”作为玩法方案。固定俯视与顶视正交只保留为编辑器制图视图，不是玩家默认镜头。

跟随支点在角色躯干附近，结合角色实际身高设置偏移，不能直接绑在上下摆动的头骨上。镜头跟随位移采用可配置平滑，输入旋转及时响应；角色、镜头朝向和移动意图分别建模。FOV、支点高度、默认/最小/最大距离、俯仰限制与灵敏度在 P1–P2 实跑调优，保存为本机镜头设置，不修改角色米制身高。近距仍为第三人称，v1 不追加第一人称模式。

### 输入与移动配合（首版方案，可在 P1 调整按键）

| 操作 | 首版行为与约束 |
| --- | --- |
| 鼠标右键拖动 | 控制水平/垂直绕视；按下捕获、松开恢复光标，丢焦/打开模态 UI 必须释放；拖动不触发世界交互 |
| 滚轮 | 调整期望跟随距离，限幅且平滑；鼠标在可滚动 UI 上时只滚 UI |
| WASD | 按相机水平朝向移动，忽略相机俯仰，水平向量归一化；角色转向移动意图，不能再固定按世界东南西北移动 |
| 原地观察 | 站立时转镜头不强迫角色原地转身；移动时朝向跟随运动规则，进入近竖直视角也不使方向翻转 |
| 左键单击 | 复用目标选择/交互和点击寻路：优先处理 UI 与可交互目标，再对可行走地面发移动意图；实际意图显示清楚 |
| 右键原有动作 | 审核旧快捷操作，改为其他显式输入或区分点击/拖拽；不能与镜头同时执行，阈值按屏幕输入尺度处理 |
| 方向切换/取消 | 新键盘移动取消点击路径；跟随点击路径时镜头绕视不重新解释已确认的世界路径；技能瞄准明确消费/放行镜头输入 |

以上是本项目首版操作契约，不声称两款参考游戏使用完全相同的按键。输入动作应可映射，避免硬编码在相机脚本里。水平移动意图转换后传给权威移动层，相机绝不直接修改角色权威位置。

### 镜头避障、遮挡与加载依赖

- 从跟随支点到期望相机位置执行具有体积的避障查询，考虑近裁剪面和安全余量，不能只用一条细射线让画面边缘穿墙。忽略受控角色自身及不阻挡镜头的装饰/触发体，镜头碰撞类别独立配置。
- 墙、桥底、屋顶、地面和门框阻挡镜头时缩短实际距离；障碍离开后平滑恢复用户的期望距离，不反复跳近跳远。支点或相机已处于障碍内须有安全回退，不能继续穿墙显示背面。旋转镜头要覆盖侧向扫过障碍的情况。
- 优先通过镜头避障保持视线，不默认把整座建筑/屋顶隐藏。必要时可对遮住受控角色的指定前景物件作局部淡化；可视、拾取、物理碰撞和阴影分别处理，不因淡化允许隔墙选人或点击走入未检查空间。贴近角色时允许局部淡化，避免头发/身体充满镜头。
- 传送、出生、复活及切地图重置旧位置的平滑历史；保留或重置朝向按明确规则执行，不能让相机从旧地图飞过去。暂停、对话和 F5 切回编辑器时分别恢复对应的输入状态。
- 渲染预取考虑 360° 快速绕视、低角度远景及最大拉远距离。镜头避障几何覆盖跟随支点、期望轨迹和安全边界，不仅覆盖角色脚边；未加载区域不能被解释为“镜头无障碍”。不可用时暂限到已验证的安全距离并预取，不同步阻塞加载或穿过未知墙体。
- 第三人称能看到建筑侧面、背面、屋顶和远景，素材不能只制作固定俯视时看得到的正面。P2 样板四周巡查，P6 计入更多可见物件、远景、阴影和快速转镜头的性能开销；不等整城完成再发现素材不适用。

编辑器保留自由观察、顶视正交、米制网格，以及“切到玩法第三人称视角”。F5 必须使用正式游戏相机/输入/避障，不可用固定观察相机替代验收。

保留当前 `canvas_items / expand`，不因切成 3D 就强制修改全工程 UI 拉伸。若需降低 3D 渲染分辨率，应与 HUD、文字清晰度分离测试；登录、捏人、旧编辑器都需回归。

角色从脚底基点标定世界米制身高、肩宽、门宽、栏杆和阶梯。保留用户此前“缩小一个人头”的视觉方向，在实际街区对比确认，不能把 2D 像素缩放常数直接当作 3D 身高。体型变化同步更新适用的胶囊和交互高度；不设置只改变外观却不改变通行的本机 0.5–2 倍任意角色缩放。

跑步按实际米/秒和动作步幅校准，包含斜向移动、加速、停步、坡道和楼梯；检查前倾、摆臂、垂直弹跳、足底滑动。原先 0.32 / 0.16 秒每格只作为旧行为参考，新模式以米/秒和连续小数脚点驱动，不保留按格步进的隐式锁定。

移动位置只有一个权威来源：默认使用代码驱动位移、原地动作匹配速度；如果采用 root motion，须明确提取和消费方式，不能与代码位移叠加。共享 mesh/材质可复用，但骨骼姿态、动画状态、发色/瞳色覆盖与头发物理状态按角色实例隔离，防止一个 NPC 改色影响其他角色。

美术样板确定统一的模块尺寸、枢轴、拼接点、材质风格、贴图密度、光照与阴影；复用素材要记录来源和授权条件。建筑套件至少包括地面、墙直段/转角、门窗、屋顶、桥面/桥墩/栏杆、楼梯、城墙段/城门。是否 LOD、实例合批及纹理压缩由规模实测驱动，不以“免费素材多”替代风格和性能整理。

### 室内、天气和光照迁移

v1 默认建筑室内用独立地图 + 门口传送，复用已规划的加载和回退；同图无缝多层室内不作为首期强制需求。桥洞/檐下仍在同一户外地图，屋顶隐藏是显示规则，不应顺带关闭其真实碰撞、阴影或遮雨语义。可视、拾取、碰撞、遮雨和导航是不同标记。

现有世界有昼夜/天气表现，迁移清单必须说明其 3D 对应：时间和天气状态可复用，原来针对画布颜色/二维粒子的实现不能直接套用。默认切换前至少覆盖晴天白昼、夜间路灯和一种降水：角色与地图受统一光照，室内/檐下不穿雨，水面和半透明头发不出现明显排序问题。若首期缩减天气效果，要明列差异，不能在默认切换时静默消失。

## 8. 编辑器：保留涂地图体验

核心分层：WorldDocument（完整数据）→ 编辑命令/UndoRedo → 3D 视图与拾取 → 存储/资产适配器。UI 和 MCP 调用同一命令层，不能各自直接改场景树；文档修订驱动局部可视、碰撞与导航更新。

### 3D 模块库，不沿用二维瓦片素材面板

地图中摆放的是 3D 对象/组合模块，不能再用二维图集切格选瓦片作为主入口。模块库以实时或缓存的 3D 渲染缩略图展示对象，支持旋转预览、尺寸查看和拖入场景。缩略图只是选择对象的入口，落到世界里的是实际 3D 实例。

一个可放置模块是 prefab/装配定义，可包含多个模型、材质、简化碰撞、导航语义、连接点、枢轴和默认属性；它不等于单个 mesh。建筑、树木等支持单独摆放；地面、墙段、桥段等标记为可铺设模块，才进入画笔/拼接工具。不是所有 3D 对象都适合“涂”。

拖画道路时重复铺放 3D 地面模块；拖画城墙时依据连接规则生成直段、转角和端头；桥需要桥面、桥墩、栏杆和高差参数，不能按二维格简单填满。连通规则、模块间缝隙、实例高度及碰撞必须一起预览。普通模型导入后先校准米制尺寸、枢轴、朝向和碰撞，才能登记为可铺设模块。

模块库定义、缩略图和派生缓存全部在工程外。共享模块带稳定 ID 与版本；实例可以有受控的材质/参数覆盖，升级模块须报告受影响实例，避免替换一个模块后静默改变全城碰撞。glTF 模型与应用层 prefab/装配语义的映射从 P0 最小验证开始，P3 正式存储实现前完成往返验证。

B 阶段必需工具：

| 工具 | 验收要求 |
| --- | --- |
| 3D 模块库 | 对象分类/搜索、3D 缩略图和旋转预览、真实尺寸、连接点/碰撞预览、稳定资产 ID、缺失引用提示；替换模块保持兼容的实例配置 |
| 3D 地面铺设 | 对可铺设模块做单格/连续拖画、矩形铺设、同层填充、擦除、吸管、旋转；生成 3D 实例，一次笔画一次撤销 |
| 模块摆放 | 吸附网格/高度/连接点，移动、旋转、复制、删除；预览碰撞和落点 |
| 墙与桥拼接 | 拖线生成连续段和转角；桥面、栏杆、台阶的连接规则；超出规则时明确提示 |
| 选择与图层 | 框选、多选、批量操作、显隐/锁定；桥上桥下独立选择，不能总选最上层 |
| 楼层和高度 | 显式选择编辑表面、显示高度、放置楼梯连接；无需通用地形雕刻也能编辑多层 |
| NPC/事件/传送 | 表单化属性、角色预览、条件页、目标地图/出生点选择、范围可视化和错误定位 |
| 文档操作 | 新建/打开/保存/另存、dirty 状态、撤销重做、恢复、只读和写入失败反馈 |
| 试玩 | 对当前修订生成外部试玩快照，F5 进入真实游戏，结束返回原编辑状态 |

F5 不隐式覆盖正式地图；使用同一资源解析/世界运行管线，不能另造一个省略业务逻辑的预览世界。试玩使用独立的玩家存档和 MockServer 会话，背包、任务、自开关、角色位置及 content.json 都不能写回正式游戏。试玩快照包含可达传送目标的修订/依赖，目标为未保存地图时明确采用哪份修订，不混用正式世界和草稿。

正常结束、崩溃重启和取消时都能回到原文档、选择、相机及撤销栈；清理试玩临时状态。检查对话 actions 真正显示、条件页切换、传送成功，同时核对正式存档与启动配置未改变。

MCP 作为 UI 完成后的自动化适配：`create_world`、`place_prop`、`paint_ground`、`place_npc`、`place_event`、`validate_world`、`save_world`、`query` 等沿用同一命令/校验。端口 18766 仅作候选，与旧编辑器分开，遇到占用须报错；默认只监听 loopback。文件写入限授权外部内容根，工具不能任意执行脚本或访问任意路径。请求有大小、对象数量、耗时及取消限制，避免单次大填充锁死编辑器。

## 9. 旧地图导入与城市迁移

旧包只读，导入生成新的外部包。导入前后比较原文件内容哈希，而非仅比较字节数。源尺寸、NPC、事件和传送数量每次读取，不硬编码 Axel 永远为空。

可将地面、水、阻挡、书签等转换为灰盒/规划参考，保留能够映射的游戏配置；对单向通行、自动瓦片、图层语义等无法可靠映射的信息给出逐类数量和位置报告。不得把单向边自动改为四向通行后静默发布。

灰盒导入不计作成品美术。城市生产分为：布局和比例确认 → 样板模块 → 街区搭建 → 桥/城墙及高差 → NPC/事件恢复 → 全城通行与视觉检查 → 性能优化。每阶段可独立验收，旧地图保持可用直至替代完成。

## 10. 安全、可观测性与数据生命周期

- 规范化路径并解析实际目标，防止 `..`、绝对 URI、符号链接/目录联接逃出允许的内容根；glTF 缓冲与图片、应用资产引用都走相同规则。外部共享库必须显式登记允许根，不任意联网取资源。
- 输入验证包括文件/解压体积、纹理尺寸、节点/三角形/事件数量上限；损坏包给出具体对象/依赖错误，不静默加载半张正式地图。
- 日志记录 map/修订/资产版本、各加载阶段耗时、取消原因、缺失引用、活动块数、导航版本、主线程提交预算、内存/显存。避免每帧刷日志。
- 性能报告区分进程内存、Godot 静态内存和显存，不把单个指标叫作全部内存。
- 缓存有上限和清理入口，版本失效释放旧引用；临时试玩包、导出半成品和验收媒体有明确所有者和退出清理。正式素材和用户未保存恢复数据不得当作验收垃圾删除。

### 米制、小数坐标专项验收

- P0：外部 1 m 校准立方体导入/保存/再导入后尺寸和轴向正确；包含旋转/父子缩放，防止厘米源文件 100 倍误差或重复轴转换。
- P1：玩家停在非格心位置；键盘松开不吸回整数位置，点击小数目标不过度吸附；30/60/120 FPS 同时长运动距离在定义的容差内一致，斜向不加速。窗口/渲染分辨率改变不改变物理尺寸和速度。
- P2：在小数高度的桥上桥下移动；正负区块边界与地图边缘查询一致，空间容差不会跨层或穿墙。
- P3/P4：`(12.375, 0.180, -7.625)` 和更多小数位样本经输入、变换、撤销、保存重开、F5、传送及存档恢复后无整数化/累计漂移；面板显示位数不截断原值。
- P6：在已声明的最大坐标范围重复测量往返误差、碰撞与显示抖动；正交比例尺与投影一致，透视比例尺标注局部测量条件。测量结果达标后才冻结范围。

### 实际游戏与编辑器验收

必须使用实际 Forward Plus 渲染和正式游戏入口，不以角色预览或 headless 代替：

1. 从登录/载入进入街区，键盘走跑、点击寻路、斜向转弯、上下阶梯、过桥再走桥下。
2. 在门口、桥洞、城墙边缘验证遮挡与点击；检查同一 XZ 不同高度的 NPC/事件不串层。
3. 检查角色比例、光泽/光照、跑步前倾/摆臂/步频/足滑，切外观不触发全地图重建。
4. 从空白地图用编辑器完成一段道路、转角墙、桥、楼梯、NPC 和传送，撤销重做、保存重开并 F5 试玩。
5. 真正移动穿过未加载区块、窄事件范围、缩放、往返传送，核对一次性事件不漏发/重发，并持续采样；截图读回与性能计时分开。
6. 实跑室内外往返、夜间灯光和降水；同时显示多个不同外观 NPC，确认材质、动画及头发状态不串实例。
7. 用独立导出程序和只读安装目录验证外部包、可写缓存、存档和缺失依赖提示。

### 第三人称镜头专项验收

- P1：站立绕视不转动角色；按相机方向走跑，抬头/低头不改变水平速度；滚轮缩放、右键拖动、左键目标选择互不误触。窗口丢焦、对话/背包打开后光标状态正确。
- P2：贴墙、绕墙角、窄门、桥洞、楼梯、屋内低顶和高差边缘实跑；相机近裁剪面不穿墙，不钻地、不剧烈弹跳；离开障碍恢复原期望距离。点击路径期间转镜头不改变已选世界目标。
- P3/P4：F5 与正式游戏使用同一镜头；出生/跨图/复活切换无长距离镜头滑行；UI 或技能瞄准模式不意外移动人物。
- P6：快速 360° 绕视、低俯角、最大拉远与移动组合测试，记录视锥/避障预取就绪及慢帧；建筑背面/远景无因原俯视假设造成的缺失。

### 初始性能预算（P0 记录硬件，P1 起采样，P6 冻结规模门槛）

以目标 60 FPS 提出初始预算，不对未知硬件承诺：目标机器、分辨率、画质、街区/城市对象与纹理规模先记录，再冻结门槛。当前开发机的旧 2D 基线可参考 `docs/map_stream_performance.md`，不能直接当 3D 已达标证明。

- 街区连续跑动至少 3 分钟，记录 P50/P95/P99、最长帧及 >50/100 ms 次数；初始目标 P95 ≤ 16.7 ms、P99 ≤ 25 ms，稳定游玩不出现由资源同步加载造成的 >100 ms 停顿。
- 常态流式主线程工作初始预算 ≤ 2 ms/帧；重任务必须可拆分，报告超预算原因，不用“一帧一块”作性能指标。
- 首屏 Loading 区分冷/热启动，分别记录解析到交互恢复的时间；初始样板目标热加载 ≤ 3 s，冷加载门槛按代表性素材实测在 P6 冻结。
- 编辑器常用命令即时反馈，目标 ≤ 100 ms；大填充、保存、导入可异步但必须可见进度/取消，不能卡住窗口。
- 地图/纹理/实例数量至少覆盖样板、典型街区和预计整城三档；记录 CPU/GPU 峰值、换图双驻留和缓存上限。P0 按硬件提出上限假设，P6 以实测冻结数值上限，未定规模预算前不能宣称整城可扩展。
- 连续 10 次往返传送和重复开关编辑器，无旧世界/角色实例及资源无界增长；单图整载超预算时必须改加载粒度后再扩城。

## 12. 实施顺序与默认切换

### 顺序原则：先能跑，再能改，再扩城

先用少量外部模块打通真实游戏，再验证多层通行，随后立即接入最小编辑器；不要等完整加载系统、所有玩法和生产工具做完才首次试玩。保存可靠性在用户开始制图前完成，规模加载在批量建设城市前完成，默认切换最后进行。

P0–P9 是交付阶段，不要求一个阶段塞进一个大 PR。每阶段按“可独立合并、可测试、可回滚”的工作拆成小 PR，放在开发 profile/功能开关后。后续阶段扩展同一套 WorldDocument、运行入口和命令层，不为快速演示创建一套最终必须扔掉的独立预览实现。

### 关键依赖与反馈点

推荐主线：`P0 → P1 → P2 → P3 → P4 → P5 → P6 → P8 → P9`。P7 从 P4 完成后可以开展，必须在 P8 前完成，并与 P6 做一次联合回归。这是工作依赖安排，不要求开启多个代理或多条同时改公共接口的任务。

- **第一次实际游戏验收在 P1**：尽早暴露人物比例、相机、跑动和外部加载问题。
- **第一轮桥墙效果验收在 P2**：如果多层通行或视觉不成立，先修正，不向后堆编辑器功能。
- **第一次用户制图验收在 P3**：先证明“放对象 → 保存 → 重开 → 游戏试玩”可靠，再加入批量生产工具。
- **第一次事件与跨图验收在 P4**：提前发现模板身份、玩家状态、传送和资源生命周期问题。
- **大规模制图前必须过 P6**：性能测量从 P1 开始；P6 是代表性负载的阻断关卡，不是第一次开始考虑性能。

### 各阶段的规模边界

P0/P1 的代码生成场景只用于少量模型和接口验证；P2 增加高差组合；P3/P4 用编辑器制作的场景替代手工夹具作为主要验收对象；P5 才做生产工具。每阶段必须写明“已支持/暂不支持/下一关补齐”，开发入口对超范围数据明确拒绝，不能把临时简化规则当正式兼容承诺。

Loading、取消、错误返回和计时从 P1 就有；复杂调度和真正资源流式按 P6 负载决定。最小格式读取在 P0/P1 验证，完整可靠保存最迟 P3 完成。这样既不拖延第一版试玩，也不拿用户地图试验不安全的存储。

### 默认入口和回滚

默认迁移使用完整启动 profile：world mode、pack/map/spawn 和格式版本一同选择。旧 2D profile 原样保留，3D profile 指向外部内容根；不拆成“关开关后还要手动改出生地图”的回滚方式。新模式加载失败给出错误和返回/选择旧 profile 的入口，不偷偷把 3D 世界交给 TilemapPack。

P9 前不设 `world_3d=true` 为全局默认。正式替换时说明内容和旧存档迁移结果；失败能够整体恢复旧 profile 与旧存档。`docs/character_3d.md` 的 2D 合成描述在新世界验证通过后补充模式说明，不在计划阶段就宣布已废弃运行中的实现。

## 13. 决策冻结时机与失败处理

决策在首个依赖它的生产阶段前冻结，不把所有问题压到 P0，也不拖到整城搭完。冻结记录包含选择、证据、支持上限和允许重开的触发条件。技术选择按验证结果推进；影响用户视觉偏好或产品范围时，提供可玩结果供评审。

| 决策 | 最迟冻结时机 | 验证方法 / 不通过时的处理 |
| --- | --- | --- |
| 包/地图/实例身份、位置类型、读取入口 | P0 结束，P1 前 | 最小夹具与干净导出读取；map_ref 和稳定 ID 不依赖机器路径/节点下标 |
| 世界文档格式与装配引用 | P2 结束，P3 正式存储实现前 | glTF 候选多次往返、重复子对象、未加载对象和依赖验证；不能无损则采用轻量世界描述 + glTF 资产，保持 WorldDocument 接口，不删字段迁就格式 |
| 单 GLB 或版本目录提交 | P3 覆盖正式地图之前 | Windows 中断/恢复、依赖更新和峰值磁盘测试；不通过只能保存独立临时草稿，不制作正式内容 |
| 米制小数位置与导航表示 | 1 单位 = 1 m、小数 XYZ 本轮已确定；P0 落入接口，P2 冻结内部导航算法 | 任意小数落点、关吸附、斜桥/多层、负数块索引及不同帧率走跑；导航格号不得回写覆盖真实位置 |
| 角色、台阶、坡度和模块米制规格 | P2 结束，P3 模块配置前 | 实跑门宽、桥洞、步幅和体型变化；避免量产后统一改尺寸 |
| 第三人称镜头参数与输入/避障规则 | 第三人称透视方向本轮已定；P1 接通，P2 完成避障/操控验收，P5 前固定基线 | 实跑旋转/缩放、相机相对移动、窄巷/桥洞/室内、输入冲突与传送重置；不再把固定俯视作为候选 |
| 依赖版本锁定、独立实例与编辑局部失效 | P3 核心契约固定，P5 工具验收 | 重复装配、升级/撤销、局部重建及干净导出；资源缺失不能偷偷选择别的同名版本 |
| 试玩/正式存档隔离和迁移 | P3 完成隔离，P4 验证保存恢复，P7 完成迁移 | 试玩前后正式数据不变；删除表面/跨层恢复有确定行为；P9 再做回滚演练 |
| 地图规模、内存上限和分块方案 | P0 记录假设，P1 起测量，P6 进入整城前冻结 | 三档负载测峰值；超预算就增加派生分块/区域文件或降低已声明上限，不凭感觉扩城 |
