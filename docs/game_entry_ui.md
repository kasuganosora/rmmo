# 游戏入口与字体渲染

## 范围

登录、角色选择、游戏共用窗体/HUD 字体；不修改内容编辑器、编辑器 MCP、用户地图或资源包。没有接入生成图片。

## 入口实景

- `project.godot` 的 `rmmo/default_pack` 指定资源包，`rmmo/entry_map` 指定其中的地图 ID。目前使用 `default / medieval_material_house`。
- 地图位于外部内容根的 `packs/<pack>/maps/<map>/map.gltf`。指定地图不存在时，只从同一包的已有地图中选择；没有地图时保留纯色底，登录功能仍可用。不会调用世界场景的示例地图生成逻辑。
- `entry_map_loader.gd` 在线程中读取已导出的 glTF 模型/材质，主线程实例化。背景使用自己的 SubViewport、灯光和 Camera3D；不启动玩家、战斗、导航或地图事件。
- 相机默认按建筑包围盒取景，地面不参与包围盒。可通过可选的 `rmmo/entry_camera_position`、`rmmo/entry_camera_target`（Vector3）覆盖入口机位，两项同时配置。
- 首次加载后在内存中缓存入口展示场景；登录和选人复用。缓存按地图路径与修改时间区分，退出程序即释放。相机稳定后暂停背景渲染，窗口改变尺寸时重新渲染，不持续占用背景帧预算。
- 地图替换、保存后会重新导入；只改贴图且未保存地图时，重新启动客户端以刷新本次会话的缓存。

## 设计检查

| Before | After | Why |
| --- | --- | --- |
| 纯色底、居中默认表单、自动填写 demo 密码 | 默认资源包实景、右侧分层表单、密码默认留空 | 保留游戏场景氛围，减少演示界面感 |
| 服务器地址常驻主表单 | 收入“连接设置”，保留随时展开能力 | 主路径集中在账号、密码和登录 |
| 提交期间仍可修改账号 | 等待响应时锁定表单，失败恢复且保留输入 | 请求身份和画面状态一致，可直接重试 |
| 每个角色开一个小头像渲染器 | 一个大幅角色预览，真实装备、职业/等级、旋转操作 | 看清当前角色并降低重复渲染成本 |
| 角色列表默认粗焦点框 | 细金色选中态，明确进入/创建/返回 | 避免重复套框，保留键盘可见反馈 |
| 小窗口文字压在高对比地图上 | 加深背景遮罩，表单允许纵向滚动 | 保持可读性和操作入口可达 |
| 入口继承像素素材最近邻采样 | 游戏 UI 显式线性采样，字体 MSDF 精度由 48 调整至 64 | 改善中文细笔画、大标题和非整数缩放边缘 |

字体设置仅落在 `EntryStyle`、`L2Style` 和 `GameWindow`。项目全局最近邻设置保留；道具等像素图标的显式最近邻设置保留。MSDF 使用灰度抗锯齿，参考 [Godot 字体渲染文档](https://docs.godotengine.org/en/stable/tutorials/ui/gui_using_fonts.html)。没有通过全局字体设置改变内容编辑器。

## 验收

- `tools/test_entry_ui.gd`：23 项通过，0 失败。真实鼠标/键盘输入；默认包地图、独立相机、无游戏物理、地图内容哈希不变、缺失地图/包回退、密码可见切换、回车登录、重复提交、失败恢复、空角色、优先选中、切换角色、旋转、回车进入、重复进入防护；1280×720 和 800×600 截图。
- `tools/test_login_character_preload.gd`：实际模拟服务器登录失败/重试、关闭重开页面、保存提交时身份、人物资源预加载以及真实跳转选人页。
- `tools/test_character_gear_session.gd`、`tools/test_identity_entries.gd`：通过。切换角色复用预览但不继承前一个角色装备；真实装备快照、体型/发型身份、极端身高头部不裁切、独立 NPC 外观互不污染。
- `tools/test_game_window_review.gd`：共用字体/采样修改后，313 项窗口和交互回归通过。
- 所有 GPU 验收使用 `tools/run_godot_background.py` 独立桌面，不抢前台焦点。截图/日志位于外部 `review_artifacts/entry/`，文字采样对比为 `text_sampling_comparison.png`。

当前背景本身仍是测试建筑地图；入口机位和 UI 已可使用，正式环境美术可在后续资源包地图成熟后替换，不需要改登录逻辑。
