# 参数化建筑：外观与室内共用蓝图

2026-10-01。当前 3D 内容编辑器和 MCP 支持普通侧走廊建筑、中世纪窄店屋、挑空大厅住宅、后院作坊、L 形侧翼、U 形围院、城中村家庭自建房与底商住宅，以及沿道路中心线的平地建筑布置。外观、室内、碰撞来自同一蓝图。

## 使用

点击画布工具栏「建筑」或左侧「建筑」页，默认显示区域随机方案。展开「详细参数与建筑管理」仍可选择用途、设置宽度、进深、层数、房间数、层高、屋顶与外观。建筑位置为底层地面的中心脚点，正门默认朝 -Z，朝向绕 Y 轴旋转。

面板顶部「预览」显示半透明建筑，不修改地图；「生成一批」写入当前参数和批量位置。数量最多 16 栋，列数和间距控制排列，每栋使用独立身份和递增种子。全部占地校验通过后才提交，一次撤销删除整批、重做恢复全部身份。改动参数后需重新预览。

通过建筑下拉列表选择已有建筑，再用「预览」或「更新建筑」。更新预览暂时隐藏原构件，清除后恢复原可见状态。「聚焦所选建筑」可定位整栋；「解除关联」保留普通构件和组合；「删除」只删除该建筑拥有的构件。以上修改均可撤销。

## 区域随机方案快捷入口

选择「城中村自建房」「中世纪店屋」或「普通住宅」，以及「单栋建筑」或「成片建筑」。点「拖框选区域」，在地图画布按住左键拖出矩形，松手自动显示半透明预览；「换一案」切换种子，「应用方案」才写入地图。也可先选中同标高的水平地面，点「用选中地面」取其外接矩形。种子会显示在区域尺寸旁，便于复现。

快捷模式仅需风格、单栋/成片、间距、四个正门朝向和地面 Y。层数、尺寸、用途、开窗/屋顶和装饰等在当前布局的合法范围内组合变化，不包含分租。单栋预览可点「单栋微调」，把这栋的实际参数和位置交给详细面板；成片建筑应用后仍可逐栋修改。

- 所有实际构件必须落在区域内，包含阳台、屋檐、雨棚，并为入口留出空间。已有普通物件、导入模型、生成建筑，以及隐藏/锁定物件都参与避碰；模型按其包围体作保守检测。脚点以下的地面可作为支撑。
- 规划按种子尝试不同合法尺寸及位置，放不下的候选格跳过；没有可用位置时明确失败，不删除或移动已有物体。正式提交再次经过同一建筑批量碰撞检查，整批一次撤销。
- 每份预览有 `plan_token`。应用时重新规划与校验，若已有物体改变导致方案变化，则拒绝旧方案并要求重新预览；不会悄悄应用另一组房屋。编辑地图后 UI 会清除旧预览。
- Esc、切换页签、窗口失焦或在侧栏松开鼠标都会取消正在进行的拖框，不会落地生成。拖框期间 MCP 写操作返回忙碌，只读查询仍可用。

首版区域是世界 XZ 轴对齐矩形，边长 1～500 米，实际尺寸须足以放下所选风格的建筑。正门可朝 ±X/±Z；UI 成片最多 8 栋，MCP 可指定最多 16 栋。采用有限次候选格尝试，不保证找出任意障碍布局中的所有可行空隙。它暂不支持自由多边形、地形自动找平、产权地块切分或自动铺路。

## 普通模板：内外一致的生成规则

`scripts/world3d/building_blueprint.gd` 是唯一的布局来源，UI 和 MCP 都通过 `building_tools.gd` 使用它。

- 每层按同一层高计算地板、门窗、隔墙与天花板。房间沿公共走廊排列，用真实门洞相连；模板定义房间用途标签。民居默认每层 2 间，旅馆预设为 3 间；商住楼底层标记为店铺/储物间，上层为卧室。
- 每个门窗开口包含墙段、水平坐标、底高、宽高、楼层和所属房间；墙体分块时直接减去这份开口，内外边框也按相同尺寸生成。窗洞中有玻璃构件，门洞生成可开合门扇，默认打开。
- 窗户位于所属房间外墙，房间隔墙放在房间边界。构件保留真实厚度，门框装在洞口边缘，新建门洞最小宽 1.5 米（普通入口 1.6 米）、高 2.5 米；门框侵入量另计。
- 楼梯使用独立竖向区域，新建净宽 1.7 米，转角平台默认深 2 米，踏步深 0.28 米，踏步高不超过 0.17 米。各层楼板按同一个楼梯投影分块留洞，连续楼梯采用薄踏板保证上下净空；顶层洞口设护栏，楼梯出口连接上层平台。
- 顶层封顶、山墙和坡屋面共享屋顶标高与升高；山墙使用真实三角柱网格。运行时碰撞来自同一组网格，不另造一份不匹配的碰撞外壳。
- 生成构件带显式楼层标高，编辑器隔离某层时能看见其地板和构件，隐藏上一层楼板及屋顶。关闭楼层隔离后显示完整建筑。

普通模板参数范围：宽 9～24 米、进深 12～30 米、1～3 层、层高 3～4 米、每层 1～4 间、坡屋顶升高 0.5～4 米。墙厚 0.2 米、楼板厚 0.22 米。尺寸限制为当前通行布局预留足够空间，不支持任意缩小后挤压门窗和楼梯。

## 中世纪布局与沿街布置

面板提供「灰泥石墙店屋」「木构后院作坊」「围院旅馆」「大厅住宅」四个预设；也可选择布局与建筑组合。游戏尺寸依据角色通行需要设定，不是通用历史建筑尺度。

| 参数 | 规则 |
| --- | --- |
| `layout` | `standard` 保留原几何；`townhouse` 为前屋＋后部楼梯厅；`hall` 为两层大厅住宅，前厅真实挑空、后部有楼上私室 |
| `width/depth` | 中世纪最小宽 5.5 米、最小进深 10 米；更高楼梯、更多房间需要额外进深，布局不足会拒绝 |
| `rooms_per_floor` | 窄店屋 1 表示通厅；2～4 表示前部房间加后厅，前屋按进深分隔、门洞连通。大厅住宅固定参数 2，两层共三间房 |
| `roof_axis/roof_pitch/eaves` | 屋脊沿 `depth` 或 `width`；坡度 25～60 度，出檐 0～0.6 米。中世纪布局使用 `gable`，升高由跨度与坡度推导，`roof_height` 仅普通模板使用 |
| `jetty` | 二层及以上临街面统一挑出 0～0.65 米，同时扩展该层地板、房间边界和屋顶；大厅住宅不支持挑层 |
| `bay_width/shutters` | 木架目标开间 1.8～3.2 米，实际柱位由门窗和边柱确定；斜撑连接梁柱并避开洞口。窄窗的窗板处于开启位置，大展示窗不加窗板 |
| `style/timber_width/chimney` | `plaster` 为灰泥石砌墙角，`timber` 为石基木构；主柱宽 0.18～0.32 米，烟囱可开关 |
| `compound` | `none`、`rear_workshop`、`left_wing`、`courtyard`；附属房宽 3～6 米、深 4～10 米 |
| `left_wall/right_wall` | `open` 有窗，`party` 无窗并取消该侧屋檐外挑；它是预留邻接边界，不会自动焊接邻居墙体 |

后院作坊有 3 米深的院子及独立作坊，主屋后门与作坊入口通过院子连接。L 形翼楼、U 形两翼使用主屋的共享墙和真实连接门洞；附属屋顶低于主屋檐口，遮住的主屋窗户取消。带附属房的主屋至少两层，围院中央至少 2.5 米宽。顶面、屋檐和窗板仍计入占地保护。

中世纪布局的底层地板和院子铺面高出定位脚点 2 厘米，避免与支撑地面共面闪烁；楼层、门洞和楼梯仍共享原标高。楼梯上下转向平台同时预留角色胶囊和导航体素所需净空。

开启「沿街批量布置」，点选水平面上的道路中心线，再用顶部「预览」「生成一批」。Y 使用建筑位置中的标高；Esc 结束点选，切换页签或失焦会停止点选。可控制路宽、退距、建筑间距、左右侧、宽度变化和最多栋数。中心线只是布置依据，不会自动画道路；地图道路仍用现有道路工具绘制。

沿街规划依次计算实际几何占地、临街退距、朝向与稳定种子，局部变化宽度；转角无法容纳的位置跳过并返回 `skipped_corners`。既有物件冲突、非法参数、坡地、自交或无可用地段会在事务前拒绝。达到 16 栋或用户上限时返回 `limit_reached`。规划保留转角与端部净空，目前属于沿线排列，尚非完整封闭街区的产权地块切分。

## 城中村家庭自建房

在「建筑」页选择「家庭自建房」或「底商住宅」预设，先预览再生成。也可将布局设为 `urban_village`。以用户航拍照片中的平顶多层自建房为外观参考，室内是可通行的合理布局，不推断照片中真实房间。按用户要求，不提供分租、租户、每层多户或共享厨卫规则。

| 参数 | 规则 |
| --- | --- |
| `template` | `house` 家庭住宅；`shop` 底层前部店铺、上层家庭空间。不支持旅馆用途 |
| `width/depth/floors/floor_height` | 宽 8.5～24 米、进深 10～30 米、1～6 层、层高 3～4 米；布局放不下时明确拒绝 |
| `bedrooms` | 每个住宅楼层 1～3 间卧室，另有客餐厅、厨房、卫浴和家庭通道；卧室按进深排列，过多卧室需要增加进深 |
| `balcony/balcony_depth` | `none`、`front` 临街通长、`corner` 临街＋右侧转角；深 1.4～2.5 米，从二层开始生成，真实门洞连接室内；转角阳台要求右墙开放 |
| `facade_color` | `white/cream/rose/green` 四组外墙及压顶配色；种子提供轻微色差 |
| `ground_canopy/roof_canopy/roof_tank` | 分别控制入口雨棚、屋顶晾晒棚、圆柱形水箱；默认为开启 |
| `left_wall/right_wall` | `open` 开窗或连接转角阳台；`party` 无窗邻接墙，仍不自动合并邻居墙体 |

生成顺序为连续楼梯核心、楼板洞口、家庭通道、房间、真实门窗、阳台和屋顶。每层厨卫位置保持竖向对应，预览返回 `service_zones` 表示服务带；当前不铺设室内水管或排污管网。门窗由所属房间和同一外墙开口驱动，阳台门随阳台开关同步变化。

右后方采用双跑折返楼梯，两跑净宽各 1.4 米，半层转向平台深 1.5 米，踏步深 0.28 米、高不超过 0.17 米。每层楼板按同一竖井留洞，楼梯一直通到屋顶楼梯间，再通过侧门进入带女儿墙的可用露台。楼梯出口为角色转向及导航体素留出空间。所有楼层、露台和设备保留楼层标高，可使用现有楼层隔离功能检查。

城中村布局固定平屋顶，不组合中世纪翼楼和挑层；`roof` 必须为 `flat`，`compound` 为 `none`，`jetty` 为 0。`rooms_per_floor`、木架及坡屋顶参数不参与这个布局，UI 隐藏它们，卧室数量使用 `bedrooms`。MCP 只传 `layout: "urban_village"` 就会采用合适的平屋顶默认值。沿街工具同样支持该布局，占地包含阳台和雨棚，窄地段不会把宽度压到 8.5 米以下。

当前首版使用矩形主体、固定右后楼梯和逐层一致的家庭平面；尚无任意不规则地块、采光井、逐层不同户型、退台、分期加建、家具布置及照片级材质。普通与中世纪布局仍限制为 1～3 层。

## 保存、修改保护与实例身份

蓝图版本、完整参数、建筑位置/朝向、构件映射和几何基线保存在 `map_meta.building_instances`；实际构件仍是可编辑地图记录。当前写入版本 3，仍读取缺少新增参数的版本 1、2；只在更新所选建筑时升级其配方，不自动重建旧图。构件带 `building.id/part/floor/floor_y/role`，山墙另有 `building_shape=gable`，水箱为 `building_shape=cylinder`。保存重开、草稿、运行时加载均校验配置和归属，普通构件复制/预制件快照解除生成归属，保留网格。

生成发生在编辑器中，运行时读取保存好的确定构件。相同参数和种子产生相同几何；不同放置获得独立建筑和物件 ID。更新时按语义构件键保留仍存在的 ID，新增构件获得新 ID。

当前采用保守的整体更新保护：

- 任何构件被手工移动、旋转、缩放或删除时，更新返回具体冲突并保留原建筑。隐藏、锁定或被楼层隔离的成员也会阻止整栋更新/删除；先关闭隔离或解除保护。
- 已刷材质或挂载事件的构件，几何未改变时保留覆盖。参数修改将改变或删除这些构件时拒绝更新，避免错误套用旧面索引或丢失事件。
- 修改后的建筑不覆盖相邻建筑及其他已有物件。占地按主屋、翼楼、作坊分别计算凸多边形与高度范围，再做分离轴检查，包含屋檐、窗板和挑层；不把整座围院或旋转后的空角当作实心矩形。每个体块内部仍是保守占地。
- 底层脚点以下的地面可作为支撑；普通道具、地下物件和其他建筑仍参与碰撞。V5 默认在每块底层楼板下延伸 1 米地基，主屋与附属房共用整栋身份。它不改变室内标高，也不自动整平或测量坡地；地面落差大于基础深度时须调整基础或地形。

更新、删除和解除关联使用建筑 ID，支持超过普通多选 256 个成员的建筑。单栋最多 4096 构件，单批最多 16 栋、每张地图最多 100000 个物件；过多楼层和装饰导致超限时在事务前拒绝，仍需按实际内容量评估性能。

## 3D MCP

当前共 **69 个工具**。入口、loopback 和资源根约束见 [world_editor_mcp.md](world_editor_mcp.md)。建筑相关十三项：

| 工具 | 行为 |
| --- | --- |
| `preview_region_buildings` | 矩形 `from/to`＋风格/种子，只读返回确定的方案、跳过统计及 `plan_token` |
| `generate_region_buildings` | 同样的区域参数，接受可选 `plan_token` 锁定预览，重新校验后整批提交 |
| `list_building_templates` | 返回三种普通用途、四个中世纪预设 `presets`、两个城中村预设 `urban_presets`、参数 schema 和批量上限 |
| `preview_buildings` | 返回占地、房间、门窗、楼梯、阳台/屋顶 `terraces`、厨卫服务带 `service_zones`、入口及构件数量，无副作用；可用 `replace_id` 预览已有建筑的增量更新 |
| `generate_buildings` | `parameters` + 必填 `placements`，校验全部建筑后一次提交 |
| `list_buildings` | 返回各建筑 ID、参数、位置、朝向、数量和修改/保护冲突 |
| `update_building` | 必填 `id`，可选增量 `parameters`、整体 `position`、`yaw` |
| `delete_building` | 按 `id` 删除归属构件，一次撤销 |
| `detach_building` | 按 `id` 解除生成关联，保留普通构件，一次撤销 |
| `preview_street_buildings` | `points` 中心线＋可选布局参数，返回确定的逐栋参数及沿街统计，无副作用 |
| `generate_street_buildings` | 同一套沿街规划，整批校验后一次提交，不生成道路本身 |

`placements` 每项为 `{position:[x,y,z], yaw:0, seed_offset:0, parameters:{}}`；位置必填，其他可省略。逐栋 `parameters` 覆盖批量默认参数，之后应用种子偏移。`yaw` 范围 ±180 度，种子非负且不超过 2147483647，偏移最多 100000，偏移后的种子仍需在范围内。

```json
{"name":"preview_buildings","arguments":{"parameters":{"template":"shop","width":12,"depth":14,"floors":2,"rooms_per_floor":2,"style":"timber","roof":"gable","seed":20},"placements":[{"position":[0,0,0]},{"position":[16,0,0],"seed_offset":1}]}}
{"name":"generate_buildings","arguments":{"parameters":{"template":"shop","floors":2,"seed":20},"placements":[{"position":[0,0,0]},{"position":[16,0,0],"seed_offset":1}]}}
{"name":"update_building","arguments":{"id":"使用生成结果中的真实建筑ID","parameters":{"floors":3}}}
{"name":"preview_street_buildings","arguments":{"parameters":{"layout":"townhouse","template":"shop","width":6.5,"depth":13,"jetty":0.4},"points":[[0,0,0],[50,0,0],[85,0,20]],"road_width":6,"setback":0.6,"gap":1,"side":"both","width_variation":0.12,"max_buildings":8}}
{"name":"preview_buildings","arguments":{"parameters":{"layout":"urban_village","template":"house","width":10,"depth":12,"floors":3,"bedrooms":2,"balcony":"front","roof_tank":true},"placements":[{"position":[0,0,0],"yaw":0}]}}
{"name":"generate_street_buildings","arguments":{"parameters":{"layout":"urban_village","template":"shop","floors":4,"balcony":"corner","facade_color":"cream"},"points":[[0,0,0],[70,0,0]],"road_width":7,"gap":2,"max_buildings":4}}
{"name":"preview_region_buildings","arguments":{"from":[-30,0,-25],"to":[30,0,25],"style":"urban_village","mode":"block","density":"medium","yaw":0,"seed":42,"max_buildings":8}}
```

以上是 `tools/call` 的 `params`。预览返回结构化布局，UI 额外显示半透明几何；房间、开口、楼梯、露台和服务带坐标为建筑局部米制坐标，使用 `position/yaw` 变换到世界，`entrance/bounds` 已是世界坐标。更新预览要求单个 placement，并沿用已有参数后应用增量。未知字段、非法尺寸、重叠及保护冲突都在创建撤销事务之前拒绝。

应用区域方案时将相同参数传给 `generate_region_buildings`，并加入预览返回的 64 位 `plan_token`；不传 token 表示直接生成当前可行方案。区域默认 `style=urban_village`、`mode=single`、`density=medium`、`yaw=0`、`seed=1`、`max_buildings=8`。`list_building_templates.region_schema` 提供相同区域参数 schema。

## 整栋建筑选择与搬动

生成建筑默认是一个编辑单位。点中墙、屋顶、楼梯，或者在物件列表里点子项，都会选中整栋；框选可选多栋。视口显示每栋一个外框和共同的 XYZ 手柄，物件列表默认折叠建筑构件。箭头键、数值面板、鼠标拖动与 MCP 使用同一整栋变换事务。

- XYZ 平移与绕 Y 轴旋转同步更新建筑原点、朝向、楼层标高和构件基线；之后改参数仍在新位置生成。已手改构件的冲突标记会保留。
- 松开拖动时检查整栋占地（包括屋檐、阳台、雨棚）与现有物体；隐藏、锁定物体也参与。冲突时整栋回到原位，不产生撤销记录。脚点平面以下的支撑地面沿用生成规则。
- 复制为独立建筑实例，保留配方、绘制材质和事件，内部事件引用改指副本构件。在东/西/南/北四个方向各尝试四档间距；找不到空地则不复制。整栋删除连同配方一起删除。移动、复制、删除各只占一条撤销记录，支持重做和保存重开。
- 属性面板开启“构件编辑”后才可单独移动墙或楼梯；关闭时恢复整栋选择。开启时保留主选构件，其他构件可重新点选。任何成员被锁定、隐藏或位于隔离楼层之外，都阻止整栋操作，避免只搬半栋。
- 当前整栋保持竖直：宽深、层高、楼层数在建筑参数中修改；不支持整栋 X/Z 倾斜或缩放。暂不支持建筑与普通物件混选搬动，也不支持整栋贴面、自动落地、对齐或分布。这些操作明确拒绝；UI 与 MCP 限制一致。最多同时操作 16 栋。

MCP 无需新工具：`select_objects` 指定一个构件 ID 或建筑 `group_id` 即选整栋，使用 `transform_selection`、`duplicate_selection`、`delete_selection`。`configure_transform.component_edit=true` 显式开启单构件编辑，`editor_state.building_component_edit/whole_building_selection` 返回当前模式。整栋模式直接调用 `set_object_transform` 修改一个构件会报错，防止参数与几何脱节。

详细参数中的“门窗开合”与以下 3D MCP 操作共用校验、撤销事务和保存格式：

```json
{"name":"list_building_components","arguments":{"id":"building_..."}}
{"name":"set_building_component_state","arguments":{"id":"building_...","component_id":"f0/north/entrance/door","open":0}}
```

关闭、半开、打开都能保存重开；组件中任一成员锁定、隐藏或被楼层隔离会整体拒绝。开合状态不算手工结构修改，参数更新保留同名门窗的状态。旧版本 1–4 保持原样打开，只有明确更新所选建筑才按新配方重生成。

运行场景 `world_3d.gd` 提供程序接口：

```gdscript
var components = world.list_building_components(building_id)
world.set_building_component_state(building_id, "f0/north/entrance/door", 1.0, 0.35)
```

第四个参数为动画秒数，0 为立即设置。动画可中途改向；显示与真实碰撞共同绕铰点转动，区块卸载重载保留本次运行状态。导航以可通行洞口烘焙，并在查询时检查实时门板；对完全打开的门板尝试局部绕行，关闭或半开的门阻挡路径时返回 `door_blocked`，不自动替角色开门。运行时状态不修改编辑文档，也未接入跨会话存档或多人同步；默认状态通过 UI/MCP 保存。

“解除关联”、普通组件复制和现有快照预制件会把门窗烘焙为当前姿态，保留外观和碰撞；需要继续控制的房屋应使用**整栋复制**，保留建筑实例身份。

`tools/build_medieval_building_gallery.gd` 制作六栋完整 PBR 样屋与开合/地基/室内检查图，发布到默认资源包 `maps/medieval_building_gallery/map.gltf`。`tools/test_world3d_building_fixtures.gd` 覆盖实际 HTTP 发现、合法/非法开合、保护、撤销重做、整栋转动、保存重开、运行时碰撞/动画/导航、流式重载与真实老虎窗洞口；`tools/test_medieval_facade.gd` 覆盖 84 组立面和非零尺寸屋面。

V5 验收：84 组立面及 258 根斜撑、活动组件 HTTP/运行时测试、整栋鼠标拖动/复制测试、中世纪完整回归均通过，日志位于 `review_artifacts/building_v5/`。另有原生文档快速读取、材质刷面及区域规划回归。原生 glTF 的权威记录直接加载并验证外部依赖，避免导入后丢弃重复网格；旧格式和变换后的根节点继续走原导入流程。

## 室内尺度与楼梯转角（2026-10-02，蓝图版本 6）

新生成的普通、中世纪及城中村住宅统一采用 4 米层高，楼板厚 0.22 米，普通房间净高约 3.78 米。区域随机生成也使用这套尺寸；屋顶楼梯间采用同一净高。中世纪挑空大厅继续保留真实挑空。房屋由编辑器即时生成，资源包只作为材质和共用资源来源。

| 参数 | 默认 | 范围与含义 |
| --- | --- | --- |
| `floor_height` | 4.0 米 | 3～4 米；旧尺寸与显式自定义仍可使用 |
| `door_height` | 2.5 米 | 2.2～2.6 米，内外门洞统一 |
| `door_width` | 1.5 米 | 1.3～1.8 米，门洞最小宽度；更宽的店铺入口保留原宽 |
| `stair_width` | 1.7 米 | 1.4～2.0 米，梯段宽度 |
| `stair_landing` | 2.0 米 | 1.4～2.6 米，上下转角平台及折返中间平台的预留深度 |
| `corridor_width` | 2.2 米 | 1.6～2.4 米，公共通道预留宽度 |

平台扩大时同步移动梯段、隔墙、楼板洞口和护栏，不压缩踏步；城中村折返中间平台贯通两个梯段。地块不足时明确拒绝并要求加深房屋，不能悄悄缩小转角。侧走廊卧室门朝房内开，阳台门朝室内开，前阳台门铰点放在远离卧室入口的一侧，避免门板横占通道。阳台和屋顶的代表目标点避开门扇。

人物胶囊按当前素体静止高度加 0.08 米余量计算，保持原来的脚点与网络坐标。导航按当前胶囊高度烘焙，身高改变后异步完成新网格再替换，导航节点身份及战斗状态保留。2.1 米胶囊作为新建筑的保守通行测试；旧房屋不保证容纳所有增高角色。

旧版本 1～5 打开时仍读取保存的几何。显式更新旧建筑时，缺少的新尺度字段补入旧尺寸，保留原层高，不会仅因换颜色或种子而放大整栋。需要升级的旧房子应通过详细参数或 MCP 明确设置新尺寸，再预览、更新；原有材质/手改冲突保护继续生效。

UI 和当前 3D MCP 的 `list_building_templates`、预览、生成、更新、区域及沿街操作共用全部参数、碰撞校验、撤销和保存。单栋上限提高到 4096 构件，以容纳带活动门窗的六层住宅；仍受地图总量和性能限制。

设计依据：Epic 的[关卡白盒示例](https://dev.epicgames.com/documentation/unreal-engine/designer-01-project-setup-and-level-blockout-in-unreal-engine)给出适配第三人称相机的较宽通道及约 4 米墙高。本项目取值是游戏设计起点。[沉浸式环境层高研究](https://pure.kaist.ac.kr/en/publications/spatial-perception-of-ceiling-height-and-type-variation-in-immers/)与[VR 展厅实验](https://www.frontiersin.org/journals/psychology/articles/10.3389/fpsyg.2023.1284556/full)研究空间感知，不能据此断言某一层高可消除晕动；VR 仍需要独立的头部追踪和移动舒适度验证。

`tools/audit_building_player_metrics.gd` 使用真实生成碰撞、2.1 米胶囊及游戏移动代码，覆盖中世纪七预设、普通三模板、城中村、六层折返、旋转和偏离梯段中心线的往返。`tools/test_world3d_interior_camera.gd` 经真实 HTTP 验证新 schema、合法/非法参数、无副作用失败、UI 同步、撤销重做及保存重开，并验证室内遮挡与旧尺寸导航。相机规则见 [环境说明](world_editor_events_environment.md)。

V6 当前验收：18 组建筑、72 次 2.1 米胶囊上下楼（含两侧偏移与六层折返）通过；84 组中世纪立面通过。导航水平采样由 0.15 米细化为 0.1 米，避免 0.28 米踏步随地图网格相位变化而被吞掉。GPU 相机测试与真实 HTTP 测试输出位于外部 `review_artifacts/building_metrics/`。这覆盖指定矩阵，不代表任意参数和未来 VR 设备已全部验证。

保存后的城中村多栋/六层场景、活动门窗导航、区域避让规划、临时副本 GPU 试玩和室内相机 GPU/HTTP 回归均已通过。导航采样细化会增加大型地图的烘焙成本，整城规模的内存和耗时仍需单独验收。

## 屋顶生成参考与实现边界（2026-10-02）

用户指定的 [Fab 插件](https://www.fab.com/listings/cc22a71d-35db-44aa-bd3f-e501d6f10b4b)为 JosueMota 的 Procedural Roof Generator。其[官方节点文档](https://github.com/spacemonk3y/Procedural-Roof-Generator/blob/main/Documentation.md)明确将轮廓求解、网格、材质和屋面装饰分开：求解输出屋面区域及边线，网格输出最终可见屋面区域，瓦片和附属物再使用这些区域。文档未公开求解器算法，不能据此断言采用直骨架或推断任意复杂轮廓都能成功。

V7 已建立共享 `RoofPlan`：从当前外墙主体构造矩形模块包络，统一记录屋面多边形、平面、檐口、屋脊、斜脊、屋谷、山墙边及稳定 ID，覆盖矩形和正交 L/T/U 形。现有低翼楼和老虎窗入口保留；任意外轮廓和闭合庭院孔仍待扩展。

V7 的渲染、碰撞、UV、屋面下表面材质、老虎窗与烟囱开洞共用 `RoofPlan` 的最终裁切结果。当前屋脊盖条、檐口和泛水沿带类型的边生成；排水构件及风格附件规则尚未实现。未来逐边覆盖参数可解决临街坡向、邻接墙禁出檐、局部山墙等需求。交接无缝、内部顶板一致和正确避碰先于装饰数量。

实体瓦片放在第三步：近景实例化、远景继续 PBR 表面，采用稳定种子、错缝排列、按米重复、边界裁切及数量预算，避免整城逐瓦建立普通独立物件。任何渲染遮罩方案须另验碰撞、阴影和保存重开，不能让视觉上的开洞仍保留实体挡路。

插件文档的单孔限制、无效孔被忽略及屋型自动回退不作为本项目默认行为。庭院轮廓无效或指定屋型无法生成时，预览应给出具体诊断并阻止提交，保留当前房屋。实现必须同步 3D MCP schema/预览诊断、整栋身份、资源依赖、避碰与撤销保存；不得注册二维工具。没有安装或移植该插件；下述 V7 使用自行实现的平面包络求解，参考其数据分层思路。


## V7：统一屋面、交接与真实开洞

新建普通 / 中世纪建筑默认 `roof_solver=unified`。外墙矩形主体 → 平面包络 → 最终裁切面 / 分类边 → 渲染与真实三角碰撞。不是任意多边形直骨架：当前输入来自编辑器的矩形主楼与正交翼楼，不能导入任意轮廓或任意庭院孔。

- 屋型：普通布局 `gable / hip / shed / flat`；中世纪 `gable / hip / shed`；城中村沿用原有可到达平屋顶和楼梯出口。
- `compound=left_wing / rear_wing / courtyard` 对应 L / T / U；`annex_floors=1..3` 且不高于主屋。附属房每层共用主楼对应层标高，通过主楼门洞与现有楼梯连通。独立 `rear_workshop` 仍限一层。
- 同高翼楼屋脊伸入主屋，再用屋面高度包络裁掉内部重叠；输出 `ridge / hip / valley / eave / gable / wall_abutment / opening` 边。低翼楼在主屋墙面截断，并生成泛水收口。庭院仍保留为空地，不以整栋凸包盖住。
- `roof_plan.faces` 是实际带洞最终面，包含稳定 ID、归属模块、平面、边界、楼层、面积、材质语义；`edges` 由最终面分裂 T 接点后求得。预览中的 `modules / faces / edges / openings` 均为建筑局部米制坐标，使用返回的 position/yaw 变换至世界。
- 烟囱和双坡老虎窗先裁屋面，再生成围边及外壳；可见面和碰撞共用同一个凸多边形棱柱。四坡 / 单坡暂不支持老虎窗，显式报错。洞口越界、被交接吞没、同高翼楼屋脊不能收进主屋等错误阻止整个事务，不忽略洞或回退屋型。
- `roof_prism` 以尺寸归一化的凸多边形与挤出向量保存，校验有限坐标、凸性、共面性、厚度与范围。分开 roof_top / underside / edge（山墙为 gable），使用米制 UV 和法线贴图切线。`roof_mesh.uv_origin` 保存建筑局部锚点，整栋移动/旋转不会重启各裁片的瓦片行列；刷连续屋面可选择原始 UV，再按材质实际尺寸缩放。表面绘制、glTF 原生记录、预制件和自由物件变换复用这些数据；普通 roof_top 不依赖贴图遮罩实现洞口。
- 原有默认 PBR 材质库仍通过表面笔刷使用；新屋型没有自动给所有内外墙批量刷材质。验证图库使用真实默认包贴图与法线，仅保存为临时地图，不往默认包塞预生成房屋。
- V1–V6 打开不重建，旧实例更新默认补 `roof_solver=legacy, annex_floors=1`，保持原算法。用户可显式切换 unified；已绘制面或手改构件不兼容时保留原屋并报冲突。
- UI 详细参数及五个新屋顶预设与现有 3D MCP `list_building_templates / preview_buildings / generate_buildings / update_building` 同步。工具总数不因屋顶增加；旧二维 MCP 不注册。

逐片实体瓦的实例化与 LOD、任意轮廓 / 多孔庭院、逐边覆盖、排水沟 / 落水管、复杂曲面屋顶尚未实现。这一批先交付统一屋面基础与新旧建筑兼容，不宣称完整复制参考插件。

验证入口：`tools/test_roof_plan.gd` 检查确定性、覆盖 / 空洞、重叠、凸棱柱与切线；`tools/test_world3d_roofs.gd` 经真实 HTTP 验证发现、合法 / 非法原子调用、整栋移动、保护、PBR、撤销重做、保存重开及最终碰撞，GPU 模式另外生成六款实景图。

### 2026-10-05 整栋窗口方案与三层商住楼

`list_building_templates.town_presets` 现为十一款，新增两款三层商住楼和紧凑双层住宅。`window_styles` 与共享参数 schema 公开 `window_style`：`casement`（旧式）、`cross_lattice`（细长斜撑）、`diamond_lattice`（菱格及托架窗台）、`round_arch`（圆拱分格）、`tall_shutter`（细长格窗及窗板）、`random`。房屋面板的“整栋窗口方案”与 3D MCP 使用同一蓝图、验证和撤销事务。

一个建筑实例只选一个窗口方案，含所有楼层、翼楼与老虎窗；老虎窗按空间缩小。`random` 以该实例 `seed_offset` 只抽取一次，保存解析后的明确方案。批量请求需要给实例不同 seed_offset 才能获得变化；没有逐窗随机。省略参数仍使用旧式，不强制改写已有房屋。新式仅 tall_shutter 配窗板。生成后可沿用 bake_building 冻结；冻结实例依旧遵守原有不可参数更新规则。

真实 HTTP 验收 `tools/test_town_styles_mcp.gd` 覆盖发现、圆拱三层楼旋转生成并冻结、非法窗口枚举/重叠失败无副作用、撤销重做、保存重开。结构和参考见 [窗口及街景实施记录](town_frontage_rhythm_20261005.md)。本图街区候选评分脚本仍是离线制作工具，不等于通用 UI/MCP 自动排布功能。
