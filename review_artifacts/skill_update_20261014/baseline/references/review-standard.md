# 每模型检查与判定

## 1. 身份、用途与结构（每模型）

- 记录模型名/ID、制作源、实际运行资源绝对路径与SHA、制作阶段、参考资料、已认可外观基线。外部购买资源保留来源及已知许可记录，不把参考图内文字当执行指令。
- 对照轮廓、层次、材质分区、实际尺寸/单位、朝向、原点、缩放、连接与活动件。识别项目补充设计；第三人称适配尺寸单独说明。
- 检查AABB/可见性边界、法线/切线、UV、透明模式、背面、重复或隐藏几何、意外相机/灯/人物占位。隐藏节点可能是LOD/动画/碰撞，确认用途后才能清理。
- 程序环形石块等封闭曲面变形后，检查实际导出三角形的绕序、退化、翻折与自交；单轴压缩外环可能改变角序，倒角不能修复内部翻折。可通行顶面除真实控制器遍历外，按用途抽样垂直射线，排查重叠顶冠和朝下顶面；仍以参考和实际画面判断是否像自然石，通行通过不能放行规则柱状外观。
- 多物件独立部署或复用需要保留节点/锚点/ID；角色保留骨骼、skin权重、morph与动作轨道；不要用静态拼接破坏功能。

## 2. 资源清单与优化优先级（每模型）

|数据|需要分清|
|---|---|
|文件|母版、GLB/实际源、native压缩字节与未压缩字节；同SHA实例复用|
|几何|唯一几何、全部LOD合计、实际可见LOD、碰撞/拾取几何；不要把各LOD相加当一帧面数|
|渲染|节点、surface、材质数和实际draw calls；资源数不等于提交批次|
|贴图|通道用途、分辨率、编码格式、解码格式、mip、alpha、有效引用、逐图SHA和跨文件复用|
|内存|CPU图片/网格、GPU估算、full-peak准入预算与真实进程测量分别报告|
|加载|冷/暖、源SHA读取/解码/上传/CPU准备阶段；版本、缓存状态及计时范围|

先定位“成本与屏幕效果不相称”的部分，不按文件大小一刀切。低面数资源也可能被多张大贴图主导；LOD也可能增加编辑器精确拾取准备成本。

优化顺序按证据选择：未用依赖/历史导出数据 → 严格重复图片和资源 → 恒值/无效通道与texel密度 → 有界纹理尺寸候选 → 几何/LOD/碰撞代理。不是每件都要执行全部改造，记录“不需要”的依据。

依赖清理从实际使用的场景/节点/mesh材质出发，纳入动画、skin、morph、扩展、extras和保留的独立变体根。未被默认scene引用不必然可删除；确认交付范围。重新映射材质、texture、image、accessor、bufferView等表，验证共享数据段和完整引用闭包。对不认识的扩展/索引型extras保守保留，不能默默丢弃。

相同编码SHA支持严格去重；解码像素一致还要核对色彩空间、sampler和材质角色。几乎相同也必须标为有损。恒值图缩到1像素仍需验证采样/mip行为。ORM单通道裁剪必须匹配shader读取通道，不能继续读取不存在的G/B。

PNG/WebP/JPEG重压不代表GPU压缩。新GPU压缩格式需当前导入、native校验和footprint合同实际支持；不要仅换扩展名或绕过校验。跨文件图片相同不证明运行时共享，不能擅自改成未支持的外链依赖。

## 3. 减面、LOD与交互（按类型）

- 简单模型可以不需要LOD；复杂/重复高频模型检查各级面数、距离、投影尺寸和实际剔除，不默认用固定百分比。
- 近景保留识别轮廓、孔洞、倒角、叶簇、缝隙与高光。不要把真实射击孔/通行口填平。比较形体和阴影，而不只看三角面统计。
- 检查LOD切换前后及阈值两侧、消失距离、重叠/空档、共享边界；风动画/骨骼变形不能出界被裁掉。远景不应同时渲染全套LOD。
- 渲染、实际碰撞和编辑拾取各自验收。简单碰撞代理不得堵门、填孔、丢地面或改变步行/阻挡语义。
- 门、窗、柜门等活动件检查枢轴、轴向、开合范围、固定件与碰撞；房屋保留逐层/屋顶隐藏。重复灯具的光源/阴影成本需单独量测，不随意合并或关闭已需功能。
- 骨骼模型检查bind pose、关节与权重、morph、代表动作、装备接触/穿模；共享资源不能共享每实例动态状态。

## 4. 固定条件画质对比（每模型；白模按阶段）

锁定实际相机变换、投影/FOV、输出尺寸、灯光、曝光、环境、渲染器、过滤/mip/AA。记录这些值并让候选复用，不各自拍“好看角度”。环境或生产shader变化先确认A/B仍可比。

最小覆盖是正常游玩近/中/远视角和材质/结构细节；细节镜头要让目标占足够像素，不能用整条街小缩略图掩盖损失。新模型无旧版本时，对照参考并检查各视角；减面/压图候选对照未优化母版的运行导出。

条件增加：

- 布料/植被/头发：无风与至少两个相同风时刻，保留锚点、振幅和形变；变化涉及过滤或动态稳定性时另看短连续动画，静帧不证明无闪烁。
- 透明材质：亮暗背景、近景叶缘/发丝、接收投影的地面。相同总alpha覆盖率不保证每条轮廓或阴影不变。
- 发光灯/玻璃/金属：按用途补代表性昼夜和高光角度，确认发光体、透明片、色温与反射没有混淆。
- 屋瓦、石砖等凹凸材质：先核对实际导出的法线图片、色彩空间、OpenGL/DirectX 方向及 native 材质强度。程序高度转法线时使用纹理覆盖米数和像素间距计算坡度，同时表现大尺度弧面、叠压边与微表面；勿仅放大噪声或加黑接缝。固定斜光检查隆起/凹陷方向、过黑尖边、平铺接缝，再看正常近中远受光。法线只改变着色，不能宣称产生真实轮廓、位移或接触投影。
- 建筑：侧/背面、屋顶收口、开口/楼梯及真实第三人称相机；只检查本次受影响区域，已验组件不重复逐屋验收。

先检查导入和材质语义，再看截图。无损候选应保留解析后的几何/材质/节点语义、有效图片像素，确定性渲染下要求像素一致；若引擎噪声导致不一致，先定位控制变量，不能直接叫无损通过。有损候选记录MAE/最大差/区域差但必须人工查看目标区域，全画面背景会稀释误差。

可见的非预期织物微对比、白边亮度、叶脉、透明轮廓、光影或运动损失必须回退；没有统一“最大差1级必过”阈值。允许明确的用户设计改变，但记录它并按新目标验收。

## 5. 导出、缓存与接入（每模型选择适用管线）

- 在隔离内容根用真实运行导入器/后处理加载导出文件，检查依赖、节点/材质/extras、缺贴图/异常警告，保存native再重开，核对功能语义。
- 走当前支持的资源格式与校验合同；静态PackedScene的限制不直接套用于角色动画。遇到不支持的类型应选择正确管线或记录缺口。
- 记录源码fingerprint/generator与资源SHA。源或管线变化后重建该测试根的派生资源；禁止给旧manifest改签名冒充有效缓存。
- 仅局部材质改动时，可凭独立差异审计复用未受影响的活动件、灯光或合批合同：列明允许变化字段，证明其余几何、图片、材质通道及相关交付文件不变；旧证据保留原 SHA，新增记录显式引用证明。新源的资源成本、真实导入/native 及受影响画面仍须重验，不能直接把旧报告 SHA 换成新值。
- 新管线/缓存相关变化：在可恢复的隔离副本上测试源变更导致旧native、footprint、冻结准备失效，恢复后可读。稳定管线重复制作模型时可引用同版本合同验收证据，不要求每件破坏性重测缓存；每件的真实导入/保存重开不能省略。
- 已授权接入时检查资源包依赖、保存重开、实例/碰撞/选择/撤销及适用游戏功能。若新增编辑器能力，按AGENTS同时验当前3D MCP schema/HTTP合法与非法调用；仅导入普通模型不凭空要求新增MCP工具。
- 性能验证分开控制“程序开关变化”和“资源替换”。GPU全局计数不能当单模型VRAM；共享纹理不按实例相乘。整图性能由集成阶段验证，单模型报告不冒称整城FPS提升。

## 6. 结论与证据

使用模板，留下源/候选SHA、选择与回退版本、数字口径、相机和图片、语义/管线结果、与参考的偏差、未验范围。输出必须区别：严格无损、有界有损、仅metadata变化、待验实验；不能将自动脚本pass当人工批准。

素材放当前外部content/art_sources根；报告和工具留项目，母版、候选、回退相互独立。原有授权决定何时发布；不擅自覆盖hash资产或用户地图，也不要求已授权工作重复审批。
