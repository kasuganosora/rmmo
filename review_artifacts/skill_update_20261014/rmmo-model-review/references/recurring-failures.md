# 反复问题与处理经验

用于将用户反复指出的问题转为可观察的验收结果。按本次变更选读，不把整份清单变成每件模型都要跑的测试。第 1 节用于建筑/家具，第 2 节用于材质，第 3 节用于法线与凹凸，第 4 节用于导入发布，第 5 节用于图片与清理，第 6 节用于复验收尾。

## 1. 参考误读、结构接缝与可复用家具

- **先确认物件是什么。** 相似轮廓可能是装饰板、墙、布幡、玻璃或金属。记录参考帧、可见边缘/厚度/连接、用户修正及不确定处。公会雕像两侧是独立薄装饰板，环饰是金属；徽幡是布。这些是该公会的已确认要求，不推广为其他建筑规则。
- **遮挡不是缺失证据。** 幡后看不见门，不证明阳台没有入口；用空间关系核对通行。已授权的隐藏面、连接件和必要功能补为“项目补充设计”；不同建筑的外观资料分别归档。新结构沿项目要求核对实物、平面/剖面等资料，不能用通行测试代替结构依据。
- **屋顶要查相交处。** 从正面、斜上和侧面检查外墙顶与屋面包覆、挑檐、老虎窗尖顶、中央山墙、屋谷、压边和饰条端点。查墙穿屋面、悬空/错位收口、重叠闪面和透光缝；远景轮廓正确不能代替近景连接正确。修生成器并重导出，防止下次构建复发。
- **开口要查完整墙体。** 从内外检查洞口，包含独立房间内衬、窗洞侧面、屋壳与碰撞；删外墙一块不等于窗洞贯通。疑似堵洞时用沿当前相机的射线/剖切确定命中物，区分近侧堵片和穿过开口看到的对侧屋面，不因透视误判盲目扩大洞口。
- **支撑与落地关系可见。** 入口平台/台阶覆盖并对齐扶手、矮墙及柱脚，检查正侧面是否悬空或缺口；尺寸变化后复查 UV 物理尺度。公会幡架检查墙锚、外挑横杆、三角撑、悬挂环与布面下垂；不能只摆几根不连接的杆。类似检查按各物件真实支撑方式执行，不强制所有支架都用三角形；视觉连接或抽样射线通过不等于工程承载、水密性认证。
- **家具既看装配也看独立资源。** 灯、桌椅、床、柜、布幡等按复用范围独立导出，保留安装点、原点和 ID。核对独立素材与楼内实例是否同版，防止整楼修好、素材库仍旧。镜头可见的金属包边、把手、铰链不能遗漏；柜门与门窗须有正确枢轴，测试关闭、代表中间态和全开，检查门板、铰链固定端、内腔、碰撞及复制实例状态隔离。
- **游戏适配需绑定实际角色与相机。** 检查门洞、净高、楼梯、平台转身和相机遮挡；记录参考尺寸与游戏调整。不能将某个层高或门宽称作通用游戏建筑规范。已有组件未受影响时复用相同版本证据，外部布景改动不逐屋重测室内。

## 2. 材质身份与“塑料感”专项

先建立“部件 → 应是什么材料 → 应看到什么 → 实际运行结果”表；色板、粗糙度、金属度、透射、发光与表面层次分别判断。共享材质、同类变体和室内/室外对应部件都应排查，但保留参考确实不同的材质身份。

|对象/症状|必须看到的证据与修正边界|
|---|---|
|公会灯柱像绿塑料|按用户要求表现烤黑涂层金属的杆和笼架；金属底材与涂层分开判断，不因物件叫“金属”便将全部表面 metallic 拉满。白模灰色或诊断材质不能充当最终材质。|
|灯笼成为整块发光板|玻璃片、金属框与内部悬浮菱形暖白魔法石分层可见，发光来自石头；大厅灯和门口壁灯都查。近景能透过玻璃认出石头，夜景检查周边受光，不用不透明乳白发光玻璃替代。|
|石头亮、周围不亮|检查实际光源/socket、启用状态、距离预算与遮挡。光源在封闭石头内部可能被自身挡住；若需排除自投影，仅作用于已明确识别的包围发光体，保留笼架和其他物体阴影，不能全场关阴影来掩盖问题。发光材质本身不保证照亮周围。|
|彩窗像粉彩板或塑料板|参考深色宝石色板、深色铅条与玻璃透光层次；外立面圆窗和室内扇窗分别查看。换亮暗背景、正面/斜面/背光，确认玻璃真的影响背景而非只画一块颜色。排查洞后实心墙、双层面排序、alpha/透射支持；避免靠自发光伪装透光。|
|魔法球成为不透明蓝球|透过球壳看到内部立体星尘，正侧面能识别深度；检查壳、微云纹、内部星光和金属环的遮挡/透明排序。优化可以合并星尘网格，不能删掉辨识细节或用外贴亮点冒充内部体积。|
|金属无环境反射、像灰塑料|先核对实际金属/涂层参数与粗糙度，再看室内环境、反射探针及曝光。单独光棚通过不证明装配场景已解决；不能给金属加发光或套无遮挡室外天空伪装室内反射正确。环境待调时明确该场景画质待验。|
|塔顶/塔身/号角材质串区|该告警塔上部红陶瓦/砖色屋顶，下部塔身及承托为石砖，号角是偏金的黄铜；逐部件核对，不能把一片局部修色当整塔正确。其他模型依据自己的参考分区。|
|布幡、床布像硬金属|非金属响应、织物粗糙度/微法线与厚度一致；褶皱、悬挂处受力和自由边下垂体现布性，图案与色板保持。仅改 roughness 无法修复错误板状结构。|
|石墙像瓷砖、瓦片只有黑缝|核对米制尺度、砂浆凹槽、石面起伏、瓦身弧度和叠压边；检查法线、粗糙度、AO 是否真实生效，执行第 3 节。不能靠强高光、黑缝或高频噪声冒充层次。|

实时薄玻璃近似、屏幕折射、彩色透射投影、焦散和 GI 是不同能力。报告实际支持与限制，不能因为玻璃可透视就声称彩色光斑已实现。白模阶段这些材质项不适用，结构与玻璃/发光体分件仍可检查。

普通玻璃不靠发光伪装透射，不等于所有魔法玻璃都禁止发光；允许参考明确需要的魔法球壳效果，但仍须保留内部细节与预期光学层次。旧阶段标签或材质名与现状冲突时，以当前导出通道、socket 和运行证据定位，不能只信标签或只看命名。

## 3. 凹凸诊断：先证明法线生效，再调强度

1. **定位实际绑定。** 真实导入并保存重开后，读取渲染网格的活动材质（含 surface/material override、next pass），核对 normal 开关/强度、纹理与 sampler、UV 米制覆盖和切线。源 JSON 写了路径、材质工厂返回正确或文件名相同，都不能证明当前网格在用它。发生“导出后变平/细节消失”或管线变更时，读取实际纹理解码数据，与源图在统一像素格式下比较 SHA；允许的转换如绿色通道翻转、mip 生成应单独说明，勿把编码文件 SHA 当像素 SHA。
2. **排除方向与光照误判。** OpenGL/DirectX 的法线 Y 按管线约定只转换一次，技术图走正确的数据色彩空间。低太阳高度不保证正在检查的面受光：定义 L 为表面指向光源的方向，检查代表面 N·L 为正并有适度斜入射；屋顶、立面、材料片朝向不同，要分别布光。固定条件 A/B，必要时换另一个方向的光，看明暗是否随光改变，区分烘死的阴影和法线反应。
3. **补结构层次而不是噪点。** 根据实际瓦缝布局、纹理覆盖米数与像素间距计算高度梯度，归一法线，限制尖峰。大/中尺度表现瓦弧、搭接边、砂浆和抹痕，微尺度表现粗陶、砂粒或石面。通道须按同一 UV/物理尺度对齐；扫描细节与生成色图组合时明确是复合材质，设计起伏幅度不能冒称扫描实测值。
4. **保留材料身份。** 普通房屋的方形错缝瓦不能因为“和公会一样平”就改成鱼鳞瓦；泥灰不能变成石块。修法线时保持任务外的色板、铺贴、粗糙度和既有正确墙面，逐族判断而非统一放大法线。正常游戏距离会滤掉细颗粒，不为远景可见而制造尖锐噪声。
5. **验诊断视角，也验正常画面。** 受控斜光用于查隆起/凹陷方向、接缝和反应；最后看实际装配的近中远、平铺边界与正常环境。锁定曝光、相机、尺寸、AA、mip/过滤和稳定帧数；不能只选最显凹凸的一张特写放行。发现色图既有平铺边界时明确保留/待修，不用新法线宣称旧问题消失。
6. **区分着色与几何。** 法线不会生成轮廓厚度、视差或真实接触阴影。新增法线可能只补切线数组；按位置、顶点法线、UV、索引、碰撞、包围盒和 LOD 分通道对比，不能因缓冲长度变化就说形体改变或新增面数。是否需要位移/实际瓦边几何按镜头需求另判，不擅自增加高成本几何。

## 4. 实际接入、运行衍生物与版本一致性

- **分别写四个里程碑。** 独立候选通过、正式素材库可发现/使用、正式地图部署、场景玩法/性能验证不是同一件事。发布清单绑定模型 ID、分类/名称、实际源与目标 SHA、native/管线版本及缩略图；不要把内建条目数、模型文件数、预制件目录数混为一谈。
- **正式库也要实际使用。** 从正式目录发现资源，在隔离地图实例化/刷面，检查选择、碰撞、活动件、适用的撤销重做和保存重开；依既有合同复用未变测试。仅把文件拷过去、隔离候选已通过或 HTTP 能列出名字都不足以证明正常接入。不要为普通资源导入发明新 MCP；新增/修改能力按项目合同同时验证真实 3D HTTP。
- **母版、独立家具、楼内实例与缓存同步。** 核对实际引用，缓存指纹覆盖受影响材质/灯光/几何转换；保持源节点可编辑，静态合批只动派生渲染数据。不得通过给旧报告/manifest 换 SHA 来跳过重新生成。
- **运行特效不混入作者几何。** 蜡烛火焰、光晕等运行时生成节点，在加载完成及保存重开后核对数量、碰撞和拾取；排除应依据显式运行时标记/元数据，不按名字删节点，作者同名真实几何必须保留。重复生成和异步晚到节点也纳入本次受影响检查。
- **材质发布与候选参数一致。** 比较完整有效参数，尤其省略时会继承的默认值，例如 normal 格式/强度；不能只复制新通道。沿原子保存、冲突检测与恢复机制写入，失败只回退本次仍匹配的写入，避免覆盖用户同期变更；收据失败也不是完整成功。
- **既有地图不在范围时保护旧依赖。** 若本轮已获正式库发布授权，用新版本路径/哈希资源发布，保留冻结场景仍引用的旧贴图，避免改共享路径悄悄改变旧图。只有验收授权时保持隔离候选；记录实际保护和检查范围，不声称逐一验过未遍历的地图。不为每次更新额外备份整份地图。
- **缓存容量问题先查依赖。** 沿正式目录、保存/恢复信息和当前有效索引核对孤立派生物；经授权后可隔离确证孤儿以恢复空间。不能扩大容量上限冒充优化，也不能把疑似旧文件直接删掉。磁盘节约与解码/实测内存分开报告。

## 5. WebP、验收证据与清理

- 按用户 2026-10-14 最新要求，所有发送 OpenAI 的验收截图先实际有损编码为 WebP **quality=90**（编码质量参数，不承诺文件缩小90%），保持尺寸/色彩。已有 WebP 若无匹配压缩记录也要处理；有目标 SHA、quality=90、lossless=false 的一致记录时直接复用，避免累计重压。
- 精确像素误差在本地未受损数据上计算；必要时以 `--lossless --keep-source` 留本地参考，不能将有损上传图用于证明像素无损。已有有损 WebP 再保存成无损不能恢复原始像素。需精查区域时可补原比例局部截图后仍按质量90编码，不缩放或过度锐化掩盖差异。
- 检查查看工具实际发送的格式，不仅看扩展名；上传应取脚本返回路径，不能继续发送原图。替换归档图时维护旧/新路径、SHA 和引用；存在进行中的对比器或尚未迁移的报告引用时使用 `--keep-source`。只转换验收图，不把模型 PBR 技术贴图一起有损转换。
- **清理按用途，不按后缀。** 同一 review 目录可含测试贴图、原始参考、导入资产、最终证据和重复预览；正式素材库缩略图也可能是编辑器依赖。先做明确文件清单，记录绝对路径、用途、字节、SHA、资源依赖与报告引用、保留/删除理由。未知用途暂留，可安全确认的部分继续。
- 默认保留支撑当前选定版本的关键同条件 A/B、细节和必要动态证据及其配方；优先清理可重建的重复联系表、早期预览和临时图。用户明确要求删除这些最终图时可执行，但须记录删除清单与状态，不将仅剩数值报告表述成仍有图像可回查。
- 执行删除前核对最终解析路径在批准范围内，包括链接/重解析点；预览清单与执行使用同一集合，若文件在间隔内改变则跳过并重查。按当前权限执行，动作被拒绝时查明原因并缩小范围或取得所需授权，不能换解释器执行同一被拒绝动作。
- 清理/迁移后检查剩余依赖和证据链接；报告记录保留、迁移或已清理、原路径/SHA、可重建入口及实际释放字节。历史报告可保留原记录，附清理清单表明哪些图不再可用；不可凭不存在的图重新授予画质通过，也不虚构可恢复性。证据缺图不自动证明模型/正式贴图损坏，资源状态与证据可用性分开记录。

## 6. 复验收尾与范围控制

用户的新修正加入同一问题表，覆盖共享材质/生成器和相关独立资产，说明修复前后证据。若问题已归因场景环境且本轮仅修资产，分开写资产结果与场景待验，不把缺口藏在“整体通过”后面。

每次修复只重跑实际受影响项；已有管线合同可引用同版本证据，证明不变后复用活动件/LOD结果。新源身份、实际导入保存重开和受影响画面不能凭旧报告跳过。纯文档、技能或报告文字修改不启动 GPU。不要按检查数量衡量完成度：必要项未过或可见问题未解决，仍应修复或明确待验。
